# Activity Bar 시안 1 후속: 이름 표시와 고유 아이콘 (#1812)

2026-11-19 (KST) · 브랜치 `spike/1812-activity-bar-labels` · 태그 `spike/2026-11-19-activity-bar-labels` · 앞 스파이크 `spike/1812-activity-bar`(태그 `spike/2026-11-19-activity-bar`) 위에서 갈라짐

이 브랜치의 코드는 병합하지 않는다. 채택되면 master에서 새 이슈로 다시 구현한다. 앞 스파이크의 시안 1·2·3(`?activityBar=1|2|3`)은 그대로 남아 있다.

## 확인하려는 질문

시안 1(항상 보이는 막대에 패널과 플러그인 아이콘)에서 아이콘만으로는 어떤 플러그인인지 알기 어렵다. 아이콘 아래 이름(1-L)과 플러그인 고유 아이콘·첫 글자 타일(1-T)로 이 문제가 풀리는가, 막대 폭이 늘어난 화면이 받아들일 만한가.

## 만든 것

개발 전용 쿼리 두 개를 더했다. 테스트는 추가하지 않았다.

- **1-L `?activityBar=1L`**: 막대 폭 72px. 위 그룹(탐색기·검색·변경)과 가운데 그룹(템플릿 갤러리·플러그인)은 아이콘(20px) 아래에 한 줄 이름(`--font-size-xs` 12px, `--line-height-meta` 16px, `--id-color-text-muted`). 길면 말줄임, 전체 이름은 Tooltip. 아래 그룹(설정·색 모드·Desktop·연결 상태)은 아이콘만. 열린 패널과 활성 플러그인 화면은 아이콘+이름을 함께 감싸는 선택 배경(`--id-color-surface-selected`, 글자 `--id-color-text-selected`)으로 표시하고, 열린 패널만 왼쪽 끝 선을 더한다.
- **1-T `?activityBar=1T`**: 막대 폭 48px 그대로. 플러그인이 자기 SVG를 주면 그것을(막대에서 20px), 아이콘이 없으면 이름 첫 글자를 둥근 사각 타일(20px, 모서리 `--space-1`, 배경 `--id-color-accent`, 글자 `--id-color-text-on-accent`)에 넣는다.
- **공통**: 1-L에도 같은 고유 아이콘·첫 글자 타일 규칙을 적용했다. manifest가 Editor가 아는 아이콘 이름을 주면 지금처럼 lucide 아이콘을 쓴다. '더 보기'(⋯)는 짧은 메뉴 대신 시안 3 팝업과 같은 검색칸+아이콘·이름 목록(`WorkScreenList`)을 막대 바로 오른쪽에 연다. 목록은 넘친 항목만이 아니라 작업 화면 전체다(검색으로 아무 것이나 찾게).
- 넘침 계산은 가운데 그룹 첫 항목의 실제 높이로 칸 수를 잰다(1-L은 항목이 48px라 더 빨리 넘친다).

**72px의 근거**: `calc(var(--space-16) + var(--space-2))` = 64+8px. 버튼 폭은 막대에서 양쪽 `--space-1`을 뺀 64px, 버튼 안 좌우 2px 여백으로 이름 칸은 60px다. 12px 한글 기준 띄어쓰기 포함 5글자 정도가 들어간다.

## 측정

오른쪽 개요 패널(256px)이 열린 기본 배치. '문서 영역'은 탭 줄 폭, '문서 열'은 활성 문서 본문 상자 폭.

| 조건 | 막대 | 사이드바 | 문서 영역 | 문서 열 |
| --- | ---: | ---: | ---: | ---: |
| 지금, 1440 | 없음 | 240 | 944 | 896 |
| 시안 1, 1440 | 48 | 240 | 896 | 864 |
| **1-T, 1440** | 48 | 240 | 896 | 864 |
| **1-L, 1440** | 72 | 240 | 872 | 840 |
| 지금, 640 (사이드바 닫힘) | rail 48 | — | 592 | 560 |
| 시안 1, 640 | 48 | — | 592 | 560 |
| **1-L, 640** | 72 | overlay 200 (x=72부터) | 568 | 536 |

- **정렬**: PanelHeader·탭 줄은 모든 변형에서 y=40~73(가운데 56.5). 1-T 첫 아이콘 가운데 y=57. 1-L은 아이콘(20px)만 이 띠 가운데에 맞추고 이름은 띠 아래로 내려간다(아이콘 가운데 y=58, 항목 상자 y=43~91). 선택 배경도 띠 아래로 18px 넘는다.
- **항목 간격**: 1-L 항목 상자 48px(위아래 여백 4px씩, 아이콘 20px, 아이콘-이름 2px, 이름 16px 안팎), 항목 사이 4px로 52px 주기. 모든 항목에서 같았다. 1-T는 28px 버튼, 32px 주기(앞 시안과 같음).
- **말줄임**(60px 이름 칸): '템플릿 갤러리'→'템플릿 갤...', '요구사항 검토'→'요구사항 ...', '프로젝트 보고'→'프로젝트 ...'. 띄어쓰기 포함 5글자 이하('품질 점검'·'공정 분석'·'출시 점검' 등)는 잘리지 않았다. 한 줄 고정이라 줄바꿈은 생기지 않는다.
- **넘침**: 1-L은 1440×900·8개면 9개(템플릿+8)가 다 들어가지만, 1440×700·12개면 5개만 보이고 8개가 '더 보기'로 간다. 640×700·8개는 5개 보이고 4개 넘침. 1-T는 1440×900에서 13개 전부, 1440×700에서 11개 보이고 2개 넘침.

## 관찰

**1-L (아이콘 아래 이름)**
- 이름이 보여서 막대만 보고 어떤 플러그인인지 알 수 있다. 첫 글자가 같은 플러그인(합성 예의 '공정 분석'·'공급 문서')도 이름으로 구분된다.
- 대가가 크다. 넓은 창에서 문서 영역이 지금보다 72px(시안 1보다 24px) 줄고, 항목 높이가 28→48px이라 같은 창 높이에서 들어가는 플러그인이 절반 가까이로 준다(1440×700에서 12개 중 8개가 '더 보기'). 60px 칸이라 한국어 6글자 이상 이름은 잘린다 — 플러그인 이름을 짧게 쓰게 하거나 막대용 짧은 이름이 따로 필요해진다.
- 640×700에서는 막대 72px+overlay 200px가 화면의 42%를 덮고 overlay가 닫혀도 문서가 568px다. 겹침·잘림은 없었다.
- 아래 그룹은 아이콘만이라 막대 안에서 아이콘 크기(위 20px, 아래 16px)와 가로 정렬 기준이 두 가지가 된다.

**1-T (고유 아이콘·첫 글자 타일, 48px)**
- 막대 폭과 넘침은 앞 시안 1과 같고, 고유 SVG와 첫 글자 타일 덕에 아이콘이 서로 확실히 달라 보인다. 다만 '어떤 플러그인인지'는 여전히 Tooltip이나 '더 보기' 목록에서 이름을 봐야 안다. 첫 글자가 같은 플러그인(예: '공정 분석'·'공급 문서')이 둘 다 아이콘이 없으면 타일이 같아진다. 이번 합성 예에서는 한쪽이 SVG라 겹치지 않았다.
- 타일(강조색 면)과 플러그인 SVG(자기 색)가 섞이면 막대가 알록달록해지고, 패널 아이콘(16px 선 아이콘)보다 플러그인 쪽이 시각적으로 무겁다.
- 플러그인 SVG 색은 플러그인이 정하므로 다크에서 대비가 약할 수 있다(합성 초록 네 칸이 다크에서 흐림). 첫 글자 타일은 테마별 강조색·글자색 토큰이라 라이트·다크 모두 읽혔다.

**공통 — '더 보기' 목록**
- 검색칸+아이콘·이름 목록이라 12개를 이름으로 한 번에 훑을 수 있다. 막대 바로 오른쪽에 열려 탐색기 위를 덮는다(시안 3은 사이드바 바깥에 열렸음). 목록에 전체를 넣어 막대에 이미 보이는 항목도 반복된다.

## 검증하지 않은 것

- 실제 플러그인 설치와 manifest의 실제 SVG/PNG artifact. 아이콘 응답만 합성했다. PNG·큰 그림·투명 배경 없는 그림, 64px 이상 그림의 축소 모양은 보지 않았다.
- 한국어 외 언어 이름(영어 긴 단어), 사용자가 글꼴 크기를 바꾼 경우, 실제 Desktop(Electron) 창, Windows 배율 125·150%.
- 스크린 리더 낭독: 이름은 `aria-hidden`으로 두고 버튼 `aria-label`을 그대로 썼다. 키보드 이동(roving focus)은 앞 스파이크와 같이 구현하지 않았다.
- 기존 브라우저 시나리오는 시안 쿼리를 켠 상태로 돌리지 않았다. 쿼리 없는 기본 화면과 앞 시안 1·2·3은 이번 변경에서 class·변수만 늘었지만 전체 suite로 확인하지 않았다.
- 첫 글자 타일 규칙을 탭 줄·설정 화면의 플러그인 아이콘에는 적용하지 않았다(막대와 '더 보기' 목록만).

## 현재 결정과 어긋나는 점

앞 스파이크와 같다(#671의 상시 Activity Bar 도입 조건, Editor UX shell 계약의 rail·footer 배치, UI 결정표의 새 표면 구조). 더해서:

- [플러그인 실행 계약](../../docs/design/plugin-stage1-v1.md)은 아이콘이 없을 때의 표시를 정하지 않았고, Editor는 지금 FileText로 떨어진다. 첫 글자 타일은 새 표시 규칙이라 채택하면 화면 코드 계약 또는 UI 패턴에 적어야 한다.
- 72px 막대 폭은 기존 레이아웃 토큰(`--layout-sidebar-rail-width` 48px)에 없는 값이다. 채택하면 새 레이아웃 토큰이 필요하다.

## 추천

결론: **미정** (소유자 결정 전)

작업자 추천은 **1-T(48px + 고유 아이콘·첫 글자 타일)를 기본으로, 이름은 '더 보기' 목록과 Tooltip에서 보이게** 하는 쪽이다. 1-L은 이름 문제를 확실히 풀지만, 문서 폭 72px·한 화면에 들어가는 플러그인 수 절반·한국어 6글자 이상 잘림이라는 세 대가가 함께 온다. 1-T는 '서로 다르게 보인다'까지만 풀고 '무엇인지'는 풀지 않으므로, 소유자가 막대만 보고 이름을 읽어야 한다고 본다면 1-L이 맞다. 1-L을 고르면 플러그인 manifest에 막대용 짧은 이름(5글자 안팎)을 두는 것을 함께 검토할 가치가 있다.
