```text
## 공통 규칙
- AGENTS.md, CONTRIBUTING.md, docs/README.md에서 연결된 관련 설계 계약을 먼저 확인한다. 필요하면 `pnpm install`을 먼저 실행한다.
- 가장 작은 변경으로 해결한다. 무관한 리팩터링과 문서 수정은 하지 않는다. 현재 동작을 바꾸면 관련 설계 문서를 같은 PR에서 갱신한다.
- UI 작업은 `docs/design/ui-decision-table-v1.md`에서 표면·공통 구현·예외를 고른다. 기존 토큰·variant·아이콘 관례 안의 선택은 묻지 않고 정하며, 새 표면 구조·기존 계약 변경·새 공통 상호작용·공개 Plugin API 변경만 소유자에게 올린다. 결과에 선택한 공통 구현과 예외 이유를 적는다. 화면에는 상태·대상·지금 할 수 있는 행동만 상시로 두고, 설명·상세 사유·반복 안내는 hover·keyboard focus 안내로 충분하면 그렇게 한다(정보 자체는 접근 가능하게 유지). 실제 AI 호출로 응답을 확인해야 하면 AGENTS.md대로 가장 저렴한 모델을 쓴다.
- 기존 테스트 보완을 우선한다. 고유한 보호 가치가 있는 검사만 추가한다. 로컬에서는 CONTRIBUTING verification matrix에 따라 변경 영역의 대상 검사만 실행한다. 브라우저 시나리오는 이번에 고친 결함을 직접 잡는 것만 로컬에서 돌리고, 나머지 회귀는 CI에 맡긴다.
- 테스트나 시나리오·조합을 추가·확대하면 기존 검사와 다른 결함, 주된 검증 계층과 실행 경로를 적는다. 전수 조합·새 subprocess·무거운 E2E를 추가하면 대표 사례로 충분하지 않은 이유와 관측 실행 시간 또는 미측정 사유를 덧붙인다.
- 버그는 수정 전 실패를 먼저 확인한다. 재현할 수 없으면 추측성 수정 없이 근거를 보고한다.
- 브라우저는 `pnpm browser:test`(persistent profile)만 쓴다. Edge 채널, 패키지된 Desktop 검사, 새 profile을 만드는 probe는 로컬에서 실행하지 않고 CI에 맡긴다. <계정 잠금 임계값이 켜진 PC면 SKILL.md 3절의 카운터 대기 규칙을 여기에 붙인다. 꺼져 있으면 이 문장을 지운다>
- 화면이 바뀌면 PR을 올리기 전에 자기 캡처로 다음을 확인하고 고친다: 같은 행의 세로 중심·글자와 테두리 사이 여백·칸 안 쏠림 / 패널·스크롤바·화면 밖 잘림과 가림 / 오해 소지가 있는 문구와 한국어 줄바꿈 / 다크 테마와 한국어 640px / `docs/design/ui-patterns-v1.md`에서 같은 패턴을 쓰는 다른 화면과의 일치.
- 리뷰 agent나 하위 agent를 띄우지 않는다.
- 결정 범위 밖의 제품 판단이 필요하거나 이슈와 다른 원인을 발견하면, 구현을 멈추고 근거와 선택지를 보고한다.
- 커밋은 UTF-8 메시지 파일(`git commit --file`)로 만든다. 마지막 trailer 블록에 정확히 `AI-Agent: <agent>`, `AI-Model: <provider>/<model>`을 한 번씩 넣는다(실제 구현 모델). merge 커밋도 포함하고, Co-authored-by는 쓰지 않는다. 커밋마다 `git log -1 --format='%H%n%(trailers:only)'`로 확인한다.
- master를 base로 PR을 만든다. 본문에 `Closes #<N>`(일부만 해결하면 `Refs #<N>`), 변경 요약, 실행한 검증을 쓴다. 시각 변경은 1440px와 640px 전후 캡처를 남긴다. 재생성 가능한 대용량 근거 파일은 커밋하지 않는다.
- PR CI 결과까지 확인한다. 실패하면 재실행 전에 artifact를 분석해 제품 결함인지 테스트 문제인지 판정한다. 사람이 실제로 낼 수 있는 속도와 순서에서 생기면 제품 결함이다. 테스트 문제라면 단언을 약화하지 말고 실제 상태를 기다리게 고친다. 재시도나 timeout 증가로 덮지 않는다. 병합은 하지 않는다.
- 끝나면 직접 시작한 dev server와 브라우저 세션을 정리한다. 최종 보고에는 PR URL, head SHA, 변경 요약, 검증 결과, CI 상태, 남은 프로세스 여부, 범위 밖 발견을 포함한다. 한국어 정상 문장으로 보고한다.
```

## 후속 지시 예

- **master 반영:** "PR #<M>(<무엇을 바꿨는지>)이 master에 병합됐다. origin/master를 merge해 양쪽 의도를 보존하며 충돌을 해결하라. merge 커밋 trailer를 확인하고, 단위 테스트·typecheck·충돌 파일 관련 브라우저 시나리오만 실행한 뒤 push하라. CI까지 확인해 새 head와 결과를 보고하라. 병합하지 않는다."
- **queue 실패:** "PR #<N>이 merge queue 실행 <run-id>의 <job>에서 `<오류>`로 실패했다. `gh run download <run-id>`로 artifact를 받아 원인을 판정하라. (공통 규칙의 판정 기준을 적용) push 후 CI까지 확인해 원인, 수정, 새 head를 보고하라."
- **queue 감시(완료 알림이 오는 백그라운드 실행이 없는 하네스):** "PR #<N>을 merge queue에 넣었다. `node .agents/skills/litzio-orchestrator/scripts/queue-watch.mjs --wait <N>`을 실행해 병합이나 이탈을 확인하고 결과를 한 줄로 보고하라. 이탈했으면 원인(충돌 또는 merge_group 실패 run)까지 확인해 보고하라. 수정은 하지 않는다."
- **리뷰 중 대기:** "같은 worktree에서 독립 리뷰어가 브라우저로 검토한다. 이 worktree에서 브라우저와 서버를 실행하지 말고 CI 결과만 확인해 보고하라."
- **재개:** "모델 오류로 턴이 중단됐다. `git status`, `git log --oneline -3`, 열린 PR을 확인한 뒤 처음 지시대로 이어서 진행하라. 끝낸 단계는 반복하지 마라."
