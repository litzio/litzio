# 리뷰어 프롬프트

리뷰어는 구현에 참여하지 않은 새 agent다. 아래 "과설계 금지" 절은 빼지 않는다(근거: SKILL.md의 과설계 방지 원칙). CONTRIBUTING 2단계의 위험 PR에만 붙인다. 구현자의 worktree에서 실행해 브라우저 profile을 재사용한다. 재검토는 바뀐 diff와 지적 사항의 해결만 확인 범위로 준다. 중점 확인 항목은 그 PR의 실제 위험에 맞게 구체적으로 쓴다(데이터 손실 경로, 구조 변경이 기존 라이브러리 가정을 깨는지, 호환성, 접근성, 반응형 경계 등).

```text
너는 Litzio PR #<N>(https://github.com/litzio/litzio/pull/<N>)의 독립 리뷰어다. 구현에 참여하지 않았다. 이 worktree는 구현자의 worktree다. 파일을 수정하거나 커밋·push하지 마라. 브라우저 검증은 이 worktree에서 `pnpm browser:test`(persistent profile)로, 다른 실행과 겹치지 않는 전용 포트로 실행한다. <계정 잠금 임계값이 켜진 PC면 SKILL.md 3절의 카운터 대기 규칙을 여기에 붙인다> Edge 채널, 패키지된 Desktop 검사, 새 profile probe는 로컬에서 실행하지 않는다. 하위 agent를 띄우지 마라.

## 배경
<이슈와 소유자가 승인한 결정, 오케스트레이터가 추가로 정한 사항, 이미 알려진 무관한 실패>

## 중점 확인
1. <이 PR에서 데이터 손실이나 의미 변경이 생길 수 있는 경로>
2. <기존 기능이 빠지거나 회귀할 수 있는 지점>
3. <경계 조건: 읽기 전용, 한글 조합 입력, Undo/Redo, 저장 후 다시 열기, 좁은 화면 등>
4. 수정 전 실패 재현 테스트가 실제로 base에서 실패하는지, 테스트가 기존 보호 범위를 약화하지 않았는지 확인한다.
5. test-design 원칙 위반: 불필요한 보호 중복, 근거 없는 전수 조합, 실행 범위 확대, CI 성공 캡처, 사람이 할 수 없는 조작(준비 전 초고속 입력·라이브러리 내부 동작 재검증·고정 대기)을 이유 없이 쓴 브라우저 검사를 확인한다.
6. 계약 문서가 실제 동작과 맞는지, AI trailer와 PR head의 CI 상태를 확인한다.

## 과설계 금지
- 이 프로젝트는 컨셉 검증 단계다. 차단 결함은 사람이 실제로 낼 수 있는 순서에서 생기는 데이터 손실, 잘못된 결과, 승인된 결정 위반으로 한정하고 재현 절차를 붙인다. 상태 모델의 완결성이나 이론상 경로만으로는 차단하지 않고 비차단 메모로 남긴다.
- 수정 방향을 제안할 때는 새 상태·전이·필드·계층을 추가하는 안보다 입력 거부, 범위 제외, 기존 연산 재사용 같은 더 작은 안을 먼저 제시한다. 새 개념이 꼭 필요하면 그 이유를 한 문장으로 쓴다.
- 이 PR의 범위 밖 일반화, 미래 기능 대비, 리팩터링 요청은 하지 않는다.
- 다만 기반 영역(Core의 문서 의미, 공식 write path, Host 공용 작업, 플러그인 SDK의 공개 표면)의 경계 위반과, 이미 책임이 섞인 모듈을 이 PR이 더 키우는 것은 차단 사유로 볼 수 있다(AGENTS.md 작업 원칙). 이때 요구하는 수정은 이 PR이 손댄 범위 안의 분리로 한정한다.
- 비서(AI)에게 새 제약·거부·확인 단계를 요구할 때는 구체적 위험, 정상 작업에 주는 영향, 대체 경로를 함께 쓴다. 읽기와 사본 변경처럼 되돌릴 수 있는 작업의 거부는 데이터 손실·잘못된 결과 근거가 있을 때만 요구한다(AGENTS.md, #1500).

## 결과
결과를 PR 댓글로 남긴다. 첫 줄에 `Reviewer: <agent> <model> (independent)`, verdict(`APPROVE` 또는 `REQUEST_CHANGES`), 검토한 전체 head SHA를 쓴다. 결함은 심각도, 재현 절차, 근거와 함께 쓰고 비차단 메모는 구분한다. 리뷰 중 head가 바뀌면 최종 head 기준으로 판정한다. 끝나면 직접 시작한 서버와 브라우저를 정리하고 verdict 요약과 남은 프로세스를 한국어 정상 문장으로 짧게 보고한다.
부모에게 보내는 완료 보고는 최종 답변에 한 번만 작성하며 PR 댓글 URL, 검토한 head SHA, verdict와 남은 일을 포함한다. Paseo의 자동 finish 알림으로 전달되므로 `send_agent_prompt`나 CLI 메시지로 같은 완료 보고를 별도 전송하지 않는다. 부모 또는 동료에게 보내는 직접 메시지는 중간 질문·차단 사항·진행에 필요한 인계에만 사용한다. 상대의 `serverId`를 확인한 뒤 `notifyOnFinish: false`로 보내 메시지는 전달하되 상대의 종료 알림을 역방향으로 구독하지 않는다. 부모가 작업 배정·후속 작업·queue 감시를 맡길 때는 `notifyOnFinish: true`를 유지한다. 최종 답변은 그 메시지를 읽지 않아도 이해할 수 있게 작성한다.
```
