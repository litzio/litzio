# Changelog

## 0.0.6

- 연결 설정 표시 이름을 사용자 표현으로 바꾸고 SDK 0.4.0을 요구합니다. 저장 키는 유지합니다.

## 0.0.5

- 계정·프로젝트·해결 여부만 기본 표시하고 나머지는 공통 추가 조건으로 접습니다.
- PAT 표시 이름 안내와 계정·보고자·프로젝트 자동완성(read 작업)을 연결합니다. 안내는 조회 인자를 바꾸지 않습니다.
- 기본 7열과 추가 후보 6열을 공통 열 선택에 연결하고 500행 상한의 잘림·Jira 전체 건수를 표시합니다. 회사 Jira 확인은 소유자에게 남깁니다.

## 0.0.4

- 검색에 행 데이터용 fields만 요청하고 페이지당 최대 500건을 순차 조회. 서버의 작은 페이지도 실제 반환 건수로 이어서 조회. 8초·500행·Host RPC 예산 유지.
- Created·Updated·댓글·조회 시각은 Host PC 현지 `YY-MM-DD HH:mm`, dueDate는 `YY-MM-DD`로 축약.
- 큰 불필요 필드가 있는 가짜 HTTP 서버의 300건 비교는 PR에 기록. 실제 회사 Jira 200~300건 성공은 소유자 확인 필요.
- 표 열 선택·입력 자동완성 적용은 다음 버전으로 유지.

## 0.0.3

- 일반 Lucide Ticket SVG를 manifest icon으로 선언해 사이드바·탭·설정 목록에서 재사용. ISC 라이선스 고지 포함.

- JQL 검색 v1이 기본이며 간편 검색 issues v4는 같은 경로 위에서 JQL만 조립. 두 기본 뷰 제공, 키별 404 자리 행은 검색 결과로 전환. 400은 기존 failed 고정 안내, 자세한 오류는 Jira 웹에서 확인.
- 기본 표시를 Key·제목·Status·Assignee·Reporter·Created·Updated 7열로 정리. 추가 후보 필드는 행 스키마와 데이터에 보존.
- 프로젝트 키·보고자·생성/수정 기간 AND 검색, JQL escape·날짜 유효성 검사. 500건·8초와 실제 페이지 offset 유지.
- 비서/CLI 공용 read `detail` v1: 설명·최근 생성 댓글 최대 10개, 출처·조회 시각·댓글 범위·본문 상한과 잘림 표시. 화면 상세 패널·Jira 쓰기 없음.
- 제한: 생성일과 수정일 기간을 동시에 거는 조건은 지원하지 않음. 기간 기준(수정일 기본/생성일)과 시작일·종료일로 입력 8개를 유지하며 정렬은 최근 수정순.
- 실제 Jira 검증은 소유자 수행. 공통 표 열 선택은 #1351 후속.

## 0.0.2

- 현재 사용자 또는 선택 계정의 할당 이슈를 미해결(기본)·해결됨·전체로 수동 조회. 최근 수정순, 안전한 JQL 계정 escaping.
- 실제 반환 건수로 페이지 진행, 전체 8초 제한. 최대 500건까지 표시하며, 넘는 경우 따로 알리지 않음.
- 동일 `community.jira.issues` v2 작업으로 화면·CLI 조회. 기존 번호 조회를 같은 폼의 보조 입력으로 유지하고 번호 입력 시 우선 적용.
- 없는 이슈는 짧은 `없음 (404)` 상태. redirect는 기존 failed 고정 안내. healthCheck와 SDK 0.3.0 경계 유지.
- 제한: 자동 첫 조회·행 Tooltip·입력 옆 버튼·잘림 안내는 공통 계약의 후속 후보. 실제 Jira 확인은 소유자 수행.

## 0.0.1

- 설정 창에서 연결 확인. PAT 인증을 포함한 현재 사용자 조회와 안전한 고정 안내.

- Jira Data Center 9.12.28 대상 BASE_URL/API URL 설정, context path, 필수 PAT secret 및 Bearer 인증.
- 최대 20개 키의 상세 조회와 공통 표·입력 폼, 동일 CLI 공용 작업.
- 일부 404 행, 안전한 오류 분류, 8초 전체 제한과 redirect 거부.
- 이슈 키를 누르면 Jira 이슈 페이지로 이동. BASE_URL 기반 URL과 SDK 0.3.0 공통 링크 열을 사용.
- 제한: 번호 없는 검색·JQL·쓰기·동적 UI·맞춤 즐겨찾기 없음. 실제 회사 Jira는 소유자 확인 필요.
