## 알려진 제약과 수동 확인

- 빠른 저장의 실제 업무 문서 적중률은 측정하지 않았다. 측정은 합성 문서에서만 했다. 5,000블록 문서 탭은 110초 안에 편집기가 준비되지 않아 열기·저장 시간을 측정하지 못했다. 같은 크기의 HTTP Host와 플러그인 문서 보기는 측정했다. [빠른 저장](https://github.com/litzio/litzio/pull/1991), [작업 스레드](https://github.com/litzio/litzio/pull/1988).
- 빠른 저장 직후 뒤따르는 확인이 끝나기 전(5,000블록 표 칸에서 최장 약 4.5초)에 Host가 종료되면 확인이 남지 않는다. 이 틈은 다음 열기의 네이티브 검사로 확인한다. 확인이 진행 중일 때 도착한 같은 문서의 저장은 전체 경로를 탄다. [편집 세션 저장 계약](../design/editing-session-save-v1.md), [#1986](https://github.com/litzio/litzio/issues/1986).
- Ollama 그림 전달은 파일 보기를 명시한 턴에서 확인했다. 작은 로컬 모델이 스스로 그림을 열어 수식을 판독한 과제는 0/3이었다. [그림 전달](https://github.com/litzio/litzio/pull/1966).
- 새 빌드 설치 뒤 기존 플러그인이 자동으로 켜지지 않는 원인과 0.0.3부터 이어지는 실제 Windows 한국어 IME 확인은 남아 있다. [자동 켜기](https://github.com/litzio/litzio/issues/1918), [Stable 수동 확인](v0.0.3.md#사용자-수동-확인-안내).
- 실제 GitHub 설치·업데이트, Windows SmartScreen·게시자 표시와 서명 배포는 미검증이다. IeumDoc에서 자동 업데이트할 수 없으며 새 설치가 필요하다. [Desktop 계약](../design/desktop-distribution-v1.md#channels-and-versions).

## 한국어 Release 본문 초안

서명 없는 Windows Beta 배포입니다. Windows에 게시자 또는 SmartScreen 경고가 나타날 수 있습니다. SHA-512는 파일 무결성을 확인하며 게시자를 인증하지 않습니다. Unsigned Windows Beta. Windows may show publisher or SmartScreen warnings. SHA-512 checks file integrity; it does not authenticate the publisher.

Litzio v0.0.4-beta.2의 0.0.4-beta.1 이후 주요 변경입니다.

- **문서에서 찾기.** 문서에서 Ctrl+F를 누르면 찾기 막대가 열립니다. 일치하는 곳을 모두 표시하고 Enter·F3으로 다음, Shift+Enter·Shift+F3으로 이전 일치로 이동합니다. 플러그인 화면의 문서 보기에서도 쓸 수 있습니다.
- **큰 문서 저장.** 큰 문서를 저장하는 시간이 줄고 저장 중에도 화면이 멈추지 않습니다. 한 줄 문단이나 표 칸 하나를 고친 저장은 그 부분만 다시 쓰고, 뒤에서 기존 방식으로 한 번 더 확인합니다. 결과가 다르면 기존 방식의 결과로 파일을 바로잡고 알림으로 알려 드립니다.
- **표.** 표 칸 안에서 Shift+Enter로 줄을 바꾸고, 표 아래에 표 주석을 달 수 있습니다. 표는 최대 500행·32열·8,000칸까지 만들 수 있습니다.
- **문서 안 링크.** 문서 안의 다른 위치로 링크를 걸고 Ctrl+클릭으로 이동합니다. 링크와 번호 참조에 마우스를 올리면 대상 표·그림·수식·절을 미리 볼 수 있고, 링크와 참조는 파란색으로 표시됩니다.
- **플러그인.** 플러그인 화면의 문서 보기에서 문서 구조는 그대로 둔 채 내용을 고쳐 저장할 수 있습니다.
- **비서.** Ollama 모델이 그림을 지원하면 비서가 연 그림 파일을 모델에 전달합니다. 새 문서를 만들 때 잘못된 입력은 어떤 항목이 문제인지 알려 줍니다.

**알려진 제약.** 아주 큰 문서(5,000블록)를 문서 탭으로 열 때의 시간은 측정하지 못했습니다. 작은 로컬 모델은 그림을 스스로 열지 않을 수 있습니다. 실제 GitHub 업데이트는 확인하지 않았습니다.

**채널.** Stable 채널에는 이번 Beta가 표시되지 않습니다. 0.0.3에서 받으려면 설정에서 Beta 채널을 선택하세요. 이미 저장한 채널 선택은 유지됩니다.

전체 변경과 검증 범위는 [배포 기록](https://github.com/litzio/litzio/blob/v0.0.4-beta.2/docs/releases/v0.0.4-beta.2.md)에 있습니다.

## 검증과 게시 판단

- 로컬에서 `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm docs:check`, Desktop 단위 검사 108건(PowerShell)과 `git diff --check`를 통과했다. Git Bash에서 같은 단위 검사를 실행하면 Windows 프로세스 조회·창 시작 검사 25건이 실패했고 PowerShell에서는 모두 통과했다. 실행 셸의 환경 차이로 판단했다.
- 격리 경로(Host 데이터·비서 작업·비서 설정·daemon·플러그인 설정, `LITZIO_RESET_DIR`, `TEMP`/`TMP`)로 clean Windows `package`를 만들고 `verify-release.ts --tag v0.0.4-beta.2`로 설치 파일·blockmap·`beta.yml`(버전 `0.0.4-beta.2`)을 확인했다.
- `test:packaged`는 12건 중 11건이 통과했다. 실패 1건은 창 내용 폭을 1440px로 바꾼 뒤 1439px을 받은 단언이다. 이 PC의 주 화면이 요청한 창보다 좁아 생긴 환경 차이로 판단했고 CI의 Windows Desktop 검사에 맡긴다. 시험은 고유 profile과 격리 daemon을 쓰며 실행 전후 Litzio 프로세스가 없었다.
- `test:update`·`test:uninstall`은 CONTRIBUTING에 따라 작업용 PC에서 실행하지 않았다. 공개 설치본 회귀(공개 0.0.3 설치 파일 사용)는 릴리스 워크플로에서만 실행된다. 로컬에서는 대신 이 사례가 조작하는 0.0.3 화면 요소를 `v0.0.3` 태그 소스와 대조했다: 설정 단추(`Settings` 이름표), 설정 분류 `About & updates`, `app-version`, 문서 준비 상태(`status`의 `data-operation`), 릴리스 채널 선택 상자(`Release channel` 이름의 `<select>`, 값 `stable`·`beta`), Desktop bridge `info()`의 `channel`. 모두 현재 검사가 가정하는 이름·역할·값과 일치한다. 0.0.4-beta.1 게시 워크플로가 같은 사례를 통과했다.
- 빠른 저장의 전체 대조(`pnpm exec tsx packages/core/test/local-write-corpus.ts`)를 master `39835125`에서 실행했다. 35개 문서의 9,652건 가운데 빠른 저장 2,284건(문단 866, 표 칸 1,418), 전체 경로 선택 2,240건, 건너뜀 1건이며 불일치는 0건이다. 실행 시간은 약 4분 24초였다([#1986](https://github.com/litzio/litzio/issues/1986) 조건 3의 릴리스 확인).
- 같은 소스의 CI local-feed는 Stable `0.0.1 → 0.0.2`와 Beta `0.1.0-beta.1 → 0.1.0-beta.2`를 사용한다. 릴리스 전 공개 설치본 회귀는 SHA-256 고정 공개 Stable `0.0.3` 위에 이 Beta 후보를 빌드해 NSIS 설치·시작·보존을 확인한다.
- 실제 GitHub opt-in의 대상은 `0.0.3 → 0.0.4-beta.2`다. 공개 0.0.3 설정에서 Beta 채널을 선택하며 후보 공개 후 실행할 수 있다. 실행하지 않았다.
- 게시 워크플로는 태그가 가리킨 커밋에서 브라우저 8개 shard, 공개 설치본·Stable·Beta 설치/업데이트와 전체 제거, 최종 패키지와 자산 검증이 성공해야 게시한다.

## 게시 후 기록 PR에서 바꿀 항목
