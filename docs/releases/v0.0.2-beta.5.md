- Status: Draft
- Last verified: 2026-11-02 (beta.4 이후 master 병합 이력과 실제 PR 본문·브랜드 계약 대조. 공개·설치·업데이트 결과가 아님).
- Scope: [#926](https://github.com/litzio/litzio/issues/926)의 Windows x64 unsigned Beta 준비 PR. 직전 공개는 IeumDoc beta.4이며 [기존 기록](v0.0.2-beta.4.md)은 후속 이름 정리로 Litzio 표기를 사용한다.

## 준비 단계 작업 계획

- 소유자의 2026-11-02 최신 지시에 따라 오늘 작업을 마친 master를 기준으로 한다. 이슈 본문의 이전 #892·#901 제외 계획 대신 실제 병합 결과를 포함한다.
- Desktop 후보를 `0.0.2-beta.5`로 올리고 startup 버전 fixture를 맞춘다. 공개 버전은 IeumDoc `0.0.2-beta.4`로 유지한다.
- opt-in 실제 GitHub harness의 향후 대상은 같은 브랜드 Litzio `0.0.2-beta.5 → 0.0.2-beta.6`으로 설정한다. 둘 다 공개된 뒤에만 실행할 수 있으며 beta.5 공개나 업데이트 검증 완료를 뜻하지 않는다.
- #960은 아래에 병합 대기로 분리한다. 병합 통보 후 master를 반영해 범위와 로컬 검사·CI를 확정한다.
- 제외: 기능 코드 변경, tag 생성, release workflow 실행·게시, 병합, 로컬 앱 실행·설치·패키징, test:update·test:uninstall, 브라우저(Edge 포함), PATH·레지스트리·사용자 데이터 변경.
- 완료 기준: 지정된 로컬 검사와 준비 PR의 필수 CI 성공 후 PR·head SHA·검증 범위를 전달한다. 게시·공개 자산 확인은 오케스트레이터의 후속 작업이다.

CI local-feed fixture는 Stable `0.0.1 → 0.0.2`, Beta `0.1.0-beta.1 → 0.1.0-beta.2`를 유지한다. 공개 자산을 쓰는 GitHub LIVE 검증과 구별한다.

| 검사 | 결과 |
| --- | --- |
| Frozen install | `pnpm install --frozen-lockfile` 통과, lockfile 변경 없음 |
| Desktop 단위 테스트 | `pnpm --filter @litzio/desktop test` 85/85 통과 |
| Typecheck | `pnpm typecheck` 전체 workspace 통과 |
| 문서·공백 | `pnpm docs:check`, `git diff --check` 통과 |

| 실제 GitHub 설치·업데이트 | **미실행·미검증**. 이 PC의 설치 상태 보존 제약을 따른다. CI local-feed 성공으로 대신하지 않는다. |

## 알려진 제한과 수동 확인

- **제품 이름 변경(IeumDoc → Litzio)으로 앱 ID·설치·데이터 경로가 바뀌어, IeumDoc beta.4 설치본은 Litzio로 자동 업데이트되지 않는다. 새로 설치해야 한다. IeumDoc 데이터·설정·복구 기록·플러그인 설치는 이전되지 않는다.** 호환 alias도 제공하지 않는다.
- 새 앱은 `io.github.litzio.litzio`, 기본 설치 `%LOCALAPPDATA%\Programs\litzio`, 데이터 `%APPDATA%\litzio`, 공용 플러그인 `~/.litzio/plugins`를 사용한다. [브랜딩 안내](../guides/branding.md)를 따른다.
- 개발 단계이므로 과거 문서·복구 기록·설정의 하위 호환성과 자동 migration을 보장하지 않는다. 중요한 원본 문서는 따로 백업한다. 네이티브 표식도 `litzio: 1`이며 과거 표식 호환을 보장하지 않는다.
- unsigned Beta는 Authenticode 게시자 인증을 제공하지 않는다. 체크섬은 무결성 확인이며 SmartScreen·조직 보안 경고가 나타날 수 있다. Stable은 미공개다.
- AI 비서는 Codex 설치·로그인이 필요하다. 현재 Codex app-server와 사용자 Codex 환경을 재사용한다. Docling PDF 변환은 별도 외부 REST 서버가 필요하다. 자동 검사·synthetic REST/AI는 실제 서비스 수용성 증명이 아니다.
- 실제 GitHub 설치·업데이트는 이 PC의 설치 상태 보존 제약으로 **미실행·미검증**이다. 향후 같은 브랜드 beta.5 → beta.6 harness와 CI local-feed는 별도 근거다.

다음은 별도 수동 확인 항목이며 이번 준비 작업에서는 실행하지 않는다. [수동 확인 경계](../test/README.md#manual-review)를 따른다.

- 실제 Windows 창 드래그·더블클릭 최대화, SmartScreen·설치 안내
- 한글 IME 수식·캡션·그림 속성 입력, 본문 이동 후 즉시 입력
- Desktop CLI 켜기·끄기, 탐색기·외부 링크·로그 폴더 열기
- 복구 비교·저장 전 변경점 보기, 샘플 열기·교체, 두 그룹 편집·Undo
- 실제 Docling 서버의 PDF 변환·원본 대조·원문 번호, 구조 검수·승인·되돌리기·페이지 제외
- 실제 Codex 연결·대화 기록 재개·문서 생성, 모델·언어 설정과 중단
- 별도 Windows 환경에서 Litzio 새 설치 및 IeumDoc 데이터가 자동 이전되지 않는 경계
