## 준비 근거와 승인

- 2026-11-23 소유자가 현재 master를 v0.0.3 Stable로 내기로 결정했다. 게시 모드는 `unsigned`다(2026-11-12 소유자 결정, 서명 없음 경고 유지).
- 소유자는 Beta를 먼저 거치지 않고 바로 Stable로 내기로 했다. 따라서 beta.6 이후 병합된 PR 16개(#1854, #1855, #1865~#1873, #1875, #1878, #1879, #1882, #1883)는 설치본으로 써 본 사람이 없다. beta.6의 실제 Windows 한국어 IME 수동 확인 5건도 아직 미확인이다. 두 사실을 아래 수동 확인 안내와 Release 본문의 알려진 제약에 적었다.
- 집계 기준은 master `a56d0504867547ca42f441f5c9e122d1f511e012`(#1883 병합)다. `git log --first-parent --merges v0.0.2..a56d0504`의 병합 203개를 beta.1~beta.6 기록의 포함 변경 표와 대조했다. beta.6 이후 범위는 `git log --first-parent --merges v0.0.3-beta.6..origin/master`와 각 PR 본문으로 확인했다.
- 순서: 이 준비 PR의 CI → 통합 담당자의 병합과 merge queue Windows 확인 → 검증한 master에 `v0.0.3` tag → master에서 `unsigned` 실행 → 전체 release 검사 성공 뒤 게시 → 공개 자산과 한국어 본문 확인, 기록 PR. 이 준비 작업에서는 병합·tag·workflow 실행·게시를 하지 않는다.

## 사용자 수동 확인 안내

자동 검사가 판정하지 않는 항목이다. 확인 전에는 제품 성공으로 선언하지 않는다.

**beta.6에서 넘어온 실제 IME 확인(미확인).** Tiptap·ProseMirror 갱신(#1840)은 CDP 조합 입력으로만 시험했고, 이후의 ProseMirror 셋 갱신(#1855)은 브라우저 회귀로만 시험했다. 실제 Windows Microsoft 한국어 IME로 다음을 확인해야 한다.

1. 문단 끝에서 한글을 조합하던 중 Enter: 조합 중인 글자가 남고 새 문단이 정확히 한 번 생기는지
2. 조합 중 Backspace: 자모 단위로 지워지고, 이전 글자나 앞 블록이 지워지거나 합쳐지지 않는지
3. 표 셀·표 캡션·Figure 캡션·각주 정의 안에서 1, 2와 같은 동작
4. 빠르게 연속 입력한 직후 Enter/Backspace(예: `안녕하세요` 입력 직후 Enter)
5. 명령 센터나 대화 상자를 닫고 Editor로 돌아온 직후 바로 한글 조합 입력: caret이 원래 위치에 있는지(#542 경로)

**#1855 ProseMirror 셋 갱신.**

6. Markdown 입력 규칙(`# `, `- `, `1. `, `> ` 등)과 그 직후 Backspace 되돌리기가 이전과 같은지. 한국어 IME로 입력한 뒤에도 같은지

## 게시할 한국어 Release 본문

첫 단락의 unsigned 경고는 workflow가 넣으므로 그대로 둔다. 그 아래를 게시 뒤 본문으로 적용한다.

서명 없는 Windows Stable 배포입니다. Windows에 게시자 또는 SmartScreen 경고가 나타날 수 있습니다. SHA-512는 파일 무결성을 확인하며 게시자를 인증하지 않습니다. Unsigned Windows Stable. Windows may show publisher or SmartScreen warnings. SHA-512 checks file integrity; it does not authenticate the publisher.

Litzio v0.0.3 Stable의 0.0.2 이후 주요 변경입니다. 0.0.3-beta.1~beta.6의 변경과 그 이후 변경을 함께 담았습니다.

- **작업 막대와 알림.** 창 왼쪽의 작업 막대에서 탐색기, 템플릿 갤러리, 플러그인 화면, 설정과 연결 상태를 바로 엽니다. 설정에서 막대 이름을 숨겨 아이콘만 둘 수 있습니다. 알림은 종이 있는 오른쪽 위에 나타납니다.
- **비서.** 비서가 원본 문서를 바로 고치고, 대화에서 바뀐 내용을 비교하거나 되돌릴 수 있습니다. 미저장 편집이 없는 열린 문서는 외부 변경을 바로 보여 줍니다. Codex와 Copilot 대화 기록을 한곳에서 검색해 이어 가고, 이름 바꾸기와 보관을 할 수 있으며, 입력창에서 이미지와 파일을 바로 첨부합니다.
- **편집.** 표 안에서 행·열 도구와 우클릭 메뉴로 행·열을 다루고 위·아래 화살표로 같은 열을 이동합니다. 문서에 검토 상태를 붙일 수 있고, 선택한 글자 뒤에 미주를 넣는 버튼이 생겼습니다. 목록 아래 Backspace와 제목 맨 앞 Enter가 일반 편집기처럼 동작합니다.
- **붙여넣기와 검색.** 메모장이나 AI 채팅의 마크다운 글자를 붙이면 서식으로 들어갑니다(글자 그대로는 Ctrl+Shift+V). 한글 입력기가 영문 상태여도 슬래시 메뉴와 명령 센터에서 한글 항목을 찾습니다(예: `/vy` → 표).
- **저장.** `**정확도(Accuracy)**를`처럼 문장부호에 붙은 굵게·기울임과, 줄 맨 앞이 `+++`·`%`·`:::`인 문단을 저장합니다. 큰 문서의 작성과 입력 부담을 줄였습니다.
- **플러그인.** 플러그인이 자기 화면을 제공합니다. 설정에서 로컬 폴더나 공개 GitHub 저장소의 플러그인을 추가하고 버전 확인과 업데이트를 할 수 있습니다. 선언형 화면, Docling 원문 검수, 기존 실험 플러그인은 제거됐으며 호환되지 않습니다.
- **화면.** 글씨·부품·움직임 규칙을 하나로 맞추고 설정 화면과 Windows 방식의 폴더·파일 선택 창을 정리했습니다. 한국어 문구를 용어집에 맞췄습니다. 다른 PC Host를 등록하는 화면을 없애고 같은 PC의 연결 하나로 정리했습니다.
- **보안과 기반.** Electron 45.4.1(Node 24.22.3), Tiptap·ProseMirror, PDF.js와 보안 수정이 있는 의존성을 갱신했습니다.

**업데이트 전에.** 열린 문서를 모두 저장하세요. 이전 탭·기억·복구 기록과 0.0.2 비서의 적용 전 사본은 새 형식으로 옮기지 않으므로, 업데이트 뒤 필요한 문서를 직접 다시 여세요. 0.0.2에 등록한 플러그인은 파일을 보존한 채 비활성으로 표시되며, 다시 쓰려면 원본 폴더를 다시 추가하고 신뢰해야 합니다. 개발 단계로 과거 데이터 하위 호환을 보장하지 않습니다.

**알려진 제약.** 마지막 Beta(0.0.3-beta.6) 이후의 변경(작업 막대 이름 숨기기, 영문 자판 한글 검색, 한국어 문구 정리, 설정 Escape와 미주 호버 수정, 이름 바꾸기 중 외부 변경 오경고 수정, ProseMirror 일부 갱신, 내부 구조 정리)은 Beta로 먼저 내지 않고 이번 Stable에 바로 담았습니다. Tiptap·ProseMirror 갱신 뒤 실제 Windows 한국어 IME 입력(조합 중 Enter·Backspace, 표 셀·캡션·각주 안 입력, 대화 상자를 닫은 직후 입력)은 확인하지 않았습니다. 마크다운 붙여넣기는 글 전체를 읽을 수 있을 때만 서식으로 넣습니다. GitHub 플러그인은 공개 저장소만 지원하며 업데이트 확인과 적용은 수동입니다. 비서의 변경 보기·되돌리기는 공급자 편집 이벤트가 있는 기존 UTF-8 파일(1 MiB 이하)에 한정되며 셸 직접 쓰기 등은 경로만 표시합니다. [현재 비서 한계](https://github.com/litzio/litzio/blob/v0.0.3/docs/design/main-agent-v1.md#현재-한계)를 확인하세요. 실제 GitHub 설치·업데이트, SmartScreen·게시자 표시와 서명 배포는 미검증입니다.

**채널.** Stable 설치본의 최초 기본 채널은 Stable이며 저장된 채널 선택은 유지됩니다. Stable 채널의 0.0.2 사용자는 0.0.3을 받습니다. Beta 채널 사용자도 설치된 0.0.3-beta.N보다 높은 0.0.3을 받으며, 채널은 Beta로 남습니다. 이번 Stable은 latest.yml만 제공합니다.

전체 변경과 검증 범위는 [배포 기록](https://github.com/litzio/litzio/blob/v0.0.3/docs/releases/v0.0.3.md)에 있습니다.

### 채널 안내의 근거

- Stable 채널은 GitHub의 latest full release와 `latest.yml`만 읽고 더 높은 Stable semver만 제안한다([채널 표](../design/desktop-distribution-v1.md#channels-and-versions), `apps/desktop/src/update-policy.ts`의 `configureUpdater`·`offerFor`).
- Beta 채널은 `allowPrerelease`로 release feed에서 가장 새 semver tag를 고른다. 고정된 electron-updater 6.8.12의 `GitHubProvider`는 Stable tag(`v0.0.3`)도 고르며, 그 Release에 `beta.yml`이 없으면 `latest.yml`로 대체해 읽는다. `offerFor`는 `0.0.3 > 0.0.3-beta.6`이고 prerelease가 아니므로 Beta 채널에도 제안한다.
- 유효하게 저장된 채널 선택은 다른 버전을 설치한 뒤에도 유지된다. 따라서 Beta 채널 사용자는 0.0.3 설치 뒤에도 Beta 채널에 남는다.

## 검증과 게시 판단

이 PR에서 실행한 로컬 검사(Windows 작업용 PC):

- `pnpm install --frozen-lockfile`, `pnpm docs:check`, `pnpm --filter @litzio/desktop typecheck`, `git diff --check`가 통과했다.
- Desktop 단위 검사 `pnpm --filter @litzio/desktop test` 105건이 PowerShell에서 모두 통과했다. 처음 Git Bash에서 실행했을 때는 22건이 실패했다. `window-startup` 20건은 coreutils `whoami`가 Windows `whoami.exe`를 가려 생겼고, 소스 버전을 원래 값으로 되돌려도 똑같이 실패했다. `installation-lifecycle`·`reset-guard` 2건은 그 셸에서 Windows PowerShell 시작 오류(0x8009001d)로 실패했다. PowerShell에서 다시 실행하자 전부 통과해 이번 변경과 무관한 실행 셸 문제로 판정했다.
- 실행하지 않음: 로컬 패키징, 자산 검증, packaged·`test:update`·`test:uninstall`(CONTRIBUTING상 작업용 PC 금지), 브라우저 회귀, 실제 GitHub 설치·업데이트, SmartScreen·게시자 표시와 서명.

`update.e2e.ts` 변경과 그 검증 경로:

- CI의 같은 소스 Stable `0.0.1 → 0.0.2`, Beta `0.1.0-beta.1 → 0.1.0-beta.2` 쌍은 그대로다. 업데이트 알림 문구의 채널 표시를 `BETA` 대신 목표 버전에서 정하도록 바꿨지만 두 쌍에서는 값이 같다. merge queue의 Windows Desktop 설치·업데이트 검사가 확인한다.
- release workflow의 공개 0.0.2 Stable 회귀(`LITZIO_TEST_PUBLISHED_BASE=1`)는 Beta 후보를 전제한다(Beta daemon 위치와 `beta.yml` 복사). Stable 후보 버전 `0.0.3`으로 빌드하면 `latest.yml`만 생겨 실패하므로, v0.0.2 Stable 때와 같이 같은 소스의 Beta fixture 버전 `0.1.0-beta.2`를 공개 0.0.2 위에 설치한다. 이 검사는 PR·queue CI에서 돌지 않고 release workflow에서만 돈다. 실제 버전 `0.0.3` 빌드는 workflow의 최종 패키지와 자산 검증이 다룬다.
- LIVE opt-in harness의 대상은 Beta 채널의 `0.0.3-beta.6 → 0.0.3`이다. v0.0.2 때(#1560) 최신 공개 Beta → Stable 후보로 정한 원칙을 따랐다. 0.0.3 게시 전이라 실행할 수 없고 실행하지 않았다.
