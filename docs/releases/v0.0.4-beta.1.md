## 알려진 제약과 수동 확인

- 설치본에서 **플러그인 폴더 열기**가 실제 Windows 탐색기를 여는지는 미확인이다. Desktop의 **Ctrl+W**와 경로·복구 내용 복사는 개발 실행과 관련 자동 검사까지 확인했다. Ctrl+W는 Desktop 전용이다. [폴더 열기](https://github.com/litzio/litzio/pull/1930), [탭 닫기](https://github.com/litzio/litzio/pull/1945), [클립보드](https://github.com/litzio/litzio/pull/1944).
- Ollama는 Copilot CLI 설치가 필요하다. 추론 켜기·끄기는 실제 `qwen3.5:4b`에서 확인했고 단계형과 미지원 모델은 가짜 서버로만 확인했다. `qwen3.5:4b`의 플러그인 제작은 실패했고, `gemma4:e4b`는 현재 제품과 같은 Copilot CLI 경로의 격리 실험에서 3회 중 1회 성공했다. 새 Ollama 설정·대화 형식으로 이전 실험의 Copilot 로컬 설정·대화 기록을 변환하지 않는다. [공급자 분리](https://github.com/litzio/litzio/pull/1925), [모델별 추론](https://github.com/litzio/litzio/pull/1943), [입력 경량화](https://github.com/litzio/litzio/pull/1932), [실모델 과제 기록](../spikes/2026-11-24-ollama-pi-audio.md).
- 새 빌드를 설치한 뒤 기존 플러그인이 자동으로 켜지지 않는 원인은 확인 중이다. 이번 변경으로 실패 사유를 화면과 로그에서 볼 수 있다. 격리 시험에서는 설치 중 서비스가 강제 종료되면 설치본이나 다운로드 임시 폴더가 남았다. 여러 서비스가 한 저장소를 함께 쓸 때의 소유 규칙과 이 잔여 폴더 정리는 실제 사례가 나올 때까지 보류됐다. [자동 켜기](https://github.com/litzio/litzio/issues/1918), [잔여 폴더](https://github.com/litzio/litzio/issues/1931), [저장소 공유](https://github.com/litzio/litzio/issues/1933).
- 인라인 수식을 빈 채로 취소했을 때의 커서 위치 단언이 병합 대기열에서 한 번 실패했다. 이후 대기열은 통과했고 원인은 확인되지 않았다. [실패 실행](https://github.com/litzio/litzio/actions/runs/45332228773), [후속 통과 실행](https://github.com/litzio/litzio/actions/runs/45333561207).
- 0.0.3부터 이어지는 실제 Windows 한국어 IME 확인이 남아 있다. 문단 끝의 조합 중 Enter·Backspace, 표 셀·캡션·미주, 대화 상자를 닫은 직후 커서 위치를 실제 IME로 확인해야 한다. Markdown 붙여넣기는 글 전체를 읽을 수 있을 때 서식을 적용한다. [Stable 수동 확인](v0.0.3.md#사용자-수동-확인-안내), [붙여넣기](https://github.com/litzio/litzio/pull/1844).
- GitHub 플러그인은 공개 저장소를 지원하며 업데이트 확인·적용은 수동이다. 비서의 변경 보기·되돌리기는 공급자 편집 이벤트가 있는 기존 UTF-8 파일(1 MiB 이하)에 한정된다. [플러그인 계약](../design/plugin-stage1-v1.md), [비서의 현재 한계](../design/main-agent-v1.md#현재-한계).
- 실제 GitHub 설치·업데이트, Windows SmartScreen·게시자 표시와 서명 배포는 미검증이다. IeumDoc에서 자동 업데이트할 수 없으며 새 설치가 필요하다. [Desktop 계약](../design/desktop-distribution-v1.md#channels-and-versions).

## 한국어 Release 본문 초안

워크플로가 넣는 unsigned 경고 다음에 붙일 본문이다.

Litzio v0.0.4-beta.1의 0.0.3 이후 주요 변경입니다.

- **비서와 로컬 모델.** 비서에서 Ollama를 골라 준비한 로컬 모델로 대화할 수 있습니다. 모델에 따라 생각을 켜고 끄거나 지원하는 단계만 선택할 수 있습니다. 진단 화면에서는 Ollama 연결과 Copilot CLI 상태를 따로 확인하고, Codex와 Copilot CLI에 새 버전이 있으면 업데이트를 실행할 수 있습니다. 비서가 매번 보내는 안내를 줄였고, 다시 연 대화 앞에 빈 응답이 생기던 문제를 고쳤습니다.
- **플러그인.** 비서가 설치한 플러그인이 같은 창의 작업 막대와 설정에 바로 나타납니다. 설치본이 등록 기록과 달라지면 설정의 해당 줄에서 원인을 보고 다시 설치할 수 있습니다. 플러그인이 아닌 폴더는 곧바로 안내하고, Desktop 설정에서는 플러그인 소스 폴더를 열 수 있습니다. 플러그인 화면에서 문서·작업 목록과 목록으로 돌아가기 단추를 볼 수 있습니다.
- **편집.** 문서 안에 체크리스트를 만들고 항목을 클릭하거나 키보드로 체크할 수 있습니다. 문단이나 표 칸에서 슬래시 메뉴의 **인라인 수식** 또는 Ctrl+Shift+6으로 수식을 넣을 수 있습니다. 슬래시 메뉴와 명령 센터에서 한글을 조합하는 중에도 검색 결과를 볼 수 있습니다.
- **탭과 탐색기.** 탭을 우클릭해 같은 묶음의 다른 탭이나 왼쪽·오른쪽 탭을 닫을 수 있습니다. Desktop에서는 Ctrl+W로 현재 탭을 닫을 수 있고 탐색기의 경로 복사와 복구 내용 복사가 작동합니다.
- **진단 로그.** 오래 걸리거나 실패한 요청, 플러그인 동작과 오류, 비서의 실행과 응답 상태가 로그에 더 자세히 남습니다. Windows에서 길게 전달되는 경로의 Codex 대화 로그도 열 수 있습니다.

**알려진 제약.** Ollama에는 Copilot CLI가 필요하고, 시험한 작은 로컬 모델은 플러그인 제작에 실패할 수 있습니다. 새 빌드 설치 뒤 플러그인이 자동으로 켜지지 않는 사례는 원인을 확인 중입니다. 이번 빌드 설치본에서 Ctrl+W, 경로·복구 내용 복사, 플러그인 폴더 열기와 실제 GitHub 업데이트는 확인하지 않았습니다. Ctrl+W는 Desktop에서 지원합니다.

**채널.** Stable 채널에는 이번 Beta가 표시되지 않습니다. 0.0.3에서 받으려면 설정에서 Beta 채널을 선택하세요. Beta 설치본은 저장된 채널 선택이 없을 때 Beta로 시작하며, 이미 저장한 채널 선택은 유지됩니다.

전체 변경과 검증 범위는 [배포 기록](https://github.com/litzio/litzio/blob/v0.0.4-beta.1/docs/releases/v0.0.4-beta.1.md)에 있습니다.

## 검증과 게시 판단

- 로컬에서 `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm docs:check`, Desktop 단위 검사 108건과 `git diff --check`를 통과했다. `verify-release.ts --tag v0.0.4-beta.1 --identity-only`는 tag 문자열·Desktop 버전·Beta 채널의 일치를 확인했다.
- 로컬 패키징, 실제 태그 preflight, 전체 자산 검증, `test:packaged`, `test:update`, `test:uninstall`, 브라우저 회귀와 실제 GitHub 업데이트는 로컬에서 실행하지 않았다. 태그와 Windows 배포 자산은 게시 단계에서 검증한다.
- 같은 소스의 CI local-feed는 Stable `0.0.1 → 0.0.2`와 Beta `0.1.0-beta.1 → 0.1.0-beta.2`를 사용한다. 릴리스 전 공개 설치본 회귀는 기존의 SHA-256 고정 공개 Stable `0.0.3` 위에 이 Beta 후보를 빌드해 NSIS 설치·시작·보존을 확인한다.
- 실제 GitHub opt-in은 직전 Stable 뒤 첫 Beta인 [PR #1571](https://github.com/litzio/litzio/pull/1571)과 같이 `0.0.3 → 0.0.4-beta.1`을 택했다. 출발본 설정에서 Beta 채널을 선택하고 공개 Release의 배달·설치를 검증하는 경로는 후보 공개 후 실행할 수 있다.
- 게시 전 병합 대기열의 Windows Desktop 검사를 확인한다. 릴리스 preflight는 기존 태그가 dispatch master의 이력에 있고, 가리킨 커밋의 Desktop 버전이 태그와 일치하는지 검사한다. 워크플로는 그 커밋에서 브라우저 8개 shard, 공개 설치본·Stable·Beta 설치/업데이트와 전체 제거, 최종 패키지와 자산 검증이 성공해야 게시한다.
