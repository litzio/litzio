## 한국어 Release 본문 초안

서명 없는 Windows Beta 배포입니다. Windows에 게시자 또는 SmartScreen 경고가 나타날 수 있습니다. SHA-512는 파일 무결성을 확인하며 게시자를 인증하지 않습니다. Unsigned Windows Beta. Windows may show publisher or SmartScreen warnings. SHA-512 checks file integrity; it does not authenticate the publisher.

Litzio v0.0.3-beta.2 Beta의 beta.1 이후 주요 변경입니다. 이 본문은 아직 게시되지 않은 초안입니다.

- **플러그인 화면 개편:** 플러그인이 자기 화면을 제공하고 문서 보기·파일 선택·문서 열기·새 문서 저장을 사용할 수 있습니다. 제작 도구와 공개 SDK가 포함됩니다.
- **제거된 기능:** 선언형 플러그인 화면, Docling 원문 검수와 OneDrive·Jira 실험 플러그인을 제거했습니다. 기존 플러그인의 호환성이나 자동 변환을 제공하지 않습니다.
- **같은 PC의 단일 연결:** 다른 PC Host를 등록하고 선택하는 화면을 제거했습니다. 같은 PC daemon과 수동 다시 연결은 유지합니다. CLI의 명시적 `--host`는 유지합니다.
- **기억·복구 형식 변경:** 이전 Host별 탭·기억·복구 기록은 새 형식으로 옮기거나 삭제하지 않습니다. 업데이트 전에 문서를 저장하고, 업데이트 후 필요한 문서를 직접 다시 여세요.
- **비서 개선:** 이미지 붙여넣기·미리보기와 보내기/중단 버튼을 개선하고 CLI 쓰기·PATH·Copilot 연결 복구를 보완했습니다. 비서의 화면 조회·대행 도구는 제거했으며 CLI와 스킬을 사용합니다.
- **편집 수정:** Mermaid 편집 중 미리보기 때문에 적용 클릭이 사라지는 문제와 읽기 전용 표 간격을 수정했습니다.

개발 단계로 과거 데이터 하위 호환을 보장하지 않습니다. 비서의 변경 보기·되돌리기는 공급자 편집 이벤트가 있는 기존 UTF-8 파일(1 MiB 이하)에 한정되며 셸 직접 쓰기 등은 경로만 표시합니다. [현재 비서 한계](../design/main-agent-v1.md#현재-한계)를 확인하세요.

Beta 설치본의 최초 기본 채널은 Beta이며 저장된 선택은 유지합니다. Stable 채널에는 Beta를 제공하지 않습니다. 실제 GitHub 설치·업데이트는 아직 검증하지 않았습니다.

## 검증과 게시 판단

현재 판정은 **막힘(검증 진행 중)** 이다. 제품 결함과 아직 실행하지 않은 검사를 구분해 아래에 갱신한다.

- 로컬 frozen install·전체 typecheck·Desktop 단위 테스트 105개·`desktop-updates` 브라우저 시나리오·문서 검사·diff 검사 통과. 브라우저 실행 중 ResizeObserver 경고가 있었으나 시나리오는 통과했다.
- 격리 경로: Host 데이터·비서 작업·비서 설정·daemon·플러그인 설정 다섯 변수 외에 `LITZIO_RESET_DIR`, Electron profile·캐시와 검증 임시 파일도 격리한다. ResetGuard 경로는 다섯 변수만으로 격리되지 않는다.
- 로컬 공식 package는 Electron 출력 폴더 rename의 `EPERM`으로 두 번 실패했고, 세 번째는 같은 출력 폴더 정리의 `EPERM`으로 실패했다. Restart Manager 파일별 조회는 `default_app.asar`를 작업 폴더를 감시하는 다른 프로그램이 열고 있음을 확인했다. 그 프로그램은 종료하지 않았다. 감시 대상 밖 별도 checkout에서 원본 명령을 재검증할 예정이다. 감지된 파일 핸들과 실패의 상관관계는 확인했지만 다른 원인을 배제한 단독 원인 실험은 아직 아니다.
- `verify-release.ts --tag v0.0.3-beta.2`와 `test:packaged`는 선행 출력 부재로 실패했다. 패키징본 앱 시작·폴더/문서 열기·편집·저장·복구·플러그인 화면/저장·실제 AI 한 턴·beta.1 데이터 잔존 실행은 아직 확인하지 못했다.
- 기존 CI의 Desktop job은 package·verify·packaged를 실행하지만 일반 PR에서는 선택하지 않으며 queue/master fallback에서 실행한다. 현재 로컬 결과를 CI 성공으로 대체하지 않는다.
- 최종 후보 SHA의 필수 PR/queue CI와 게시 전 release 검증이 필요하다. 설치·업데이트·제거는 이 작업의 실제 사용자 환경에서 실행하지 않는다.
- tag 생성·push, GitHub Release와 배포 workflow는 실행하지 않는다. 공개 자산·해시·workflow 성공을 주장하지 않는다.

## 소유자 설치본 확인 항목

최종 후보의 실제 설치·Beta 채널 업데이트, native tray와 종료 보호, 새 터미널의 CLI, SmartScreen·게시자 표시를 확인해야 한다. beta.1의 문서를 저장한 뒤 새 namespace에서 필요한 문서를 다시 열고, 플러그인 화면·문서 저장 및 실제 AI 결과를 설치본에서도 확인한다. 격리 unpacked 검증은 실제 GitHub 전달과 NSIS 설치를 증명하지 않는다.
