## 한국어 Release 본문 초안

서명 없는 Windows Beta 배포입니다. Windows에 게시자 또는 SmartScreen 경고가 나타날 수 있습니다. SHA-512는 파일 무결성을 확인하며 게시자를 인증하지 않습니다. Unsigned Windows Beta. Windows may show publisher or SmartScreen warnings. SHA-512 checks file integrity; it does not authenticate the publisher.

Litzio v0.0.3-beta.2 Beta의 beta.1 이후 주요 변경입니다. 이 본문은 아직 게시되지 않은 초안입니다.

- **플러그인 화면 개편:** 플러그인이 자기 화면을 제공하고 문서 보기·파일 선택·문서 열기·새 문서 저장을 사용할 수 있습니다. 제작 도구와 공개 SDK가 포함됩니다.
- **제거된 기능:** 선언형 플러그인 화면, Docling 원문 검수와 OneDrive·Jira 실험 플러그인을 제거했습니다. 기존 플러그인의 호환성이나 자동 변환을 제공하지 않습니다.
- **같은 PC의 단일 연결:** 다른 PC Host를 등록하고 선택하는 화면을 제거했습니다. 같은 PC daemon과 수동 다시 연결은 유지합니다. CLI의 명시적 `--host`는 유지합니다.
- **기억·복구 형식 변경:** 이전 Host별 탭·기억·복구 기록은 새 형식으로 옮기거나 삭제하지 않습니다. 업데이트 전에 문서를 저장하고, 업데이트 후 필요한 문서를 직접 다시 여세요.
- **비서 개선:** 이미지 붙여넣기·미리보기와 보내기/중단 버튼을 개선하고 CLI 쓰기·PATH·Copilot 연결 복구를 보완했습니다. 비서의 화면 조회·대행 도구는 제거했으며 CLI와 스킬을 사용합니다.
- **편집 수정:** Mermaid 편집 중 미리보기 때문에 적용 클릭이 사라지는 문제와 읽기 전용 표 간격을 수정했습니다.
- **표 편집 도구:** Edit 모드의 표 안에 커서를 두면 해당 행·열 도구와 추가 막대가 나타납니다. 행·열 메뉴로 추가·이동·삭제·정렬을 수행합니다. 행·열 전체의 실제 선택은 제공하지 않으며 CSS anchor를 지원하지 않는 브라우저에서는 열 추가 막대를 숨깁니다.
- **플러그인 사이드바:** 관리 화면에서 바꾼 플러그인 목록을 반영합니다. 여러 창에서는 다른 창을 다시 활성화할 때 목록을 갱신합니다.

플러그인에서 외부 의존성을 처음 설치할 때 포함 npm 준비에 13~30초가 걸린 검사 관찰이 있습니다. 이미 준비된 cache와 일반 Host 기동의 비용으로 일반화하지 않습니다. 알림 버튼의 본문 조작 가림(#1644, PR #1647)을 수정했습니다. 종은 머리줄의 Assistant 옆에 있고 자동 오류·진행 알림은 이전처럼 오른쪽 아래 카드로 표시합니다. 좁은 창에서는 Assistant가 더 일찍 아이콘으로 바뀝니다.

개발 단계로 과거 데이터 하위 호환을 보장하지 않습니다. 비서의 변경 보기·되돌리기는 공급자 편집 이벤트가 있는 기존 UTF-8 파일(1 MiB 이하)에 한정되며 셸 직접 쓰기 등은 경로만 표시합니다. [현재 비서 한계](../design/main-agent-v1.md#현재-한계)를 확인하세요.

Beta 설치본의 최초 기본 채널은 Beta이며 저장된 선택은 유지합니다. Stable 채널에는 Beta를 제공하지 않습니다. 실제 GitHub 설치·업데이트는 아직 검증하지 않았습니다.

## 검증과 게시 판단

현재 판정은 **게시 보류 — #1644와 최종 후보 검증 대기**다. `e0d4ac3c`까지의 추가 기능 리허설에서 새 제품 blocker는 확인하지 못했다. 아래의 로컬 native 너비 실패는 원인 미확정인 검증 제한으로 남기며 통과로 바꾸지 않는다. #1644 병합 후 최종 후보를 다시 확인할 때까지 PR은 Draft다.

### 최초 후보 검증 (`52e892b3`)

- 로컬 frozen install·전체 typecheck·Desktop 단위 테스트 105개·`desktop-updates` 브라우저 시나리오·문서 검사·diff 검사 통과. 브라우저 실행 중 ResizeObserver 경고가 있었으나 시나리오는 통과했다.
- 격리 경로: Host 데이터·비서 작업·비서 설정·daemon·플러그인 설정 다섯 변수 외에 `LITZIO_RESET_DIR`, Electron profile·캐시와 검증 임시 파일도 격리한다. ResetGuard 경로는 다섯 변수만으로 격리되지 않는다.
- 첫 브라우저 runner 실행은 다섯 Host 경로만 자동 격리해 기본 ResetGuard 경로에 actor를 남겼다. 이를 읽기로 확인하고 삭제하지 않았다. reset 경로까지 명시한 `desktop-updates` 재실행은 통과했다. runner와 수동 비서 수락 실행기의 공통 경로 목록 보완은 #1642의 PR #1643으로 병합됐다. 제품 ResetGuard는 실제 reset의 exclusive 단계에서 죽은 PID 세대의 actor를 정리하며 일반 기동 때 정리하지 않는다. stale 파일 축적만으로 reset 불가라고 판단하지 않는다.
- 준비 commit `52e892b3`의 공식 package는 Electron 출력 폴더 rename의 `EPERM`으로 두 번 실패했고, 세 번째는 같은 출력 폴더 정리의 `EPERM`으로 실패했다. Restart Manager 파일별 조회는 `default_app.asar`를 작업 폴더를 감시하는 다른 프로그램이 열고 있음을 확인했다. 그 프로그램은 종료하지 않았다. 감시 대상 밖 동일 commit의 detached checkout에서 frozen install → 원본 `package`가 성공했다. 이 경로가 확인된 회피 방법이며, 감시 프로그램을 종료해 단독 원인을 비교하는 실험은 하지 않았다.
- 최초 `verify-release`·`test:packaged`는 출력 부재로 실패했다. 별도 checkout의 성공한 패키징 뒤에는 `verify-release.ts --tag v0.0.3-beta.2`의 installer·manifest·PE 버전·blockmap 검사가 모두 통과했다. 설치 파일은 실행하지 않았다.
- 공식 `test:packaged`: 12개 중 11개 통과. 문서 열기·편집·저장·재열기, 폴더 열기·새 문서·이미지 저장, 외부 변경 충돌, 실제 crash/정상 종료 복구와 Save/Reload, 트레이 숨김/미저장 종료 보호, 채널 보존, daemon 수명/연결 복구, 격리 초기화가 통과했다. 외부 SDK/scaffold 검증도 통과한 뒤 시작·샘플 시나리오의 native layout 단계가 실패했다.
- 추가 패키징본 리허설: 공개 `screen` template을 scaffold → install하고 실제 handler의 측정값(10·18·12·24, 합계 64)을 화면에서 확인했다. 화면의 문서 저장이 201로 완료되고 canonical 파일과 열린 문서에서 내용을 확인했다. 별도의 Codex `gpt-6-luna` low 한 턴은 기존 문서 한 곳을 수정하고 CLI check를 실행한 뒤 요청한 완료 응답을 반환했다. 이는 한 건의 합성 업무이며 일반 업무 성공률을 뜻하지 않는다.
- beta.1 태그의 별도 빌드를 설치 없이 실행해 문서 저장·미저장 복구·탭/기억과 삭제된 플러그인 등록 흔적을 남겼다. 같은 격리 profile·설정·데이터로 beta.2 unpacked를 실행했을 때 빈 화면·pageerror·잘못된 복구는 없었다. 옛 localStorage와 recovery DB 내용이 동일하고, 필요한 문서를 직접 열면 저장된 본문만 표시됐다. 이는 실제 NSIS 업데이트나 과거 데이터 전반의 호환성을 보장하지 않는다.
- 기존 CI의 Desktop job은 package·verify·packaged를 실행하지만 일반 PR에서는 선택하지 않으며 queue/master fallback에서 실행한다. 현재 로컬 결과를 CI 성공으로 대체하지 않는다.
- 최종 후보 SHA의 필수 PR/queue CI와 게시 전 release 검증이 필요하다. 설치·업데이트·제거는 이 작업의 실제 사용자 환경에서 실행하지 않는다.
- tag 생성·push, GitHub Release와 배포 workflow는 실행하지 않는다. 공개 자산·해시·workflow 성공을 주장하지 않는다.

## 게시를 막는 항목과 알려진 제한

1. #1644는 PR #1647로 병합됐다. master `968a05d0`의 최종 패키징·verify와 실제 Electron의 알림 확인 뒤 PR #1639를 ready로 전환한다. 전체 packaged를 로컬에서 다시 실행하지 않으며 같은 master의 merge queue 근거를 기록한다.
2. 최종 head의 필수 PR/queue·release 검증과 소유자의 게시 지시가 필요하다. 현재 master/준비 head의 성공을 최종 후보의 성공으로 간주하지 않는다.

로컬 검증 제한: `test:packaged`의 시작·샘플 시나리오에서 `BrowserWindow.setContentSize(1440, 900)` 뒤 `innerWidth`가 기대값 1440 대신 1439였다(`packaged.e2e.ts`의 첫 너비 poll). 두 후보에서 재현됐으며 재현 순서는 공식 package → verify → 전체 test:packaged다. 기본 작업영역이 지원 최소 창보다 좁고 배율 200%인 환경에서 관찰했으며 native 크기 반올림과 제품 결함을 아직 구분하지 못했다. 단언·timeout은 완화하지 않았다. 위 master의 Windows queue 검사는 성공했으나 이 PC의 실패 원인을 해결한 증거는 아니며 지원 크기 작업영역의 설치본에서 확인해야 한다.

표 도구의 행·열 실제 선택 미지원, CSS anchor 미지원 시 열 추가 막대 숨김, 여러 창의 플러그인 목록을 창 재활성화 때 갱신하는 동작과 첫 의존성 설치의 npm 준비 비용은 알려진 제한이다. 이번 갱신에서 이를 해결했다고 주장하지 않는다.

제거된 화면·플러그인의 사용 불가와 이전 탭·복구를 자동 변환하지 않는 것은 의도된 변경이다. 비서의 변경 보기·되돌리기 범위는 위 본문의 알려진 한계다. 이들을 새 제품 결함과 섞지 않는다. 격리 실행으로 설치본·실제 GitHub 업데이트·서명·SmartScreen을 검증했다고 주장하지 않는다. 검증용 앱·Host·서버는 종료했고 생성한 checkout과 출력은 보존한다.

## 소유자 설치본 확인 항목

최종 후보의 실제 설치·Beta 채널 업데이트, native tray와 종료 보호, 새 터미널의 CLI, SmartScreen·게시자 표시를 확인해야 한다. beta.1의 문서를 저장한 뒤 새 namespace에서 필요한 문서를 다시 열고, 플러그인 화면·문서 저장 및 실제 AI 결과를 설치본에서도 확인한다. 격리 unpacked 검증은 실제 GitHub 전달과 NSIS 설치를 증명하지 않는다.
