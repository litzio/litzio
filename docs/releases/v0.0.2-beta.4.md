## 준비 단계 작업 계획 (당시 범위)

- 범위: Desktop 후보를 `0.0.2-beta.4`로 올리고 opt-in 실제 GitHub 업데이트 harness의 향후 대상을 `0.0.2-beta.3 → 0.0.2-beta.4`으로 맞춘다. 공개 버전과 후보를 구분해 문서·색인과 한국어 Release 본문 초안을 준비한다.
- 제외: 기능 코드 변경, tag 생성, release workflow 실행·게시, 병합, 로컬 앱 실행·설치. PATH·레지스트리·Litzio 사용자 데이터를 변경하지 않는다.
- 완료: 대상 로컬 검사와 준비 PR의 필수 CI가 통과했고 `Refs #758` [PR #759](https://github.com/litzio/litzio/pull/759)을 오케스트레이터에 전달했다. 병합 후 오케스트레이터가 게시와 공개 자산 확인을 수행했다.
- 검증: Desktop 단위 테스트·typecheck, 문서·공백 검사. package·release 자산 검증과 packaged·install/update·uninstall은 로컬에서 실행하지 않고 disposable Windows CI에 맡긴다. 브라우저는 실행하지 않는다.

CI local-feed fixture는 Stable `0.0.1 → 0.0.2`, Beta `0.1.0-beta.1 → 0.1.0-beta.2`를 유지한다. 현재 소스를 테스트 버전으로 각각 빌드하는 경로이며 공개 자산을 쓰는 실제 GitHub `LIVE` 경로와 구별한다.

## 알려진 제한과 수동 확인

- unsigned Beta이며 Authenticode 게시자 인증을 제공하지 않는다. 체크섬은 무결성 검증이며 SmartScreen·조직 보안 정책 경고가 나타날 수 있다. Stable은 미공개다.
- 개발 단계이므로 이전 Litzio 문서·복구 기록·설정의 하위 호환성과 자동 migration을 보장하지 않는다. 중요한 문서는 별도로 백업한다.
- #528로 기존 샘플 사본 `sample-native-v1`이 교체될 수 있다. 수정한 샘플 내용도 교체 대상이지만 앱이 소유를 확인한 경우에만 교체한다. 확인되지 않은 폴더는 보존하며, 구체적인 소유 확인·안전한 교체 조건은 [샘플 계약](../design/desktop-distribution-v1.md#native-sample)을 따른다.
- 실제 GitHub `0.0.2-beta.3 → 0.0.2-beta.4` 업데이트는 **미실행·미검증**이다. [실제 GitHub 검증 절차](../test/README.md#real-github-beta-update)와 CI local-feed 결과를 구별한다.

다음은 별도 수동 확인 항목이며 이번 릴리스에서 실행하지 않았다. 자동화·CI 성공으로 실제 사용자 환경 수용성을 판정하지 않는다([수동 확인 경계](../test/README.md#manual-review)).

[공개 Release](https://github.com/litzio/litzio/releases/tag/v0.0.2-beta.4)의 한국어 본문을 `gh release view v0.0.2-beta.4`로 확인했다. 아래 초안에서 "게시 후 Assets의"를 "Assets의"로 바꾼 본문이 게시되어 있다. 주요 변경, unsigned/SmartScreen 안내, 과거 데이터 하위 호환성 비보장·샘플 교체 안내, 실제 GitHub 업데이트 미검증과 별도 수동 확인 항목을 포함한다. 아래 초안은 준비 단계 기록으로 보존하며 게시된 본문의 사본은 아니다.

### 준비 단계 Release 본문 초안 (당시 기록)

> Litzio v0.0.2-beta.4는 Windows x64용 unsigned Beta입니다.
>
> **주요 변경**
>
> - 최대 두 편집기 그룹에서 문서를 나란히 열고 탭별 스크롤·선택·미저장 내용·Undo를 유지합니다. 문서 동작은 각 탭 줄로 이동했습니다. (#488·#695, PR #697·#718·#711)
> - 열린 폴더의 포함 관계를 정리하고 파일 패널 이름을 탐색기로 통일했습니다. 문서 탐색 탭의 개수 표시는 제거했습니다. (#702·#703·#700, PR #706·#704·#701)
> - 미주 편집은 Edit 버튼으로 시작하고 바깥 클릭·Enter로 적용합니다. 마지막 참조와 정의의 연동 삭제, 정의를 보존하는 클립보드와 CLI remove-footnote를 제공합니다. (#714·#715·#716, PR #717·#746)
> - 그림·Mermaid·표·수식의 고정 번호와 저장을 막지 않는 누락·중복 경고를 제공합니다. CLI update-enumerator도 사용할 수 있습니다. (#720, PR #727·#738)
> - 문서 제목을 frontmatter title로 분리하고 H1부터 본문 절로 편집합니다. CLI update-title과 영문·로마자 순서 목록 표지를 지원하며 인접 목록의 저장 경계를 보존합니다. (#722·#734·#730, PR #736·#737·#732)
> - 일반 링크를 Ctrl/Cmd+클릭 또는 링크 폼에서 열고 Desktop 설정에서 로그 폴더를 열 수 있습니다. 상대 이미지 링크·미주·인용에는 내용 미리보기를 제공합니다. (#725·#712·#731·#752, PR #728·#729·#744·#754)
> - 첫 Ctrl/Cmd+A는 현재 글 블록을 선택하고 연속 두 번째 입력은 문서 전체를 선택합니다. 캡션·코드·미주의 세 번 클릭이 주변 내용을 지우는 문제와 Mermaid 캡션 교체·조합 취소의 저장 불일치를 수정했습니다. (#723·#751·#724·#735·#750, PR #748·#755·#733·#743·#753)
> - 빈 캡션 입력 안내, 표 캡션 간격, 한 줄 개요 표시와 Windows 창 컨트롤 아래 구분선을 개선하고 Mermaid 줄바꿈 라벨 표시를 수정했습니다. (#698·#721·#719·#694·#707, PR #699·#745·#749·#696·#747)
> - 과거 복구 형식의 호환 처리를 종료했습니다. 지원하지 않는 snapshot의 복원은 거부하며 이미 저장된 텍스트 사본은 유지합니다. (#705, PR #708)
> - 그림 속성을 그림 옆 팝오버에서 편집합니다. 완료 버튼 하나로 적용하고, Esc는 취소, 바깥 클릭은 적용합니다. (#757, PR #762)
> - 속성을 연 채 본문을 클릭하면 그 위치에 바로 입력됩니다. 썸네일, 정렬, 빈 입력칸, 경고 표시를 보정했습니다. (#760, PR #763)
>
> **설치와 주의 사항**
>
> 게시 후 Assets의 `Litzio-Setup-0.0.2-beta.4.exe`를 사용합니다. Node.js나 pnpm은 따로 필요하지 않습니다.
>
> 코드 서명되지 않은 Beta이므로 Windows SmartScreen이나 조직 보안 정책 경고가 나타날 수 있습니다. 체크섬은 파일 무결성 확인용이며 게시자 인증을 대신하지 않습니다.
>
> 개발 단계이므로 이전 Litzio 문서·복구 기록·설정의 하위 호환성을 보장하지 않으며 자동 migration도 제공하지 않습니다. 중요한 문서는 따로 백업해 주세요. 기존 샘플 사본(sample-native-v1)은 앱이 소유를 확인한 경우에만 새 샘플로 교체될 수 있으며, 수정한 샘플 내용도 교체 대상입니다.
>
> 이 PC의 설치 상태를 바꾸지 않는다는 제약으로 실제 GitHub 0.0.2-beta.3 → 0.0.2-beta.4 업데이트는 미실행·미검증입니다. CI local-feed 결과와 구별합니다. 다음은 별도 수동 확인 항목입니다.
