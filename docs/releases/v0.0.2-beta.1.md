# Litzio v0.0.2-beta.1 — 배포·검증 및 철회 기록

- Status: Historical
- Last verified: 2026-10-28 (공식 release workflow attempt 2 성공, 공개 자산 익명 다운로드·해시 대조, 한국어 Release 본문과 기존 두 Release·자산·원격 tag 철회 확인. 실제 GitHub 설치·업데이트는 미검증).
- Scope: [#632](https://github.com/litzio/litzio/issues/632)의 Windows x64 unsigned Beta 버전 정정·신규 배포와 잘못된 `0.1.0` Beta 배포 철회 근거.
- Authority: [ADR-0004](../adr/0004-desktop-host-distribution.md), [Desktop contract](../design/desktop-distribution-v1.md), [발행 절차](../../CONTRIBUTING.md#windows-desktop-builds-and-releases).

소유자는 기존 사용자가 없다고 확인하고 현재 기능을 유지한 채 버전을 `0.0.2-beta.1`로 정정하도록 승인했다. 새 공개 자산 검증 후 기존 두 배포를 철회하는 순서로 완료했다. 기능·Core 의미·updater/installer 동작을 변경하지 않았고 다운그레이드 허용·migration을 추가하지 않았다. 기능과 기존 제한의 배경은 [철회된 0.1.0-beta.2 당시 기록](v0.1.0-beta.2.md)에 보존한다. 그 버전의 CI·해시·실제 업데이트 사례를 새 버전의 검증으로 전용하지 않는다.

## 최초 실패와 한 번의 재실행

[attempt 1](https://github.com/litzio/litzio/actions/runs/40593518064/attempts/1)의 [Windows build job 122503692718](https://github.com/litzio/litzio/actions/runs/40593518064/job/122503692718)은 Stable `test:update` 정리 구간에서 실패했다. 2026-10-27T22:22:50Z 로그는 `installed 0.0.2 and showed its window`를 기록했고, 22:22:56Z 원시 오류는 다음과 같다.

```text
Get-ItemProperty : Cannot find path
'HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Uninstall\233b6256-8045-586b-bd17-f0f20d2632c3'
because it does not exist.
FullyQualifiedErrorId : PathNotFound,Microsoft.PowerShell.Commands.GetItemPropertyCommand
```

stack은 `update.e2e.ts:41`의 PowerShell 실행 → `:46`의 `installedEntry()` → `:324`의 `finally` 제거 대기 조건이었다([해당 소스](https://github.com/litzio/litzio/blob/33f9161f765bdb934d378f93b08c98e481f8a5f5/apps/desktop/test/packaged/update.e2e.ts#L324)). 비동기 uninstaller 시작 직후 registry 하위 키 열거와 `Get-ItemProperty -ErrorAction Stop` 사이 키가 사라지는 경합으로 판단했다. 같은 SHA의 merge_group·master Windows 검사가 모두 `uninstall: 0; entry removed`와 성공을 기록한 점도 대조했다. 제품 설치/업데이트 실패의 직접 근거는 확인하지 못했지만, `finally` 예외가 선행 오류를 가릴 가능성과 단일 실패 표본의 한계는 남는다. 안정성 문제가 해결됐다는 증명은 아니다.

attempt 1은 preflight·browser 성공, build 실패, publish skipped로 종료했고 Release와 실패 artifact는 생성되지 않았다. release workflow의 Windows build에는 실패 진단 artifact 업로드 단계가 없어 위 원시 job log가 실패 근거다. 오케스트레이터가 로그·소스를 확인한 후 실패한 build와 종속 publish만 **한 번** 재실행했다. 소스·단언·timeout을 변경하지 않았고 성공한 browser 검사는 반복하지 않았다. [attempt 2 build 122509261526](https://github.com/litzio/litzio/actions/runs/40593518064/job/122509261526)과 [publish 122514657918](https://github.com/litzio/litzio/actions/runs/40593518064/job/122514657918)이 성공했으며 동일 오류는 재발하지 않았다.

## 기존 두 배포의 철회

## 알려진 제한

- unsigned Beta이며 Authenticode 게시자 인증을 제공하지 않는다. 체크섬은 무결성 근거다. SmartScreen·조직 보안 정책 경고가 나타날 수 있고 Stable은 미공개다.
- `0.1.0-beta.*` 설치본은 더 낮은 `0.0.2-beta.1`로 자동 업데이트되지 않는다. 해당 설치본은 새 설치본으로 수동 전환해야 하며, 다운그레이드 차단 정책은 유지한다.
- 개발 단계로 과거 문서·복구 기록·설정의 하위 호환성과 자동 migration을 보장하지 않는다.
- 실제 GitHub 설치/업데이트, SmartScreen reputation, 실제 사용자 Windows 수용성은 이번 검증 결과가 아니다. [실제 GitHub 검증 절차](../test/README.md#real-github-beta-update)와 CI local-feed 결과를 구별한다.

## 후속 문서 작업 계획

- 범위: 공개 자산 검증과 기존 두 Release·자산·원격 tag 철회 완료 근거를 기록하고 README·CONTRIBUTING·색인·Desktop 계약/ADR metadata·검증 안내를 현재 배포에 맞춘다. 과거 기록은 당시 버전·날짜·해시·검증 결과를 유지하고 철회 안내와 보존 commit을 덧붙인다.
- 제외: 제품 코드·동작·테스트 변경, 실제 GitHub 설치/업데이트 실행, 추가 배포·tag 변경·삭제·병합. 재생성 가능한 installer와 임시 증거 파일은 커밋하지 않는다.
- 완료: 이 기록을 Historical로 전환하고 공개·철회 안내가 일치하는 docs-only PR을 `Closes #632`로 연결한다. 소유자 지시로 독립 리뷰어를 생략하며 오케스트레이터가 diff·CI를 확인하고 merge queue를 처리한다.
- 검증: 문서 전용 matrix의 `pnpm docs:check`와 `git diff --check`, PR head의 필수 CI 성공을 확인한다. UI 변경이 없어 로컬 브라우저·캡처·packaged 설치는 실행하지 않는다.

## 준비 단계 작업 계획

- 범위: 현재 기능을 유지하고 Desktop package 버전을 `0.1.0-beta.2`에서 `0.0.2-beta.1`로 정정한다. 후보 검증 명령·현재 계약·색인을 맞추고, 실제 GitHub 업데이트 harness의 향후 대상을 `0.0.1-beta.4 → 0.0.2-beta.1`로 지정한다. CI local-feed fixture는 변경하지 않는다.
- 제외: 기능·Core 의미·updater/installer 동작 변경, 다운그레이드 허용, migration, 기존 tag/파일 덮어쓰기, 로컬 패키징·설치·실제 GitHub 업데이트, 병합·태그·게시·삭제. README 공개 링크와 과거 릴리스의 버전·검증 근거를 유지한다.
- 완료: 버전·문서가 일치하고 대상 로컬 검사와 준비 PR의 필수 CI가 통과한다. PR은 `Refs #632`로 연결하고 오케스트레이터의 diff 확인을 받는다. 소유자 지시로 독립 리뷰어를 생략한다. 이슈는 전체 배포·철회 완료 전 닫지 않는다.
- 검증: frozen install, Desktop 단위 테스트, workspace typecheck, docs checker, `verify-release.ts --tag v0.0.2-beta.1 --identity-only`, diff whitespace. UI 변경이 없어 로컬 브라우저·캡처는 불필요하다. Windows clean package·자산 검증·packaged·설치/업데이트·제거 검사는 필수 CI에 맡긴다.

준비 단계의 위 계획과 아래 로컬 검증은 [#633](https://github.com/litzio/litzio/pull/633)의 당시 범위다. 게시·철회는 그 병합 후 오케스트레이터가 별도로 수행했으며 현재 결과는 위에 기록했다.
