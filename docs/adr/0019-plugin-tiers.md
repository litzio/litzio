커뮤니티 기본 실행 차단과 신뢰·활성화의 구분은 유지하되, **비서가 digest 신뢰 단계를 실행할 수 있다.** 플러그인 관리의 건별 사용자 명시 승인은 제거하고 사용자에게 보이는 활동 기록으로 가시성을 제공한다. 이 신뢰 주체·승인·기록 범위에서는 ADR-0020을 우선 적용한다. secret 비노출·제품 고정 공식 목록·digest 신뢰 기록과 나머지 계층·SDK·격리 비보장 경계는 유지한다. 사용자 확인 없이 신뢰 코드 설치·실행이 가능해지는 위험을 수용하며 활동 기록은 예방 장벽이 아니다. 현재 구현 변경 완료를 뜻하지 않는다.

## 2026-11-09 신뢰 단위 개정 (#1379)

[소유자 결정 #1379](https://github.com/litzio/litzio/issues/1379)에 따라 아래의 digest 단위 신뢰·업데이트 재확인 서술은 등록된 플러그인(ID와 그 등록) 단위 신뢰로 대체한다. 처음 켤 때 한 번 확인하고 업데이트 뒤에는 다시 확인하지 않는다. 제거 후 재추가·등록 교체는 다시 신뢰해야 한다. 컨셉 검증 단계의 제한이며, 공식 번들 공급 목록과 digest 검증은 유지한다. UI·CLI·비서는 같은 Host 작업을 사용한다. 현재 세부 계약은 [플러그인 1단계](../design/plugin-stage1-v1.md)를 따른다. 이전 결정의 경위는 아래에 보존한다.

## 2026-11-10 지정 커뮤니티 기본 포함 개정 (#1391)

[소유자 결정 #1391](https://github.com/litzio/litzio/issues/1391)은 아래 Docling 기본 포함 금지와 #1321·#1328의 번들 제외 중 **제품에 고정한 지정 커뮤니티 공급**에 한해 개정한다. 초기 지정은 community.docling·community.jira다. 공식 계층·공식 공급 목록·기본 활성 제외와 공개 SDK·workspace 제외는 유지한다. 처음에는 꺼짐·미신뢰이며 등록 단위 신뢰 확인을 거친다. 지정 복사본은 제거하지 않고 끄며, 같은 ID의 외부 폴더 등록은 우선하고 제거 후 다음 시작에 지정 복사본을 다시 표시한다. 현재 동작은 [플러그인 1단계](../design/plugin-stage1-v1.md#지정-커뮤니티-공급-1391)를 따른다. 개정 전 결정은 경위를 위해 보존한다.

## 배경과 근거

ADR-0017 전환에서 플러그인·Docling 기능은 제거했고 삭제 직전 master는 원격 `archive/plugins-docling-2026-11`에 보관했다. 비서는 daemon 공식 기능으로 남는다. 이번에는 플러그인을 다시 개발하기 전에 계층의 뜻과 허용하지 않는 경계를 정한다.

조사 보고서 `<local-research>/plugin-tiers.md`(2026-11-05)는 Litzio `363a73def72d9962d7bf21845485282024371400`, Paseo `66676d49e6336a75837abec247871553a7658c35` 등의 정적 조사와 제안이며 현행 계약이 아니다. 제품 실행·설치·원격 연결의 증명으로 쓰지 않는다. 보고서의 “코어 플러그인” 명칭과 Docling 공식 계층 추천은 아래 소유자 결정으로 대체한다. 기본 번들·기본 활성 상태·제거 정책 등 보고서의 다른 추천도 자동 채택하지 않는다.

## 결정 ①~⑧

### ① 계층은 공식 공급·유지 책임으로 구분한다

**공식 플러그인(Official plugin)** 은 Litzio가 공식 공급·유지 책임을 맡는 플러그인이다. 그 책임을 맡지 않는 플러그인은 **커뮤니티 플러그인(Community plugin)** 으로 분류한다. 공식 개발자가 작성한 개인·실험 플러그인도 커뮤니티 계층일 수 있다.

따라서 작성자의 소속이나 소유자 작업에서의 중요도만으로 공식 계층을 지정할 수 없다. 공식 계층이라는 이름으로 번들 여부·기본 활성화·특권을 추론할 수도 없다.

### ② 이름과 배포·실행 상태를 구별한다

`@litzio/core` 문서 엔진과 혼동되는 “코어 플러그인”은 쓰지 않는다. 이름은 공식 플러그인 / Official plugin, 커뮤니티 플러그인 / Community plugin으로 정한다. 코드 키 후보는 `pluginTier: 'official' | 'community'`이며 manifest 필드를 지금 확정하거나 구현하지 않는다.

공급자(Publisher)는 플러그인 공급 주체이며 비서의 AI 공급자(provider)와 구별한다. 기본 포함(Bundled)은 배포물에 들어 있다는 뜻으로 계층과 독립이다. 활성화/비활성화는 실행 상태이며 설치됨·신뢰함·사용 가능과 구별한다.

따라서 기본 포함이라는 이유로 공식 계층 또는 활성 상태로 간주하지 않는다. 비활성화를 제거·자격 증명 폐기·기존 작업 취소와 같은 동작으로 취급하지 않는다. 구체 상태 전이·기본 상태·제거 정책은 재개 때 필요한 범위로 결정한다.

### ③ 같은 manifest·SDK·권한을 사용한다

두 계층은 같은 manifest·SDK·권한과 검증 기준을 사용한다. 공식 전용 내부 API는 없다. 향후 커뮤니티 플러그인은 기본 실행을 차단하고 명시적 신뢰 기록 뒤 활성화하게 한다. 최초의 “사용자가 명시적으로 신뢰한 뒤” 요구는 위 2026-11-05 개정으로 대체하며 비서도 신뢰 단계를 실행할 수 있다. 신뢰와 활성화는 별도 개념이다.

따라서 공식 계층에만 내부 API 우회를 허용할 수 없다. 실행 차단은 sandbox가 아니며, 신뢰 후 실행한 코드의 OS 권한·파일·네트워크·자격 증명 격리를 보장하지 않는다. 계층 분류나 별도 프로세스를 격리 보증으로 설명할 수 없다. 이 결정으로 세밀한 권한 엔진이나 sandbox를 구현하지 않는다.

### ④ 실행과 자격 증명은 대상 Host가 소유한다

플러그인은 Host(daemon) 소유이며 실행과 자격 증명은 대상 Host의 OS 계정 문맥에 있다. [ADR-0018](0018-desktop-remote-hosts.md)의 대상 Host 고정을 따른다. Desktop은 대상 Host를 선택하는 클라이언트이며 전역 플러그인 실행 주체나 자격 증명 저장소로 확장하지 않는다.

따라서 Desktop 전역 토큰, Host 간 자격 증명 공유, Host 간 자동 작업 이동은 없다. Desktop에만 설치된 플러그인은 원격 Host에서 실행되지 않는다. 연결 실패를 다른 Host 실행으로 대체하지 않는다. 자격 증명 저장 방식·OAuth 흐름은 이번에 설계하지 않으며 기존 인증 보류([#1145](https://github.com/litzio/litzio/issues/1145))를 해제하지 않는다.

### ⑤ 최초 UI는 앱 번들과 공용 작업 API로 구성한다

재개 후 최초 UI는 앱 번들 UI와 대상 Host의 공용 작업 API로만 만든다. ADR-0018의 script를 앱 번들에 한정하는 경계를 유지한다. 향후 CopilotKit 같은 동적 UI 제어 요소로 발전시킬 수 있으나 이는 이번 결정 범위 밖의 방향이며 기술 채택이나 구현 승인이 아니다.

따라서 원격 Host가 보낸 JS/CSS를 실행하지 않으며 ADR-0012의 과거 same-origin ESM/CSS 로딩을 복원하지 않는다. 동적 UI 방향을 임의 플러그인 코드 로더나 원격 UI 실행의 근거로 사용할 수 없다. 해당 경계 변경은 별도 결정이 필요하다.

### ⑥ 플러그인 기능과 관리에도 공용 작업·CLI 규칙을 적용한다

[ADR-0015](0015-shared-host-operations.md)에 따라 두 계층의 새 사용자 기능은 Host 공용 작업의 입력·결과·범위·receipt로 정의하고 CLI 명령을 반드시 함께 제공한다. 설치·활성화·설정도 대상이며, 비서 도구는 필요할 때 같은 정의로 제공한다. 대상 Host와 실행 결과를 결과·receipt에 보존한다. 문서 의미·검증·canonical write는 Core가 소유한다.

버전은 ADR-0018의 프로토콜 불일치 거부·제품 버전 차이 경고 정책을 따른다. 구체 SDK/API 요구 형식은 재개 때 정한다.

따라서 UI만 제공하는 플러그인 기능·관리 작업, 플러그인·CLI·Editor의 별도 문서 의미 구현, 공식 write path 우회는 허용하지 않는다. 장기 호환 계층·임의 구버전 자동 호환은 만들지 않는다. 이번 개념 결정을 범용 operation registry나 모든 작업의 비서 자동 공개 요구로 확대하지 않는다.

### ⑦ 비서는 제품 기능이며 Docling은 공식 플러그인이 아니다

비서(Assistant)는 ADR-0017의 플러그인과 무관한 제품 기능이다. 플러그인 계층·차단·활성 상태로 비서의 존재나 가용성을 결정하지 않는다. 비서 가용성은 기존 AI 공급자 가용성 계약을 유지한다.

Docling은 공식 유지 대상이 아니므로 공식 플러그인이 아니다. 소유자 작업의 핵심이므로, 소유자가 재개를 개시하면 커뮤니티 계층 플러그인으로 다룰 수 있다.

따라서 비서를 플러그인으로 되돌리거나 플러그인 차단으로 비서를 끌 수 없다. 소유자에게 중요한 기능이라는 이유로 Docling을 공식 계층·기본 포함·기본 활성으로 지정하거나 자동 복원할 수 없다.

### ⑧ 이번 결정은 개념 기록이며 구현 재개가 아니다

이번 PR은 ADR·용어·색인·관련 개정 안내만 변경한다. SDK·로더 구현, 보관 코드(`archive/plugins-docling-2026-11`) 참고 재개발, 보류 이슈 해제, 배포망·서명·자동 업데이트는 소유자가 명시적으로 재개를 개시할 때 다룬다. 보관 코드는 참고 자료이며 그대로 복원하지 않는다.

따라서 Accepted 상태나 #1075 참조를 구현 착수·보류 해제·릴리스 승인으로 해석할 수 없다. 플러그인 없는 현재 제품 동작과 검증 기준을 바꾸거나 기능 제거를 테스트 예외로 바꿀 수 없다.

## 기존 결정과의 관계

- **ADR-0012 개정:** 재개 시 분류·공통 SDK·신뢰·Host 소유와 최초 UI 경계는 이 ADR을 따른다. 과거 동적 ESM/CSS 기여와 채택 조건·구현 기록은 보존하되 현행 제공 기능이나 복원 지시로 쓰지 않는다. Core 의미 소유와 공식 쓰기 경계는 유지한다.
- **ADR-0017 보완:** 보류한 개념 중 위 경계를 확정한다. 공식 AI, 플러그인·Docling 기능 제거·보관, 소유자의 명시적 재개 개시 조건은 유지한다. `aiTasks` 등 구체 계약 복원·SDK·로더·Docling 재개발을 이번에 착수하지 않는다.
- **ADR-0015·0018 유지:** 공용 작업·CLI 의무, Host 대상 고정·버전 정책과 번들 script 경계를 적용한다. Host 간 공유·자동 이동·원격 코드 실행을 추가하지 않는다.

## 검증과 후속 경계

완료 조건은 소유자 결정·각 비지원 경계·용어·관련 ADR의 관계를 기록하고 `pnpm docs:check` 및 PR 필수 CI를 통과하는 것이다. 제품 실행·플러그인 설치·자격 증명·원격 연결은 이번 문서 PR의 검증 대상이 아니다. 구현 재개 시 필요한 최소 범위를 별도 정하고, 실제 동작을 바꾸는 PR에서 관련 Implemented 계약과 검증을 함께 갱신한다.
