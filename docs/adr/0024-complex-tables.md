## 배경과 제안

요구사양서의 병합 셀은 어느 항목들이 같은 조건을 공유하는지 보여 준다. [#1996](https://github.com/litzio/litzio/issues/1996)의 Word 표본 101개에서 21개는 병합을 풀고 44개는 칸 안의 문단을 이어 붙여야 했다. [#1973](https://github.com/litzio/litzio/issues/1973)과 [PR #1977](https://github.com/litzio/litzio/pull/1977)은 한 칸의 줄바꿈과 표 주석을 보존한다. 병합 범위, 여러 행의 머리글, 칸 안 블록에는 별도의 표현이 필요하다.

같은 `{table}` 지시문에 격자 표현을 두 가지 둔다. 단순 표는 현재의 정규 파이프 격자와 바이트 규칙을 쓴다. 병합 범위, 둘 이상의 머리글 행, 한 칸의 여러 문단 또는 목록이 있으면 격자에만 아래 HTML 부분집합을 쓴다. 캡션·번호·라벨·주석은 두 표현에서 같은 표의 의미다. 첫 구현은 격자를 보존하며 표시하고 칸 글자를 고치는 데까지다. 병합·분할 편집은 그다음에 연다.

## 저장 형식

````markdown
:::{table} 출력 한계
:name: output-limits
:enumerator: 4

<table>
<thead>
<tr>
<th colspan="2"><p>정상 동작 범위</p></th>
</tr>
<tr>
<th><p>항목</p></th>
<th><p>조건</p></th>
</tr>
</thead>
<tbody>
<tr>
<td rowspan="2"><p>출력<br>전압</p><p>정격값 기준</p></td>
<td><ul><li>정상 부하</li><li>최대 부하</li></ul></td>
</tr>
<tr>
<td><p>실측값</p></td>
</tr>
</tbody>
</table>

a. 정격 부하에서 측정했다.
:::
````

### 허용하는 HTML

| 위치 | 허용 범위 |
| --- | --- |
| 격자 | 속성 없는 `table` 하나. 하나 이상의 행을 가진 `thead` 하나와, 본문 행이 있을 때 `tbody` 하나를 차례로 둔다. 두 그룹에는 `tr`만 둔다. 머리글은 `th`, 본문 칸은 `td`를 쓴다. 위 칸의 병합으로 행 전체가 채워지면 빈 `tr`을 허용한다. |
| 칸 | 양의 십진 정수 `rowspan`·`colspan`과 선택적 `style="text-align: left"`만 허용한다. 정렬 값은 `left`, `center`, `right`다. span을 생략하면 1이다. 먼저 시작한 span을 건너뛰고 원문 순서대로 칸의 왼쪽 위를 배정한다. 모든 행은 같은 폭의 격자를 덮어야 하며 빈 자리, 중첩, 그룹 경계를 넘거나 격자 밖으로 나가는 span은 오류다. |
| 칸 안 블록 | `p`, `ul`, `ol`의 순서 있는 조합을 허용한다. 빈 칸은 빈 `p` 하나로 나타낸다. 목록은 한 개 이상의 `li`로 구성된다. `li`는 인라인 내용 뒤에 하위 `ul` 또는 `ol` 하나를 둘 수 있다. `ol`의 선택적 `start`는 기존 Core가 허용하는 양의 십진 정수다. 기본 십진 번호와 글머리 기호를 지원하며, 체크리스트와 그 밖의 목록 번호 스타일·구분자는 범위 밖이다. |
| 인라인 | 텍스트, `br`, `strong`, `em`, `del`, `sub`, `sup`, `code`, `a`를 허용한다. `br`은 인라인 줄바꿈이고 `code`는 텍스트만 받는다. `a`에는 `href`와 선택적 `title`을 둔다. 링크 및 마크의 중첩은 Core의 기존 인라인 규칙과 문서 보기의 링크 처리 정책을 적용한다. |
| MyST 인라인 의미 | 기존 파이프 표를 병합할 때 수식·참조·미주·인용을 잃지 않도록 텍스트만 가진 `span data-myst="…"`으로 표현한다. 값은 `math`, `eq`, `numref`, `ref`, `footnote`, `cite`, `cite:t`, `cite:p` 중 하나다. 텍스트는 각각 LaTeX 원문, 참조 라벨, 미주 라벨, 쉼표로 이은 인용 키다. 기존 Core의 인라인 검증과 인용 정규화를 적용하며 계산된 표시 번호는 쓰지 않는다. 일반 HTML 뷰어는 이 텍스트를 그대로 표시할 수 있다. |

HTML `caption`, `tfoot`, `colgroup`, 이미지, 중첩 표, 자유 HTML, CSS·너비 속성, 주석, 이벤트 속성은 입장 검사에서 거부한다. 링크는 Core 의미와 기존 렌더러의 링크 정책으로 다루며 원문 HTML을 Editor나 플러그인의 DOM에 주입하지 않는다.

### 입장과 정규 쓰기

1. `{table}`의 옵션과 선택적 캡션 다음에 완결된 HTML 격자 하나를 읽는다. 격자 안에 빈 줄이 있으면 MyST가 여러 노드로 자르므로 거부한다. `</table>` 뒤의 주석과는 빈 줄로 나눈다. 캡션은 지시문의 한 줄 인수이며, 이어지는 문단은 [표 주석 계약](../design/table-caption-v1.md#cell-breaks-and-table-notes-1973)을 따른다. 다른 곳의 HTML과 다른 표 지시문은 기존 입장 규칙을 따른다.
2. Core의 MyST 경계에서 기존 HTML 파서 계열인 `parse5`로 격자를 읽는다. 명시적 태그·속성과 루트 앞뒤의 잔여 내용을 확인한다. 파서의 자동 삽입·재배치, 닫는 태그 생략, 중복 속성, 허용 범위 밖 구조를 정상화해서 수용하면 원래 칸이 조용히 바뀔 수 있으므로 소스 토큰·위치와 트리를 대조해 거부한다. HTML의 대소문자·인용부호·엔티티·구조 태그 사이 공백의 차이는 허용 범위 안에서 정규화한다. 구조 사이 공백과 달리 문단·목록 항목의 텍스트 공백은 내용이다.
3. 현재 `{table}` 쓰기와 같은 콜론 펜스 선택, 캡션·옵션 순서(`name`, `enumerator`, `enumerated`), LF와 지시문 본문 앞 빈 줄을 쓴다. 번호, 캡션·라벨과 주석 정규화는 기존 규칙을 공유한다. HTML 태그는 소문자, 속성 값은 큰따옴표를 쓴다. `table`, 그룹, `tr`의 여는 태그와 닫는 태그는 각각 별도 줄이다. 칸은 열 순서대로 들여쓰기 없이 여는 태그부터 닫는 태그까지 한 줄에 하나씩 쓴다. 칸의 속성 순서는 `rowspan`, `colspan`, `style`이다. 기본 span과 `ol start="1"`은 생략한다. 인라인 줄바꿈은 `<br>`로 쓴다. 문자 데이터의 `&`, `<`, `>`와 속성의 `"`는 각각 `&amp;`, `&lt;`, `&gt;`, `&quot;`로 쓴다. 한 줄을 깨는 데이터 문자가 기존 인라인 타입에 허용된다면 LF·CR·TAB을 각각 `&#10;`, `&#13;`, `&#9;`로 쓴다.
4. span이 전부 1이고 머리글이 한 행이며 모든 칸이 빈 칸 또는 인라인 문단 하나이면 파이프 격자를 쓴다. 한 문단의 `<br>`은 파이프 격자에 그대로 남는다. 작성 입력의 원래 표기와 무관하게 이 규칙을 적용한다. 마지막 병합을 풀거나 블록을 지웠을 때 조건을 만족하면 파이프로 돌아간다. 정렬이나 인라인을 기존 파이프 격자로 보존할 수 없으면 해당 쓰기를 거부한다. 반대 방향에서는 기존 칸의 인라인을 문단으로 보존한다.
5. 정규 출력은 다시 읽어서 span·행 그룹·정렬·칸 블록·캡션·주석·라벨·번호 옵션을 포함한 지문을 확인한다. 칸의 인라인과 같은 내용의 문단 하나는 파이프 전환 조건 안에서 같은 뜻으로 본다. 빈 문단·목록 또는 연속 문단이 의미를 가지는 경우 그 경계를 보존한다. 편집 이후 유효하지 않거나 표현할 수 없는 내용에는 칸 경로와 이유를 돌려주고 원본 바이트를 지킨다. 두 번째 정규 쓰기의 바이트도 확인한다.

## Core, 공용 작업과 소비자

- **의미 모델**은 기존 표 블록을 확장한다. 머리글 행 수와 행별 시작 칸을 두고, 각 칸에 가로·세로 span, 정렬, 순서 있는 문단·목록을 담는다. 문단은 `InlineContent[]`, 목록은 위 부분집합을 만족하는 기존 `ListContent`다. 덮인 자리는 별도 칸으로 만들지 않는다. 경로 `[block,row,column]`은 0부터 세며 복잡한 표의 `column`은 실제 격자에서 칸이 시작하는 열이다. 시작 칸만 수정 대상으로 받는다. 명령·저장·복구는 호출의 기존 revision/snapshot 보호를 사용한다.
- **입장과 공식 작성**에 같은 격자·칸 검증을 쓴다. 공식 작성 시 기존 500행·32열·8,000칸 한도는 펼친 격자의 행·열·자리 수로 계산한다. span을 확장하기 전에 범위를 검사한다. 칸 안 문단·목록·항목과 표 주석도 기존 작성 입력의 블록 예산에 반영한다. `{table}`의 원래 option map과 해당 범위의 VFile 진단을 보존하고 기존 라벨·번호 검증을 재사용한다.
- **CLI와 SDK**의 기존 단순 표 입력·출력은 그대로 쓴다. 복잡한 표에는 `grid: "complex"`, `headerRows`, `rows`를 사용한다. 행의 `cells`는 시작 칸만 담고, 각 칸은 `column`, `rowspan`, `colspan`, 선택적 `align`, 그리고 `blocks`를 가진다. 각 블록은 `{kind:"paragraph",content:InlineContent[]}` 또는 `{kind:"list",list:ListContent}`다. 읽기에는 기존 경로·표시용 텍스트·머리글 여부를 함께 반환한다. `inspect --format json`의 표 항목에 격자 종류와 머리글 행 수, 각 칸 항목에 span과 블록을 제공해 같은 구조를 작성 입력으로 옮길 수 있게 한다. SDK의 문서 읽기/공식 작성 스키마와 문서 보기 계약은 이 구분을 공유한다.
- **편집 작업**은 기존 Host 문서 작업과 CLI `insert-table`, `update-table-cell`, `apply-batch`를 확장한다. 삽입은 구조화 격자 입력을, 칸 편집은 기존 `--text`·`--content`와 별개의 `--blocks`를 사용한다. 기존 인라인 입력은 인라인 칸에 적용하고 여러 블록·목록이 있는 칸에는 명시적 블록 입력을 요구한다. 화면과 SDK는 칸 블록을 바꾸는 같은 Core 연산과 기존 revision 확인·결과·receipt를 사용한다. 거부된 모양의 파일 교체나 별도 SDK 저장 경로는 생기지 않는다. `check`, `format`, 읽기, 변경 비교, 번호, 참조·미주·인용 집계는 같은 구조를 순회한다.
- **표 단위 동작**은 한 블록의 위치와 번호를 유지한다. 이동·삭제·복제·실행 취소에 캡션과 주석이 함께한다. 표 주석의 미주 제한은 그대로 적용한다. 번호와 라벨을 읽는 순서 및 캡션 → 격자 → 주석의 의미 순서를 유지한다. 비교에서는 한 표 블록 안의 span과 칸 블록 차이를 보여 준다. HTML 원문의 Git diff 비용은 시각 비교로 감수한다.
- **빠른 저장**은 [#1983의 공용 Save 계약](../design/editing-session-save-v1.md#빠른-저장-1983)을 따른다. 기존 적격 파이프 표 칸 수정은 계속 국소 쓰기를 쓴다. 복잡한 칸은 시작 열과 셀 자식 구조가 기존 `LocalWriteBaseline`의 인라인 칸 전제와 달라 첫 구현에서 전체 재생·검증 후 저장한다. 포맷 전환도 전체 경로다. 복잡한 칸의 국소 저장은 실제 지연이 확인되고 전체 재생과 같은 바이트·의미·revision 보호를 증명할 수 있을 때 확장한다.

## 편집기 전환

현재 `table` 노드의 끝에는 캡션과 주석이 들어 있다. [ProseMirror TableMap](https://github.com/ProseMirror/prosemirror-tables)은 표 노드의 직접 자식을 행으로 다룬다. [Tiptap 표 확장](https://tiptap.dev/docs/editor/extensions/nodes/table)을 쓰려면 같은 문서 상태 안에서 표 블록을 바깥 노드로 두고, 그 안에 행만 가진 Tiptap 격자와 기존 캡션·주석을 형제로 둔다. 바깥 노드는 문서 블록의 경로, 라벨, 번호, 블록 도구와 이동·삭제의 단위다. Tiptap 격자는 행·칸, span, selection과 Tab 이동을 맡는다. Core에 전달하는 값은 격자와 칸 블록의 의미다.

기존 표를 이 구조로 먼저 전환한다. 칸 안 문단이 생기면 caret의 부모 타입만 확인하던 키 처리, 복구 검증, 클립보드, 표 도구 위치, `tiptap-projection` 및 Save replay의 칸 위치 계산이 모두 영향을 받는다. Tiptap의 자동 격자 복구와 기본 Tab·붙여넣기 동작이 기존 구조 가드를 우회하거나 span을 정리해 버리지 않도록 점검한다. 행·열 도구는 화면에서 계속 현재 대상을 가리키고 영속 변경은 Core가 검증한다.

복잡한 표의 첫 단계에서는 글자·서식·줄바꿈과 기존 칸 속 문단·목록 항목의 글을 편집할 수 있다. 단순 표의 Enter, Shift+Enter, 마지막 칸 Tab, 캡션 이동과 행·열 명령은 기존 계약을 유지한다. 복잡한 표에서는 span이 유지되는 경로만 연다. 마지막 칸 Tab으로 행을 만들거나 기존 직사각형 전용 행·열 명령을 복잡한 표에 적용하는 동작은 막고, 이 명령들의 CLI·Host 요청도 구조를 보존할 수 없으면 명시적으로 거부한다. 일반 붙여넣기와 리치 클립보드에서 같은 표를 옮길 때 칸이나 블록을 평탄화하지 않는다. 지원 경로에서 보존을 보장할 수 없는 외부 HTML은 기존 붙여넣기 거부 안내를 사용한다.

| 경로와 입력 | 관찰 |
| --- | --- |
| MyST parser + VFile. 위와 같은 span·두 머리글 행·`br`·문단·목록, 캡션과 주석 두 문단. 콜론·백틱 두 펜스 | `mystDirective(name=table)` → `container(kind=table)` → `caption`, **`html` 하나**, `paragraph` 두 개. `html.value`에 격자 20줄이 그대로 들어갔다. 개별 칸 AST와 VFile 진단은 없었다. 캡션과 옵션을 생략해도 raw AST의 격자는 `html` 하나였다. |
| MyST 단락 경계 | 격자 중간에 빈 줄을 넣으면 `html`이 둘로 나뉘었다. 격자 뒤 빈 줄을 빼면 첫 주석이 `html.value` 뒤에 붙었다. 두 경우 모두 진단이 없었다. |
| MyST 옵션 | `name`, `enumerator`, `enumerated`는 맵에 남고 컨테이너에는 라벨, 고정 번호 문자열, boolean이 들어갔다. `label`과 `numbered: false`도 라벨과 번호 숨김으로 변환됐다. `align`은 upstream 진단 없이 맵에 남았다. 미지 옵션은 콜론·YAML 모두 진단이 났고 중복 `name`은 첫 값과 진단을 남겼다. `constructor`는 맵에서 사라졌지만 중복 진단은 남았다. `enumerated: xyz`는 진단과 함께 컨테이너의 `true`로 바뀌고, `enumerator: xyz`는 진단 없이 문자열로 남았다. 맵·진단과 별개로 Core 번호 검증이 필요하다. |
| Core 내부 MyST 읽기와 쓰기 | 현재 전처리는 `table` 자식을 찾을 때만 주석을 분리한다. HTML 격자는 캡션이 있는 경우 주석과 함께 `legend`에 들어갔고, 캡션이 없으면 격자 자체가 `caption`으로 승격됐다. 내부 재직렬화는 `unsupported-content`와 `Table container must have table node child`로 실패했다. 지시문 밖의 맨 HTML은 내부 쓰기에서 그대로 남았다. |
| 공개 Core `parse()`와 정규 쓰기 | `{table}` 안의 HTML은 `native-content`, 경로 `[1]`에서 거부돼 공개 `serialize()`에 넘길 문서를 얻지 못했다. 맨 HTML도 `native-content`로 거부됐다. 대조군인 파이프 격자는 맨 파이프 입력과 `{table}` 입력 모두 `parse → serialize → parse → serialize`를 통과했다. 정규 원문은 `{table}` 안의 파이프 격자였고, `<br>`과 대조군에 붙인 캡션·번호·주석은 유지됐다. 두 번째 출력도 같은 바이트였다. |

따라서 Core가 지시문을 들어 올리고 일반 컨테이너를 정리하기 전에 HTML 격자를 검증해 의미 노드로 바꾸고, 그 뒤의 문단을 주석으로 묶어야 한다. 정규 쓰기는 기존 파이프 표와 같이 Core가 지시문을 쓰고, 격자 writer만 의미에 따라 고른다. 이 실측은 MyST 토큰·AST 및 Core 왕복 경계를 확인했다. 제안한 변환과 Tiptap 동작은 아래 구현 검증 대상으로 남는다.

## 검토한 대안

- 모든 표를 HTML로 쓰면 기존 파이프 원문의 가독성과 변경 검토 비용이 달라진다.
- 표를 별도 파일에 두면 표 하나를 이동·복제할 때 문서와 파일 두 곳에서 캡션·주석·참조의 소유권을 맞춰야 한다.
- `list-table`은 칸 블록의 작성에는 도움이 되지만 셀 병합을 표현할 수 없다.
