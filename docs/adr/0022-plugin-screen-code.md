# ADR-0022: 플러그인 화면 코드

> 2026-11-13 #1595: 다른 PC Host 접속은 삭제했다. 현재 화면 코드는 같은 PC/개발 Host의 플러그인만 제공한다. 아래 원격 코드 실행 결정은 당시 기록이며 접속 기능의 재도입 승인이 아니다. 보관: `archive/2026-11-13-plugins-declarative`.

- Status: Accepted
- Decision date: 2026-11-13
- Authority: 소유자 승인 [#1592](https://github.com/litzio/litzio/issues/1592), under [AGENTS.md](../../AGENTS.md).
- Amends: ADR-0012·0019·0020의 플러그인 화면 선언과 앱 번들 script 한정 경계.

## 결정

1. 플러그인이 자기 화면 코드를 작성한다. 리치오 부품과 디자인 토큰을 기본으로 제공한다.
   선언형을 택했던 이유는 디자인 일관성이었고 보안 경계는 아니었다.
2. 원격 Host의 플러그인 화면 코드를 접속한 Desktop·브라우저 클라이언트에서 실행한다.
   보안은 아직 계획하지 않으며 샌드박스·iframe 격리·권한 모델·서명·버전 협상은 만들지 않는다.
3. 선택지가 갈리면 구현 복잡도와 난이도가 낮은 쪽을 택한다.
   컨셉 검증에 필요한 최소 경로로 제작 자율성을 확인한다.
4. 기존 플러그인과의 호환은 고려하지 않는다. 현재 사용자가 없으므로 manifest도 바꿀 수 있다.
5. Host의 Node 하위 프로세스·등록·reload·공용 작업과 receipt는 유지한다.
   Core 문서 의미와 공식 저장 경로를 화면이 우회하지 않는다.

외부 라이브러리는 만들 때 묶어 플러그인에 포함한다. 쓰는 쪽은 도구와 네트워크가 필요 없다.

## 감수하는 것

- 원격 Host 코드가 클라이언트 권한으로 실행된다.
- 앱 부품이 바뀌면 플러그인이 깨질 수 있다.
- 자유로운 화면 코드는 디자인 품질을 보장하지 않는다.
- 기존 플러그인이 호환되지 않을 수 있다.

## 대체 관계

ADR-0012·0020과 [플러그인 화면 계약](../design/plugin-screens-v1.md)의
“플러그인 화면은 앱이 정한 부품의 선언” 경계를 대체한다.
ADR-0019와 ADR-0018의 원격 script 금지도 플러그인 화면 코드에 한해 대체한다.
나머지 문서 의미·공식 쓰기·대상 Host 책임은 유지한다.

## 2단계 보충 (#1592)

코드 화면은 신분증(id/name/icon/실행·화면 진입점/공개 작업)만 작성하고 SDK가 내부 계약으로 정규화한다. 비공개 화면 handler는 schema 없이 호출한다. 제작·수정은 같은 Host install 작업으로 마친다. 선언형 제거는 3단계이며 과도기에는 플러그인별로 둘 중 한 방식만 사용한다.
