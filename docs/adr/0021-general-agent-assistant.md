## 현재 적용 범위 (2026-11-14 정적 확인)

범용 비서·원본 직접 수정·공급자 권한·CLI/스킬 기본은 유지한다. #1360 보완으로 창 연동 전용 도구 예외도 종료됐다. 아래 “대체하는 기존 결정”의 창 연동 예외는 보완 전 이력이며 새 창 도구를 허용하는 기준이 아니다. 현재 활성 저장 경로 전달·문서 보호·변경 확인과 되돌리기는 [비서 계약](../design/main-agent-v1.md)을 따른다.

## 2026-11-13 보완 결정 (#1360)

창 상태 조회·탭과 폴더 조작·표시 설정 변경과 되돌리기 도구 및 화면↔Host 요청 통로를 제거한다. 사용자가 말·파일 참조로 대상을 가리키며 비서는 파일과 CLI로 작업한다. 활성 문서의 저장 경로는 메시지를 보낼 때 직접 붙인다. 권한 scope·첨부 검사·미저장 보호·문서 변경 보기와 되돌리기·대화 관찰과 질문은 유지한다. 아래 3번과 창 연동 전용 도구 예외는 이 결정으로 대체하며 당시 이유는 보존한다.

## 당시 결정과 이유

1. 비서는 범용 에이전트다. 폴더의 모든 파일과 셸 스크립트를 자유롭게 다루고, 사람과의 소통은 리치오 안에서 한다.
   전용 도구로 좁힌 설계 때문에 일을 완수하지 못하고 일반 터미널 에이전트보다 능력이 제한되는 문제를 해결한다.
2. 기존 문서는 바로 수정하고 사람은 사후에 변경을 보고 되돌린다. 사본 → [적용] 방식은 폐기한다.
   사본 생성부터 사람의 적용까지 여러 단계를 거치는 편집 부담을 줄인다.
3. 전용 Host 도구는 실행 중인 창과 연동해야 하는 것만 남기고, 나머지는 CLI와 스킬 안내로 넘긴다. 지시문의 셸 금지를 지운다.
   전용 도구 우선 지시가 에이전트의 기본 파일 편집·셸 능력을 막고 불필요한 호출을 늘리기 때문이다.
4. 권한은 공급자 방식으로 단순화한다. 제한 모드에서도 셸을 쓸 수 있어야 하며, 셸이 막히는 환경은 원인과 해결 방법을 안내한다.
   셸 시작 실패는 샌드박스 자체의 한계가 아니라 실행 환경의 문제였으므로 셸 없는 편집을 전제로 삼지 않는다.
5. ADR·계약은 소유자가 실제로 정한 짧은 결정만 남기고 나머지는 이력으로 내린다. 기존 ADR은 목표 달성 여부로 다시 판단한다.
   구현 중 덧붙은 세부가 소유자가 정하지 않은 제약으로 굳는 문제를 줄인다.
6. 비서 작업 폴더는 지금처럼 앱 데이터의 비서 폴더로 유지한다. 작업 폴더 때문에 안 되는 실제 사례가 나오면 다시 검토한다.
   셸 차단과 무관하고, 여러 폴더를 한 창에 여는 구조와 맞으며, 임시 파일이 사용자 폴더에 쌓이지 않기 때문이다.

## 대체하는 기존 결정

- [ADR-0014](0014-main-agent-app-server.md)의 기존 문서를 수정하지 않고 텍스트로만 제안하는 결정을 대체한다.
- ADR-0014의 제한 권한에서 Copilot 셸을 거부하는 결정을 대체한다.
- [ADR-0015 1절](0015-shared-host-operations.md#1-새-사용자-기능은-공용-작업과-cli를-함께-제공한다)의 “비서에 필요하면 같은 정의로 비서 도구를 만든다”를 대체한다. 비서는 CLI와 스킬을 기본으로 쓰고 전용 도구는 창 연동이 필요할 때만 만든다.
- ADR-0015의 새 사용자 기능을 Host 공용 작업으로 정의하고 CLI 명령을 함께 제공하는 결정은 유지한다.

## 구현 상태

현재 동작과 검증 범위는 [비서 계약](../design/main-agent-v1.md)을 따른다. 화면 도구는 위 보완 결정에 따라 제거했다.
