## 1. 한 쪽 요약

이번 정리는 한 사람이 자기 PC에서 문서 업무를 끝내는 데 집중하기 위한 것이다. 쓰이지 않는 실험의 호환 비용을 줄이고, 플러그인마다 본체 안에 전용 화면을 만드는 부담을 덜었다.

- **걷어 냄:** OneDrive·Jira 실험 플러그인, 앱이 해석하던 화면 설명 문법, 기존 문서 변환·검수와 작업 이력, 다른 PC 접속과 여러 Host 구분, 비서의 화면 조회·대행 도구, 확실히 쓰이지 않는 코드와 의존성 선언.
- **더하고 보강함:** 플러그인이 자기 화면 코드를 제공하는 방식, 공식 문서 읽기·작성 입력, 그림 저장, 실행 주소·명령줄 연결, 문서 보기와 파일 선택. 큰 문서의 이력을 분리하고 큰 코드 파일의 독립적인 부분을 옮겼다.
- **지킴:** 문서 편집·저장·복구, 비서의 변경 보기·되돌리기·질문·중단, 같은 PC의 공유 처리 프로그램, 플러그인의 설치·설정·비밀 값·교체 검사. 제품 전용 검사를 지울 때 공통 보호는 작은 시험용 플러그인과 문서 자료로 옮겼다.

여기서 **Host**는 문서·플러그인·비서 처리를 맡는 프로그램이다. 같은 PC에서 여러 창이 함께 쓰는 Host는 남겼다.

**기존 플러그인 파일 작업(K1)의 실행 흐름도 함께 지웠다.** K1의 실행·임시 처리·이력·결과 게시가 선언형 화면과 검수 자료에 결합돼 있었다. 깨끗하게 남기려면 새 기능 계약을 설계해야 했으므로 실행 핵심까지 제거했다. 새 변환 플러그인을 예상해 공용 장기 작업 기능을 미리 만들지 않았다.

같은 PC의 공유 Host, 로컬 연결 상태와 수동 다시 연결, 개발·검사용 독립 HTTP Host, 명령줄에서 처리 대상을 직접 지정하는 기능(`--host`)은 유지했다. 플러그인의 별도 실행 프로그램과 설치·신뢰·활성·설정·비밀 값·비서 지침·설치 도구의 공통 기반도 남겼다. 단독 PDF 보기와 일반 문서의 저장·복구·변경 보기·되돌리기도 유지했다.

**저장 형식 전환의 사용자 영향은 남는다.** 정상 저장·종료 후 새 앱으로 시작하면 열린 탭, 열린·최근 폴더, 접힌 구역, 문서별 표 줄바꿈, 마지막 대화 자동 재개 기억이 한 번 초기화된다. 옛 형식의 미저장 복구 기록은 새 앱에서 복원하지 않는다. 옛 기록을 자동 변환하거나 지우지 않으며 원본 문서와 대화 본문도 바꾸지 않는다. 새 기록과 옛 창의 쓰기를 분리해, 옛 원격 기록이 같은 경로의 로컬 문서에 적용되는 일을 막았다. 이미 열려 있는 탭의 식별자나 편집 상태를 바꾸는 실시간 형식 전환은 하지 않았다. ([형식 전환 기록](https://github.com/litzio/litzio/pull/1619))

비서는 이제 “열린 탭을 다 닫아 줘”, “이 창을 다크로 바꿔 줘”를 대신 수행하지 않는다. 활성 문서의 **저장 경로**는 메시지에 직접 붙여 “이 문서”의 대상을 알려 준다. 파일 참조·비서 지침(스킬)·이미지, 열린 폴더에 근거한 실행 권한과 첨부 검사, 미저장 보호는 유지했다.

([처리 기록](https://github.com/litzio/litzio/issues/1595#issuecomment-6847479196))

### 자동 검사 정리와 시간

자동 검사(CI)는 브라우저 8분할을 유지하고 실제 실행 시간에 맞춰 배정을 바꿨다. Windows 단위 검사는 변경 제안 단계에 먼저 돌려 병합 대기열에서야 결함을 찾는 비용을 줄이려 했다. 차트 라벨이 바뀌는 순간 좌표를 읽다 실패하던 갤러리 검사도 고쳤다. 남는 기능의 보호·필수 검사·시간 제한은 낮추지 않았다. ([#1621](https://github.com/litzio/litzio/pull/1621))

다음은 [당시 CI 측정 댓글](https://github.com/litzio/litzio/issues/1595#issuecomment-6855708388)의 수치다. ‘사용 합계’는 병렬 검사 기계의 사용 시간을 합한 값이다.

| 구분 | 표본 | 전체 대기 시간 | 검사 작업 수 | 사용 합계 |
| --- | ---: | ---: | ---: | ---: |
| 변경 제안, 삭제 전 | 2회 | 10.4분 | 미기록 | 58.7분 |
| 변경 제안, 삭제 후 | 13회 | 7.5분 | 14 | 48.1분 |
| 변경 제안, CI 정리 적용 | 1회 | 8.8분 | 16 | 54.5분 |
| 병합 대기열, 삭제 전 | 5회 | 7.0분 | 미기록 | 76.3분 |
| 병합 대기열, 삭제 후 | 10회 | 7.7분 | 19 | 67.0분 |
| 병합 대기열, CI 정리 적용 | 1회 | 7.2분 | 22 | 확인하지 못함 |

**CI 정리로 전체 시간이 줄었다는 결과는 얻지 못했다.** 변경 제안은 7.5→8.8분이었고 Windows 검사 선행으로 작업 수와 사용 합계가 늘었다. 병합 대기열의 7.7→7.2분도 적용 후 표본이 1회뿐이다. 부하와 변경 범위가 섞여 있어 삭제나 분할 재배정의 효과로 단정하지 않는다.

## 4. 정리하다 찾은 결함과 조치

| 발견한 것 | 판정과 조치 | 근거 |
| --- | --- | --- |
| Windows의 짧은 경로에서 플러그인 설치 거절 | 같은 폴더의 짧은 별칭과 긴 경로가 허용 범위 비교에서 달라졌다. 실제 경로 표기를 맞춘 뒤 기존 범위 검사를 적용하도록 고쳤다. 짧은 경로 재현과 서로 다른 드라이브 시험은 따로 확인됐다. | ([#1616](https://github.com/litzio/litzio/pull/1616)) |
| Mermaid 원문 폼의 적용 클릭 손실 | 누르고 떼는 사이 미리보기가 완성돼 버튼이 밀리는 제품 결함을 강제로 재현했다. 미리보기 높이를 예약하고 큰 결과를 내부 스크롤로 바꿨다. 수정은 병합됐고 해당 이슈는 닫혔다. | ([#1625](https://github.com/litzio/litzio/issues/1625), [#1627](https://github.com/litzio/litzio/pull/1627)) |
| 작은 Mermaid 속성 창의 원문 편집 클릭 손실 | 썸네일 완성으로 버튼이 밀리는 별도 결함을 재현했다. 후속 이슈는 열려 있다. 일반 이미지의 Replace에서도 같은 클릭 손실이 나는지는 확인하지 못함. | ([#1626](https://github.com/litzio/litzio/issues/1626)) |
| visual-states 검사 실패 | 가짜 저장 응답이 현재 문서의 저장 상태 식별값 대신 처음 문서의 값을 돌려줬다. 파일 감시가 외부 변경으로 판단해 편집기를 교체했다. 현재 요청의 값을 돌려주도록 검사 자료를 고쳤다. | ([#1624](https://github.com/litzio/litzio/pull/1624)) |
| figure-draft-race 검사 실패 | 화면의 커서 위치가 편집기 상태에 반영되기 전에 검사했다. 실제 위치·포커스 단언은 유지하고 상태 반영을 관측한 뒤 입력하도록 고쳤다. | ([#1624](https://github.com/litzio/litzio/pull/1624)) |
| 주소 전달 수정이 요청 허용 범위까지 넓힘 | 리뷰가 잡아 병합 전에 되돌렸다. 지원하지 않는 주소에는 자동 주소를 주지 않고, 기존 Host·Origin 허용 정책과 거부 검사를 유지했다. | ([#1613 리뷰 대응](https://github.com/litzio/litzio/pull/1613#issuecomment-6852525215)) |
| 통과한 플러그인의 아이콘이 로드되지 않음 | 신분증 검증과 실제 로더의 지원 형식이 달랐다. PNG·SVG 정의를 한 곳에서 함께 쓰도록 맞췄다. | ([#1606 리뷰 대응](https://github.com/litzio/litzio/pull/1606#issuecomment-6848108308)) |

Mermaid 제품 결함의 강제 재현은 성공했다. 다만 원래 CI의 mermaid-authoring 실패와 같은 원인인지는 당시 포인터 기록이 없어 확정하지 못했다. 시간 제한을 늘리거나 재시도를 넣어 덮지 않고 다음 실패의 진단을 보강했다.

## 5. 남긴 것과 이유

### 지울 근거가 부족하거나 나눌 위험이 큰 부분

- **번역 후보 95개:** 정적 검색만으로는 동적 오류·선택 값·일반 문구의 소비자를 확정하지 못했다. 현재도 95개 키가 선언돼 있음을 확인했다. 새 기능 이후의 실제 사용 여부를 모두 다시 판정한 것은 아니다. 그 밖의 미사용 인자 후보와 공개 제작 도구의 표면도 일괄 삭제하지 않았다. ([#1622](https://github.com/litzio/litzio/pull/1622))
- **App의 파일 조작 처리(파일 action):** 이름 변경·삭제·되돌리기에 쓰는 원래 연결, 편집 상태, 복구 중지·재개, 되돌리기용 결과가 한 순서로 얽혀 있다. 탭 열기·닫기·미저장 보호도 연결돼 있다. 추가 분할은 지금 하지 않기로 했다. 다시 손댈 필요가 생기면 이 수명 전체를 경계 후보로 검토한다. ([#1628](https://github.com/litzio/litzio/pull/1628))
- **플러그인 작업 화면의 미사용 가져오기·인자:** `ViewWorkspace`는 병렬 문서 보기 작업 영역이라 그대로 뒀다. App의 쓰이지 않던 가져오기·PDF 탐색 보조 함수는 뒤의 별도 커밋에서 삭제했다. ([#1622](https://github.com/litzio/litzio/pull/1622), [#1628](https://github.com/litzio/litzio/pull/1628))
- **브라우저 검사 준비 파일:** 시험 자료 생성, 시나리오별 준비, 브라우저 수명·진단·정리가 섞여 있다. 자료 공급과 실행 수명을 경계로 볼 수 있으나, 준비 순서·실행 간 격리·재사용 프로필을 함께 보존해야 해 이번에는 나누지 않았다.
- **큰 공용 스타일 파일:** 창·문서·설정·공통 상호작용이 섞여 있다. 실제 화면 소유자별로 나누되 공통 색·간격 값과 조작 부품 규칙은 한 곳에서 유지하는 경계를 제안만 남겼다. ([분리 후보 기록](https://github.com/litzio/litzio/pull/1622))
- **새 문서 보기의 규모 한계:** 보기마다 저장본 읽기와 편집기 인스턴스 비용이 든다. 여러 보기를 동시에 띄운 성능·메모리와 패키지 Desktop 동작은 확인하지 못함. 셀 강조·배치 변경 뒤 대상 이동 보정도 기준 시점에는 별도 PR이 열려 있다. ([계약](../design/plugin-screens-v1.md), [#1629](https://github.com/litzio/litzio/pull/1629))
- **화면의 열린 폴더 범위:** 파일 선택·열기·저장 범위는 경로 문자열 기준이다. 폴더 안 링크를 따라간 실제 위치까지 화면 범위 안임을 보장하지 않는다. Host가 허용한 실제 폴더 경계 검사는 남아 있다. 세 호출에 함께 적용할 계약 확장이 필요해 이번에는 한계를 명시했다. ([#1620](https://github.com/litzio/litzio/pull/1620))

## 6. 다음에 볼 것

1. **사람의 클릭이 사라지는 남은 표면을 먼저 본다.** Mermaid 작은 속성 창의 후속 배치를 정하고, 일반 이미지에서도 같은 문제가 나는지 확인한다. 문서 보기의 셀·배치 보정은 진행 중인 별도 변경을 검토한다.
2. **자료 보존에 닿는 경계를 확인한다.** Copilot 종료 실패에서 실제 잔존을 판별하고, 화면 폴더 범위와 링크의 실제 위치 차이에 어떤 계약이 필요한지 판단한다. 원인이나 계약 확인 전 허용 범위를 넓히지 않는다.
3. **실제 비서가 쓰기를 완수하지 못한 이유를 분리한다.** 같은 요청·권한에서 실행 명령과 제한 언어 상태를 확인해 제품 경로 문제와 실행 환경 문제를 나눈다.
4. **검증의 격리와 빌드 재현성을 다듬는다.** 비서 폴더 격리의 기본값·안내와 고지 수집의 상위 폴더 탐색 경계를 살핀다. 기존 사용자 데이터를 쓰는 재현은 하지 않는다.
5. **남은 느림과 경고는 다음 실패의 자료로 좁힌다.** 명령줄의 단계별 시간, Mermaid 포인터 기록, ResizeObserver 발생 요소를 모은다. 시간 제한·재시도·검사 범위부터 바꾸지 않는다.
6. **고아 후보와 큰 파일은 실제로 다시 손댈 때 본다.** 번역·인자 후보의 소비자를 재확인하고, 검사 자료·브라우저 수명·공용 스타일의 경계를 검토한다. App 파일 조작 처리의 추가 분할은 현재 계획에 넣지 않는다.
