# 비서와 플러그인 만들기 스파이크

- Status: Historical
- Last verified: 2026-11-10 (Linux Host, 로컬 daemon, 실제 Codex `gpt-6.1-terra`·추론 강도 `high`, 공개 GitHub API 3~4회 호출)
- Authority: 증거만 제공한다. 현재 계약이나 구현 승인이 아니며, 동적 UI 재구축은 [Discussion #767](https://github.com/litzio/litzio/discussions/767)의 2026-11-09 기준을 따른다.

## 질문

#1341(PR #1353·#1357)이 비서 뷰 생성·저장 뷰·Views 탭·차트를 제거한 뒤, #767의 용도 B(협의·판단·수정)가 성립하는지 확인한다. 사용자가 플러그인 사양 인터뷰에서 결정을 UI로 바꾸면, 다음 질문과 사양이 바뀌고 앞선 결정은 유지되는가.

## 만든 것

- 화면: 사이드바·Command Center의 "플러그인 만들기" 탭. 비서 대화, 질문 폼, 오른쪽 결정요소(ADR 카드), 개발 계획(노드 그래프·생성 사양·열 미리보기), 승인 뒤 설치 결과와 사용 방법.
- 계약: `apps/editor/shared/plugin-builder.ts`. 위젯은 단일 선택·다중 선택·텍스트·토글 네 가지뿐이고 결정 카드·계획 노드·엣지·사양도 고정 필드다. zod로 검증하며 HTML, 코드, 레이아웃 언어는 받지 않는다.
- 비서: `POST /api/plugin-builder`. 기존 Codex 연결을 재사용하되 별도 임시 읽기 전용 thread, 동적 도구 없음, `outputSchema`로 응답을 제한한다. 검증에 실패하면 한 번 다시 묻고, 그래도 안 되면 대본 모드로 대체하며 이유를 남긴다. `LITZIO_PLUGIN_BUILDER_MODE=scripted`는 결정적 대본(GitHub 이슈, 3라운드와 결정 수정 분기)을 쓴다.
- 생성: 비서가 코드를 쓰지 않는다. 검증된 사양을 템플릿(`github-issues`, 토큰 없는 읽기 전용)에 넣어 공개 SDK만 쓰는 커뮤니티 플러그인을 만든다. 승인 뒤 공식 관리 경로(scaffold, validate, register, trust, enable)로 설치한다.

## #1341과의 관계

제거된 것(view_catalog, propose_view, 저장 뷰·즐겨찾기, Views 탭, 차트, 범용 view DSL)은 되살리지 않았다. 이 스파이크는 #767의 협의형 사례 하나에 필요한 고정 위젯과 결정 기록만 둔다. 조회 뷰의 제한을 협의형 전체로 넓히지 않았고, 일반 비서 대화·`requestUserInput`도 건드리지 않았다.

## 결과

- 사용자가 결정 D(인증)를 "토큰(PAT)"으로 바꾸자 다음 라운드가 토큰 처리 질문으로 바뀌었고, 비서가 Linux Host의 비밀값 한계를 설명했다. 다시 "공개 API만"으로 바꾸면 사양에 반영됐다. 사용자가 바꾼 결정은 이후 라운드에서도 비서가 덮어쓰지 못한다(서버가 다시 적용).
- 승인 뒤 플러그인이 설치·활성화되고 실제 `litzio/litzio` 이슈가 조회됐다.

## 한계

- 생성기는 `github-issues` 템플릿 하나만 지원한다. 다른 서비스는 계획까지만 만들고 생성하지 않는다.
- 토큰이 필요한 플러그인은 Linux Host에서 비밀값을 저장할 수 없어(Windows Host 전용) 생성하지 않는다.
- "문서에 링크 삽입"은 SDK에 기여 지점이 없어 미정으로 남는다.
- 흐름도 배치는 단순 계층 배치이며 비서가 낸 그래프가 어색하면 그대로 보인다. 화면 미리보기는 열 구성만 보여 준다.
- 인증 없는 GitHub 요청은 시간당 60회이며 출구 IP별로 공유돼 일시적으로 403이 날 수 있다. 승인 단계는 한 번만 다시 시도한다.
- 모델 이름과 추론 강도는 코드 상수다(AGENTS.md의 플러그인 제작 검증 기준). 비서 설정과 연결하지 않았다.
