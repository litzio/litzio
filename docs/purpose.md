# 리치오의 목적

- Status: Accepted
- Decision date: 2026-11-13
- Last verified: 2026-11-13 (소유자 확인. 문서의 방향을 적은 것이며 코드와의 대조는 하지 않았다)
- Authority: 소유자 결정. 제품 방향의 기준이며 [AGENTS.md](../AGENTS.md)의 저장소 제약, Accepted ADR, Implemented 계약을 대신하지 않는다. 기존 결정이 이 목적과 어긋나면 임의로 고치지 말고 소유자에게 올린다.

리치오는 문서가 중심인 업무를 사람과 AI가 함께 수행하는 작업 환경이다. 여러 곳의 자료를 검토하고 편집할 수 있는 문서로 만들고, 필요한 근거와 결과의 연결을 유지하며 분석·설계·보고를 완성한다. 그 과정에서 만든 일하는 방법은 플러그인으로 다시 쓰고 다른 사람에게 전달한다.

이 문서는 지금 제공하는 기능의 목록이 아니라 리치오가 향하는 곳을 적는다.

## 누구를 위한 것인가

문서를 만들고 다루는 것이 일의 중심인 사람을 위한 도구다. 요구사항을 정리하는 사람, 설계하고 분석 보고서를 쓰는 사람, 여러 보고를 취합하는 사람이 그 예이고, 개발자가 아닌 사람도 포함한다.

지금은 한 사람이 자기 PC에서 업무를 끝까지 해내고, 그 결과와 일하는 방법을 동료에게 전달하는 데 집중한다. 여러 부서가 각자 이 도구로 일하고 결과를 주고받는 모습은 그 뒤의 방향이다.

## 무엇을 하려는가

사람과 AI가 함께 읽고 쓸 수 있는 문서 위에서 일하게 한다.

1. **재료를 문서로 들여온다.** 처음부터 쓰거나, 이미 있는 파일(PDF, Word, 발표 자료, 표)을 변환하거나, 기존 업무 도구의 자료를 가져온다.
2. **그 문서 위에서 사람과 비서가 일한다.** 요구사항을 뽑고, 분석을 쓰고, 여러 자료를 취합한다.
3. **결과를 받는 쪽에 맞는 형태로 내보낸다.** 다른 사람이 읽을 화면용 문서나 다른 시스템이 받는 교환 파일로 내보내며, 받는 사람에게 리치오가 없어도 된다.
4. **근거와 결과의 연결을 유지한다.** 원문 검수나 요구사항 도출처럼 출처 확인이 필요한 업무에서는 가져온 자료와 그것으로 만든 결과의 관계를 확인할 수 있어야 한다. 모든 문장에 출처를 붙인다는 뜻은 아니다.

## 리치오 문서가 해야 하는 것

- **누구나 쉽게 편집한다.** 보이는 그대로 고치는 화면에서 문법을 몰라도 쓸 수 있다.
- **같은 요소는 같은 규칙으로 저장한다.** 사람이 쓰든 비서가 쓰든, 그림·표·수식·참조처럼 같은 의미의 요소는 같은 문법과 구조를 따른다.
- **복잡한 엔지니어링 문서를 담는다.** 수식, 그림과 표의 번호와 캡션, 상호 참조, 미주처럼 기술 문서에 필요한 요소를 표현하고, 필요한 외부 형식으로 전달할 수 있다.
- **외부 도구와 이어진다.** 문서는 사람이 읽을 수 있는 텍스트 형식으로 저장하고, 그림과 첨부 자료의 연결을 유지한다. 다른 도구와 자동화가 문서를 읽고, 검사하고, 고칠 수 있는 방법을 제공한다.

## 문서, 비서, 플러그인

- **지금은 문서의 기본을 먼저 갖추고, 비서가 일을 이끄는 환경을 지향한다.** 비서가 없는 사람도 읽기, 편집, 내보내기, 결과 확인, 되돌리기는 화면에서 할 수 있어야 한다. 문서가 먼저인 것은 지금의 순서이고, 제품이 향하는 곳은 비서가 맡긴 일을 끝까지 해내는 작업 환경이다.
- **비서는 맡긴 일을 끝까지 해낸다.** 사용자가 의도와 조건을 전하면 비서는 필요한 자료, 파일, 외부 도구를 다뤄 일을 진행하고, 사람이 검토하고 이어 쓸 결과를 문서와 필요한 산출물로 남긴다. 문서가 중심이라는 말이 비서가 다룰 수 있는 범위를 문서로 제한한다는 뜻은 아니다.
- **문서 기본 밖의 기능은 전용 화면 없이 비서에게 맡겨도 된다.** 다만 일의 진행과 결과를 확인하고 멈추는 조작은 화면에서 할 수 있어야 한다.
- **플러그인은 일하는 방법을 담아 나누는 수단이다.** 화면, 처리 코드, 자료, 비서에게 주는 지침을 묶어 다른 사람이 다시 쓸 수 있게 한다. 받는 쪽에 개발 도구는 필요 없다. 비서의 능력을 쓰는 것이 핵심인 플러그인도 있고, 비서 없이 화면에서 쓰도록 만든 플러그인도 있다. 비서가 필요하면 그 사실을 밝힌다.
- **플러그인은 열린 문제를 좁힌다.** 명확한 규칙으로 처리하는 코드일 수도 있고, 비서가 추론할 때 쓸 자료와 선택지를 건네는 역할일 수도 있다. 반복되는 절차와 도구 연결은 플러그인으로 틀을 잡고, 그 안에서 필요한 해석과 판단은 비서가 맡을 수 있다.
- **플러그인의 화면은 만드는 쪽이 정한다.** 리치오는 부품과 안내로 어울리는 모양을 돕고 강제하지 않는다.

## 반드시 지키는 것

- **문서를 잃거나 깨뜨리지 않는다.** 편집 중인 내용과 저장하지 않은 작업을 보호하고, 저장 도중에 문서가 손상되지 않게 하며, 밖에서 바뀐 내용을 조용히 덮어쓰지 않는다. 읽거나 안전하게 고칠 수 없는 문서는 원본을 그대로 두고 그 사실을 알린다.
- **비서가 바꾼 것은 되돌릴 수 있어야 한다.** 비서가 바꾼 문서와 작업 파일은 무엇이 바뀌었는지 확인하고 되돌릴 수 있어야 한다. 외부 시스템에서 한 일은 그 시스템이 제공하는 취소와 복구의 범위를 따른다.

## 리치오가 아닌 것

- **보관소가 아니다.** 문서는 사용자가 고른 폴더에 두고, 필요하면 조직이 이미 쓰는 보관·동기화 수단으로 관리한다. 장기 이력, 백업, 보관소의 접근 권한은 그 수단에 맡긴다. 리치오가 맡는 것은 위의 "반드시 지키는 것"이다.
- **만능 도구가 아니다.** 조직이 이미 쓰는 업무 도구를 대체하지 않고 연결해 쓴다.

## 지금 하지 않는 것

아래 기능은 지금 구현하거나 미리 설계하지 않는다. 표의 조건은 다시 논의를 시작할 근거이고, 재개는 소유자가 정한다. 현재의 문서 보호와 되돌리기는 계속 지킨다. 이미 있는 같은 PC의 daemon과 원격 Host 접속은 당장 없애지도 넓히지도 않으며, 이 목적에 필요한지는 따로 재검토한다.

| 하지 않는 것 | 다시 논의할 조건 |
|---|---|
| 중앙 서비스에 자료를 모으고 여러 사용자가 함께 쓰기 | 실제 공동 업무에서 기존 보관소와 결과물 전달로 해결되지 않는 사례가 확인될 때 |
| 실시간 동시 편집 | 위 조건이 충족되고, 동기화와 작업 분담으로 해결되지 않는 충돌이 실제로 반복될 때 |
| 리치오 자체의 사용자, 역할, 권한 관리 | 중앙 서비스를 실제로 운영하고, 기존 계정과 권한 체계로 해결되지 않는 요구가 생길 때 |
| 문서 형식이 바뀔 때 옛 문서를 자동으로 옮기기 | 기존 문서를 옮길 필요가 확인되고 소유자가 지시할 때 |
| 자체 장기 이력, 백업 | 하지 않는다. 보관소의 일이다 |
