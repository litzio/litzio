# 2026-10-30 CLI 기반 AI 보고서 작성과 채팅 탭

- Status: Historical
- Date: 2026-10-30 (브랜치 마지막 커밋일, KST)
- 결론: **미정** — 문서에 병합 후보가 아니라고 적혀 있다. 이슈 #657은 닫혔다.
- 범위: 스파이크 기록이다. 스파이크 코드는 master에 들어가지 않으며 현재 제품 계약이 아니다. 정책은 [스파이크 기록](README.md)을 따른다.

## 목적

AI가 열린 폴더의 저장 문서를 읽고 문서 CLI를 거쳐 검증된 새 보고서를 만들 수 있는지, AI 진입점을 채팅 탭으로 둘 수 있는지 확인한다(#657).

## 무엇을 만들었나

- 메모리 안의 AI 대화가 열린 폴더 문서로 새 보고서를 만든다. 보고서는 Host 검증을 통과해야 열린다.
- 코드 변경: 문서 CLI 경유 생성, `apply-batch --operations -` stdin 입력, 검증된 operations 예시 주입, 사이드바에서 여는 "AI 채팅" 특수 탭, 설정에서 모델 선택, 보고서 폴더 기본값 `reports`, 대화 지우기 버튼, 명시 요청 때만 보고서 작성.
- 구현 모델은 `codex-ai` 스파이크의 transport를 이어 쓴다(이 브랜치는 그 커밋을 포함한다).

## 결과·관찰

- 1라운드(`gpt-6-luna` 3건, 51~65초): Host 구조 검증 통과 2/3. 통과한 두 문서에 Core 참조 노드가 0개여서, 요청한 기능(표·수식·그림 참조)까지 완성한 경우는 0/3이었다. 첫 요청은 operations JSON 따옴표 문제로 빈 문서였다.
- 2라운드: stdin 입력과 검증된 예시를 넣고 같은 요청 3건을 재실행했다. 모든 batch가 stdin을 썼다.
- 3라운드: 사이드바 진입과 채팅 탭 흐름을 확인했다(2건, 약 17~20초). 보고서 품질은 평가하지 않았다.
- 상세 측정은 브랜치의 `docs/reviews/ai-report-spike-2026-10-28.md`에 있다.
