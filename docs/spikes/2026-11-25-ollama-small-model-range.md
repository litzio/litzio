- Status: Historical

## 목적

리치오 비서의 `gemma4:e4b`에 반복해서 맡길 수 있는 일을 찾는다. 한국어로 대화, 읽기, 그림 판독, 새 문서, 단순 수정, 구조 수정, 셸, 여러 단계의 합성 과제를 순서대로 비교했다.

## 무엇을 만들었나

[수식 스파이크](2026-11-25-ollama-formula-mission.md)의 실행기·Ollama 기록 프록시·판정 코드를 재사용했다. [비서 수락 시험](../test/README.md#비서-수락-시험-수동-측정)의 자료와 판정을 겹치는 과제에 가져왔고, 나머지는 합성 자료와 정답을 미리 정했다.

기준은 `715df90e246548b49f4b3a0f2f5195e76c8617e8`의 HTTP Host, Copilot ACP, 지시문과 도구다. Ollama 0.40.16에서 모델 하나를 전체 접근·추론 강도 `medium`으로 실행했다. 본 측정의 Copilot CLI는 1.0.115였다. 매 실행은 새 Host·프록시·격리 프로필·자료 사본·대화를 썼다. 8b만 같은 대화에서 두 번 보냈다. 각 실행의 관찰 한도는 5분이며 질문이나 승인 대기에는 답하지 않았다. 그림을 붙이는 과제는 화면에서 사용하는 Host 이미지 업로드 및 파일 참조 경로를 이용했다.

응답에는 미리 정한 값·파일 이름·핵심 어구를 적용했다. 파일 상태는 빌드된 공식 `check`와 Core 구조·예상 결과를 대조했다. 기존 문서에서는 대상 외 내용의 보존을 확인했다. 시간은 첫 메시지 송신부터 턴 관찰 종료까지, 토큰은 Ollama가 응답으로 보고한 입력 토큰 합이다. 중앙값은 과제의 모든 본 실행을 포함한다. 본 실행의 모델 요청 517건에서 모두 사용량을 받았다.

### 경계와 실행 근거

- 1~3단계의 9개 과제는 각각 5/5였다. `1b`와 `2a`의 원문은 같다. 붙인 글 요약은 도구 없이 모델 요청 1회였고, 활성 문서 요약은 `read_document`를 거쳐 2회였다. 폴더 낱말 검색은 다섯 번 모두 목록 조회와 문서 읽기 세 건을 수행해 정답 파일을 골랐다. `2c-3`은 정답 파일을 골랐고, 설명에서 낱말이 들어 있는 위치를 파일 이름으로 잘못 적었다. 이 과제의 판정 대상은 찾은 파일 이름이다.
- 합성 PNG 세 종류의 15회 모두 실제 Ollama 요청에 원본과 동일한 이미지 바이트가 있었다. 붙인 수식은 첫 요청에, 파일의 도형과 표는 `view`를 거친 요청에 들어갔다. 이전 수식 스파이크와는 제품 기준과 그림 과제가 모두 다르다.
- 쓰기는 4단계부터 결과가 갈렸다. 문단 두 개 작성 `4a`의 실패 중 세 번은 템플릿 전용 `language`를 일반 생성과 묶어 호출했다. 같은 과제에서 이를 빼고 호출한 `4a-3`은 저장했다. 활성 문서 요약본은 `read_document`와 `create_document`로 5/5였다. `4b-3`은 유효한 문서를 저장했지만 두 번째 담당자가 물음표였고, 모델은 요청대로 정리했다고 답했다.
- 기존 문서에서는 대상이 확실해도 도구가 갈렸다. `6a-1`은 표를 읽은 뒤 기존 경로에 `create_document`를 세 번 호출하고 멈췄다. `6a-2`는 같은 도구 오류를 겪은 뒤 `edit`로 전환해 원래 표와 기존 행을 보존했다. `6c-4`는 셸에서 실제 `apply-batch`까지 갔고, 세 번 모두 옵션 파싱에서 실패했다. `6c-1`과 `6c-2`는 PowerShell로 저장하고 완료를 알렸다. 두 파일은 `check`를 통과했지만 남은 것은 일반 문단이었다. `6c-3`은 저장 파일의 `check`도 실패했다.
- 도구 결과 길이는 짧았다. `2c`의 텍스트 도구 결과 최댓값은 891자였고, 여러 호출을 거쳐 다섯 번 모두 정답을 찾았다. `4a`에서는 최대 374자의 도구 결과를 받고도 인자를 반복해서 틀렸다. 이 자료에서는 긴 결과를 읽을 수 있는 한도를 추정할 수 없다. 쓰기 도구 선택, 필드 종류, 기존 파일과 새 파일의 구분, 명령의 인용·줄바꿈에서 실패가 관찰됐다.
- 작은 CSV 합계 답변은 5/5, 파일 이동은 4/5였다. 이동 실패는 이름이 다른 폴더를 새로 만들고 그곳으로 옮긴 경우다. CSV 집계 문서 저장은 0/5였다. `7c-1`은 스크립트 계산이 정확했고 저장 문서가 유효하지 않았다. `7c-4`는 문서의 수치가 정확했고 스크립트는 Alpha 합계를 틀렸다. 원본 CSV도 다시 썼다.
- 두 문서는 다섯 실행 모두 읽었고 비교본은 3회 저장했다. `8a-2`는 채팅에 정확한 비교를 적고 파일 저장 실패를 알렸다. `8b`는 두 턴이 모두 완료 상태에 도달했다. 기준을 충족한 첫 파일은 2개였고, 둘 다 후속 턴에서 새 문서 도구를 호출해 그대로 남았다. `8b-5`는 둘째 턴에서 세 항목을 가진 문서를 만들었고 첫 턴에는 파일이 없었다.

### 측정 조건의 범위

- 활성 문서 경로는 Host의 정상 경로로 전달했다. 폴더를 직접 지정하는 과제에서는 경로를 메시지에 포함했다. 경로 없이 진행한 예비 실행에서는 폴더를 되묻거나 비서 작업 폴더의 파일을 답했다.
- 예비 실행 다섯 번은 집계에서 제외했다. CLI 갱신 전 실행 1회, 폴더 경로 누락 2회, 글꼴이 뺄셈 기호를 상자로 표시한 수식 그림 1회, 목록 형식을 명시하기 전 실행 1회다. Host 설정값은 `medium`이었고 Copilot CLI 1.0.115의 Ollama 요청 본문에는 `reasoning.effort` 필드가 없었다. 예비 실행 중 설치 CLI가 자동으로 갱신돼 이후 같은 버전의 사본으로 고정했다.
- `7c-1`에서 모델이 설치된 Python의 `pandas`를 갱신하고 `tabulate`를 설치했다. 두 패키지는 실행 이전 상태로 복구하고 확인했다. 이후의 격리 실행에서는 기본 Python 환경으로의 설치를 pip 설정으로 차단했다.
- 첫 요청에는 36개 도구 정의가 있었고 입력은 21,074~21,386토큰이었다. 요청 하나의 최대 입력은 31,204토큰이었다. 이 PC의 짧은 합성 자료와 전체 접근에서 얻은 횟수다. 실제 화면, 긴 문서, 다른 PC, 다른 권한은 검증 범위 밖이다. 공유 Ollama의 외부 요청을 연속 관측하지 않아 시간에 미친 영향을 분리할 수 없다.

## 결론/후속

**미정.** 이 환경에서는 짧은 대화, 경로가 분명한 작은 문서의 읽기·요약과 단순 그림 판독을 우선 맡길 수 있다. 활성 문서 요약본과 작은 CSV 합계도 다섯 번 모두 맞았다. 파일을 옮기거나 고치는 작업에는 저장된 위치와 내용을 직접 확인할 사람이 필요하다. 표·수식 구조 편집, CSV 집계 문서 저장, 여러 턴에 걸친 편집은 독립적으로 맡기기 어렵다. 이 범위를 제품 안내로 채택할지는 소유자 결정이 필요하다.

경계를 넓힐 후보는 두 가지다.

1. 새 문서 도구가 일반 생성에서 허용되지 않는 필드를 구체적으로 알려 줄 때 복구가 나아지는지 확인한다. `4a-1`, `4a-2`, `4a-4`에서 템플릿용 `language`는 반복해서 남았고, 오류는 같은 일반 문구였다.
2. 기존 문서에서 표 행·수식 블록을 넣는 작업을 한 번의 편집 호출로 표현하면 완수 횟수가 늘어나는지 확인한다. `6a-1`, `6c-4`, `8b-3`은 새 문서 도구로 돌아가거나 셸 CLI 옵션을 조합하는 단계에서 실패했다.
