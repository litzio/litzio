# 비서의 변환 문서 검수와 반영

- Status: Historical
- Scope: 공개 LSR 1.1 합성 PDF 13쪽과 고정 변환본, Windows 격리 HTTP Host, Codex 세 모델의 두 턴 대화 9개.

## 목적

비서가 원본 PDF와 변환한 리치오 문서를 비교해 틀린 곳을 찾고, 기존 정답을 보존하면서 저장본을 개선할 수 있는지 확인한다.

## 무엇을 만들었나

공개 CC0 표본과 문서 가져오기 플러그인의 정답 JSON으로 측정했다. 플러그인 `7f162d0e`의 분석·작성·대응 코드를 사용해 한 번 변환했다. 플러그인이 권장한 물리 1쪽 제외를 적용했다. 그림은 화면과 같은 PDF.js 배율 및 사각형을 Node 캔버스에 적용했고 문서와 그림을 공식 `create --input`으로 저장했다. 각 대화에는 같은 기준 사본을 새로 줬다. [표본 안내](https://github.com/litzio/plugins/blob/7f162d0e513ed085976b6a77c12e9fe4fab7c8b8/plugins/document-import/pdf/test/fixtures/README.md)

공식 `inspect`에서 블록 종류, 글자, 제목 단계, 캡션, 각주와 표를 읽어 정답 ID별로 채점했다. 먼저 병합을 편 표, 표 바로 아래의 주석 본문, 호출이 없는 쪽주 18·19의 독립 문단을 받아들이는 기준을 정했다. 원래 각주 참조를 유지하고 화면의 미주 번호 재부여는 허용했다. 부록 M의 내부 표제는 부록 아래 H2를 인정했다. 그림 보존은 원본 영역과 화면에서 확인했으며 LaTeX의 의미는 사람이 대조했다. 1쪽 제외 자료와 반복 머리말·바닥글·쪽 번호는 111개 요소 점수 밖에서 기록했다. [채점 규칙과 실행기](https://github.com/litzio/litzio/tree/1a434500d66fac045d2d5406b2a062c309d6b094/scripts/spike-assistant-review)

플러그인 자체 채점은 잠금 기준선과 일치했다. 저장본에도 글자 표 6개, 해당하는 펼친 격자 6개, 수식 외 칸 127개, 독립 수식 그림 3개가 있었다. 원본 병합이 든 표 1·2의 머리글 두 행은 저장 뒤 한 행이었다. 변환 블록에서 맞음 37개였던 문단은 저장본에서 41개였다. 좌표 기반 분할과 저장 문단을 별도로 비교했고, 저장본에선 정상 참조의 화면 글자와 명시된 양쪽 문단 이어짐을 반영했다. 원본의 실제 그림 두 개 중 K.2는 왼쪽 축 정보 일부가 그림 밖의 다섯 문단으로 흩어졌다. 기준 사본에는 오류 요소 31개가 있었고 지적은 같은 수정으로 다룰 14개 묶음으로 셌다. [기준 오류 목록](https://github.com/litzio/litzio/blob/1a434500d66fac045d2d5406b2a062c309d6b094/scripts/spike-assistant-review/baseline-differences.json)

Sol medium·Terra high를 세 대화씩 먼저 실행했다. Sol 세 건에 오류가 남아 동일한 조건으로 Astra medium 세 대화를 추가했다. 회차마다 새 Host·입력 사본·대화를 만들었고 Codex CLI 0.172.0, 전체 접근, 턴당 15분을 사용했다. 첫 턴은 원본과 활성 문서 경로를 알려 주고 대조 후 목록만 요청했다. 두 번째 턴은 찾은 것을 반영하고 원본과 같은 곳은 건드리지 말라고 했다. 아홉 대화의 18개 턴이 모두 완료됐다. 승인 카드 0건, 쪽 PNG를 미리 주는 실행과 예비 실행은 0건이다.

- 사람이 LaTeX를 읽어 독립 수식 의미 일치 Sol 9/9, Terra 6/9, Astra 9/9를 확인했다. Terra-3은 세 식을 그림으로 유지했다. 표 안 수식 의미 일치는 Sol 12/12, Terra 10/12, Astra 12/12였다. Terra-3은 표 2를 그림으로 교체해 두 수식을 눈으로 읽을 수 있었지만 인라인 수식은 없었다. 대부분의 다른 실행은 두 병합 범위에 각각 한 번만 썼다. Astra-2만 병합에 해당하는 칸마다 수식을 보존하고 격자와 다른 칸 글자도 유지했다.
- 아홉 문서 모두 공식 `check`의 유효·쓰기 가능과 누락 이미지·미해결 참조 0건을 확인했다. 원본 PDF와 기준 그림 여섯 파일의 바이트는 각 사본에서 유지됐고 대체 그림은 별도 파일에 저장했다. 공식 `inspect`로 인식된 이미지와 추가한 로컬 자산 링크를 점검했다. 원래 각주 17·121의 연결도 보존됐다. 추가 각주 호출과 기존 정상 주석 형식의 손상은 별도 점수로 집계했다.
- 비서 반영 뒤 플러그인 로드 작업의 실제 결과를 확인했다. 아홉 사본 모두 대응 파일의 revision이 현재 문서와 달라 `stale: true`였다. 대응 파일은 그대로 남았다. 변경 후 대조 화면에서 어느 블록을 다시 연결하는지는 이번에 실행하지 않았다.
- 검사자는 검증 사본 아홉 개를 별도 HTTP Host와 Windows persistent Chrome의 `pnpm browser:test`에서 각각 열었다. 인식된 그림은 모두 로드됐고 KaTeX 오류 표시가 없었다. Terra-1·2는 식 자체 번호와 앱 번호가 함께 보였다. Astra-3은 참가자 명단과 보조 표 그림 두 개의 파일을 생성했지만 잘못된 그림 선언 세 곳이 코드 블록으로 표시됐다. `check`의 유효 판정은 이를 잡지 못했다.

### 원본을 보고 고친 경로

모든 대화가 Poppler `pdftotext -layout`으로 원본 글자를 얻었다. 필요한 영역은 `pdftoppm` 또는 PyMuPDF로 렌더링했다. PDF를 직접 받아 읽는 Litzio 전용 문서 도구 호출은 관찰되지 않았다. Terra는 첫 턴마다 변환본에 `read_document`를 사용했고 두 반영 턴에서도 같은 도구를 사용했다. 아홉 실행 모두 공급자 패치 또는 PowerShell·Python으로 Markdown을 직접 고쳤다. CLI 도움말과 편집 미리보기, 검사 호출은 있었으나 공식 의미 연산으로 반영을 저장한 실행은 확인되지 않았다. Sol-2의 표 머리글 변경과 Sol-3의 주석 앞 설명 추가는 원본과 일치하는 부분을 유지했다는 응답과 어긋났다.

### 모델과 도구의 영향

Astra는 Sol이 세 번 모두 남긴 표 2의 격자·수식 오류를 한 번 고쳤고, 별도 회차에서는 표 L.2·L.3을 정확한 칸 글자로 복원했다. 두 Route 표는 Terra-3도 고쳤다. 세 모델 모두 `Review participants`의 H3를 놓쳤다. 모든 모델이 원본을 읽고 Litzio가 표현할 수 있는 제목에 도달하지 못했으므로 이 항목은 지적과 판단에서 놓친 것으로 관찰됐다. 표 전용 주석 자리와 원래 쪽주 번호는 모델과 무관한 표현 한계였다. Astra는 표 주석의 정상 위치를 바꾸거나 원본에 없던 쪽주 호출과 정의를 만들었다. Astra-1·2·3의 기존 정답 손상은 7·5·2개다. Sol이 고친 부록 M의 표제는 Astra가 한 번도 고치지 못했다. 이 표본의 결과로 모델 성능과 작업 환경의 영향을 분리할 수는 없다.

격리한 것은 Host와 입력 사본이다. 전체 접근 비서가 작업 폴더 밖의 로컬 기록과 소스를 조회한 대화가 있었다. Sol-2·3은 표 2에 관한 과거 작업 기록까지 읽었다. 정답 파일을 입력 폴더에 주지 않았지만 원본과 저장본만으로 독립적으로 판단한 통제 시험으로 해석할 수 없다. 한 PC, 한 합성 문서, 모델마다 세 번이다. 다른 PDF, 별도 키를 쓰는 환경, 제한 권한, 설치형 앱과 사람의 검수 시간은 측정하지 않았다.

## 현재 결정과 어긋나는 점

없음. 기존 문서 직접 수정, 활성 문서 경로 전달, 공급자 권한은 [ADR-0021](../adr/0021-general-agent-assistant.md)을 따랐다. 제품과 계약 문서는 바꾸지 않았다.

## 결론/후속

**미정. 사람이 대조 화면에서 확인할 블록을 고르고, 비서는 고른 범위만 고친 다음 적용 전에 변경을 확인하는 흐름을 먼저 검증할 것을 추천한다.** 지적은 12~13개였지만 아홉 번 중 일곱 번에 기존 정답 손상이 있었다. 자동 일괄 반영의 채택은 편집 범위 보호와 수정 후 원본 대응의 보존을 실제로 확인한 뒤 결정한다.

1. PDF 쪽·영역과 문서 블록을 함께 가리키는 입력이 필요했다. 아홉 대화가 셸에서 추출과 렌더링을 각각 수행했고, 모두 제목 후보 하나를 놓쳤다.
2. 사용자가 지정한 블록 밖의 의미 차이를 검사할 수 있으면 표·주석 손상을 발견할 수 있다. Sol-2, Astra-1·2에서 `check`는 유효였고 기존 정답은 바뀌었다.
3. 표 병합과 표 주석의 표시·편집 한계를 작업 전에 알릴 수 있어야 한다. Terra-3은 표를 그림으로 교체했고 Astra-1·2는 별도 이미지와 주석 위치 변경으로 우회했다.
4. 수식 번호와 그림 선언의 실제 렌더링 검사 근거가 필요했다. Terra-1·2와 Astra-3은 유효 문서에서 표시 결함을 남겼다.
5. 원본 대응을 갱신해야 한다. 아홉 사본이 모두 이전 revision에 머물렀다.
