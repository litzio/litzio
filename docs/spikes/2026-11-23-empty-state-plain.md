# 2026-11-23 공용 빈 화면 안내의 점선·바탕 비교

- Status: Historical
- Date: 2026-11-23 (브랜치 마지막 커밋일, KST)

## 목적

공용 빈 화면 안내(`EmptyState`)에서 점선과 바탕을 걷어 내면 제목과 다음 행동이 더 선명해지는지, 넓은 화면에서 안내가 떠 보이는지 확인했다.

## 무엇을 만들었나

- 안 A는 점선 테두리와 바탕을 모두 없앴다.
- 안 B는 점선 테두리를 없애고 비서 사용자 메시지와 상태 라벨에 쓰이는 `--id-color-surface-subtle` 바탕을 남겼다.
- 두 안은 기존 제목과 보조 설명의 글자 역할, 가운데 정렬, 여백 토큰을 사용했다.

## 결과·관찰

공용 구현은 `screen-parts.tsx`에 있으며, 갤러리 예제, 비서 패널, 플러그인 화면 바인딩을 통한 측정값 스캐폴드와 PDF 변환 브라우저 예제에서 사용한다. 플러그인 SDK에도 사용 계약과 예제가 있다. 작성 대기 중인 그림은 `styles.css`의 `.figure-no-content`에서 점선과 보조 바탕을 직접 그린다.

| 화면 | 관찰 |
| --- | --- |
| UI 갤러리의 Screen frame 예제, 밝은 테마와 어두운 테마 | 안 A에서도 단계 표시 아래의 제목과 버튼이 함께 읽혔다. 어두운 테마에서는 안 B의 바탕 대비가 커서 상자 자체가 눈에 띄었다. |
| 비서 패널의 첫 안내 | 대화 기록과 제출이 없는 상태를 모의 응답으로 열었다. 안 A의 두 문장은 좁은 패널 안에서 자연스럽게 읽혔다. |
| PDF 가져오기 합성 예제, 좁은 폭 | 안 A의 제목, 설명, 버튼이 단계 표시 폭 안에 모여 안내 위치가 분명했다. |
| PDF 가져오기 합성 예제, 전체 폭 | 안 A의 안내는 넓은 본문 가운데에 떠 보였다. 이 화면에서는 안 B가 작업 영역의 범위를 보여 주어 더 나아 보였다. |
| 측정값 플러그인 스캐폴드 | 머리글에 이미 불러오기 버튼이 있어 안 A의 한 줄 안내로 충분했다. |

`pnpm browser:test`로 1440px 밝은 테마의 다섯 화면과 어두운 테마의 갤러리를 기존 모습·안 A·안 B로 각각 캡처했다. PNG 18장은 저장소에 커밋하지 않았다.

실제 AI 호출과 PDF 변환은 실행하지 않았다.

## 현재 결정과 어긋나는 점

스파이크 시작 시점의 [플러그인 화면 계약](../design/plugin-screens-v1.md)은 보조 표면과 점선 테두리를 규정했다. 비교용 두 안은 점선을 제거했고, 안 A는 보조 표면도 제거했다.
