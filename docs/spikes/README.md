# 스파이크 기록

- Status: Historical (색인)
- Scope: 지금까지 진행한 스파이크의 목적·결과·결론과 코드 위치를 찾기 위한 기록이다. 제품 계약이나 채택 결정이 아니다.

## 정책

- 스파이크 코드는 master에 넣지 않는다. 원격 `spike/<브랜치>`와 주석 태그(annotated tag)로만 보존한다.
- 끝난 스파이크는 브랜치 마지막 커밋에 `spike/<YYYY-MM-DD>-<slug>` 태그를 붙여 push한다. 날짜는 마지막 커밋일(KST)이고 slug는 브랜치 이름에서 `spike/`와 끝의 `-MMDD`를 뗀 것이다. 태그가 커밋을 잡고 있어 브랜치를 나중에 지워도 코드는 남는다.
- 기록은 이 폴더에 스파이크마다 한 장씩(`docs/spikes/<YYYY-MM-DD>-<slug>.md`) 둔다. 문서만 담은 PR로 master에 병합한다.
- 각 기록은 목적, 무엇을 만들었나, 결과·관찰, 결론/후속, 코드 위치, 스크린샷 절을 둔다. 결론은 채택·보류·폐기·미정 중 하나로 표시하고, 근거가 없으면 미정으로 둔다. 결과를 추정해서 적지 않는다.
- 새 스파이크를 시작하면 브랜치를 push하고, 끝나면 태그와 기록 한 장을 같은 방식으로 추가한다. 이슈·PR에 연결하지 않아도 이 색인에서 찾을 수 있다.
- 이 기록의 스크린샷 링크는 master에 이미 있는 파일만 쓴다. 이미지를 새로 추가하지 않는다.

더 이른 시기(2026-09~10)의 Desktop shell·VS Code host·editor 실험은 [Desktop shell spike](../reviews/desktop-shell-spike-v1.md)와 [VS Code host spike](../reviews/vscode-host-spike-v1.md) 등 `docs/reviews`에 기록돼 있고 `archive/*` 태그로 보존돼 있다. 이 색인은 원격 `spike/*` 브랜치를 가진 스파이크를 다룬다.
