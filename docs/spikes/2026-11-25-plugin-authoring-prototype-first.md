## 목적

막연한 요청에서 질문·계획부터 하는 방식과 화면 시안부터 보여 주는 방식 중 사용자가 요구한 기능에 더 적은 응답으로 도달하는 쪽을 확인한다. 화면의 어느 부분인지 설명하는 발화와 실제로 위치를 잘못 이해한 수정도 센다.

### 과제와 사전 판정표

과제 1은 “주간 보고 모으는 거 만들어 줘.”로 시작했다. 한 폴더에 마루, 가람, 여울, 다솔의 합성 주간 보고 네 개를 준비했다. 각 문서는 ‘이번 주 한 일’, ‘다음 주 할 일’, ‘참고 사항’을 담았다. 모래 팀 명단에는 보늬도 있다. 한 주에 한 번 화면에서 실행하고 문서를 남기는 것이 사용자 역할의 설정이었다. 같은 폴더의 여러 주를 처리하는 방법은 정하지 않았다.

1. 선택한 폴더에서 실제 사람별 주간 보고 문서를 읽는다.
2. 화면 위에 발견한 사람별 보고 목록을 보여 준다.
3. 보고 목록 아래에 빠진 모래 팀 사람을 이름으로 보여 준다. 명단에는 가람, 다솔, 마루, 보늬, 여울이 있다.
4. ‘취합 문서 만들기’ 단추로 실제로 새 리치오 문서 하나를 만든다.
5. 취합 문서는 사람 이름 가나다순으로 묶는다.
6. 각 사람의 ‘이번 주 한 일’과 ‘다음 주 할 일’ 내용만 취합한다.
7. 만든 문서를 화면에서 바로 열 수 있다.

과제 2는 “CSV 올리면 그래프 그려 주는 거.”로 시작했다. 과제 3은 아래 일곱 조건을 최초 요청에 모두 넣었다. 날짜가 섞인 표본 가의 값은 날짜순으로 14·20·26·31이고 표본 나는 20·23·7이다. 기준값 20에서 각각 26·31과 23만 초과하며 기준값 30에서 결과가 달라진다.

1. 열린 폴더에서 날짜·값 두 열의 CSV를 하나 고르고 다른 CSV로 바꿀 수 있다.
2. 선택한 실제 자료를 날짜순 꺾은선 그래프로 표시한다.
3. 그래프 위에서 기준선을 숫자로 입력하고 바꿀 수 있다.
4. 기준선을 그래프에 표시하고 기준을 초과한 점을 눈에 띄게 표시한다.
5. 그래프 아래에 기준을 초과한 날짜와 값을 표시한다. 기준과 같은 값은 제외한다.
6. 문서 저장 버튼을 눌러 초과 날짜와 값만 담은 새 리치오 문서를 연다.
7. CSV를 바꾸면 이전 자료의 그래프와 초과 목록이 새 자료에 맞게 갱신된다.

과제 1·2의 속마음은 비서에게 미리 주지 않았다. 사용자 역할은 질문받은 부분에만 속마음대로 짧게 답하고, 정하지 않은 내용에는 “잘 모르겠어, 알아서 해 줘”라고 답했다. 설치된 화면은 실제로 열고 필요하면 조작한 뒤, 한 답변에서 최대 두 가지 차이를 말하거나 맞으면 “좋아”로 수락했다. 최초 요청, 카드 한 묶음의 답변, 일반 메시지를 각각 사용자 1턴으로 세고 최대 8턴을 허용했다. 최종 수락은 기록에 남기고 비서에게 다시 보내지 않았다.

- 주간 보고에서 A-1-1은 비서가 같은 이름의 결과 문서를 미리 만들어 첫 화면의 저장 단추로 새 문서를 만들지 못했다. A-1-2는 첫 화면에서 실제 저장과 문서 내용을 확인했다. 첫 결과물의 자동 열기는 캡처로 확정하지 못해 점수에 넣지 않았다. B-1-1의 첫 실제 입력은 사람마다 파일을 고르는 방식이었다. 사용자 역할이 폴더 한 번으로 찾아 달라고 한 뒤 바뀌었다. B-1-2는 화면 합의를 받은 뒤 이미 열어 둔 폴더를 한 차례 더 물었다. 마지막에는 모두 네 사람의 두 절, 가나다순, 보늬의 누락 표시, 새 문서 저장과 열기를 확인했다.
- 막연한 CSV에서 실제 CSV를 먼저 읽은 세 화면은 처음에 파일의 행 순서대로 그렸다. A-2-2는 처음 넣은 초과 목록을 그래프 위에 두어 아래로 옮겨 달라는 응답이 추가됐다. A-2-1·A-2-2·B-2-1은 첫 저장 문서에 기준값이나 원본 정보를 함께 넣었고 수정 뒤 날짜와 값 표만 남겼다. B-2-2는 실제 연결 시 그 표만 처음부터 저장했다. 최종에는 두 자료를 바꿔서 읽고 기준값 20과 30을 입력했다. 표본 나를 다시 기준값 20으로 검사해 저장 문서에 2026-02-02의 23만 남는 것을 확인했다.

### 실행 중 제약

- 초기 A-2-1·A-2-2의 공용 차트 사용에서는 일부 날짜 눈금이 생략돼 초과 지점의 표시가 충분하지 않았다. 최종본은 화면이 각 점을 직접 그려 구분했다. 두 대화에서 공용 차트 자체의 결함인지는 확인하지 않았다.
- 비서는 설치·실행·자료 읽기까지 확인하고 실제 화면 조작은 미확인으로 표시했다. 화면을 열고 저장을 눌러 결과 문서를 확인하는 일은 측정자가 수행했다. 최종 화면을 가로막은 Host 설치나 다시 불러오기 실패는 관찰되지 않았다.
- A-1-2와 B-1-1의 재검증에서는 같은 이름의 이전 검증 산출물만 별도로 옮긴 뒤 같은 합성 입력을 사용했다. 일부 처음 캡처가 탭 전환 중의 화면을 잡았기 때문에 이후에는 실제 문서 편집기가 표시될 때까지 기다렸다.

## 결론/후속

**기본 지침 채택 보류를 추천한다.** 주간 보고에서는 시안이 먼저 보였지만 B-1-1·B-1-2 모두 실제 입력과 결과를 합의하는 데 추가 왕복이 한 차례 더 들었다. CSV에서는 B-2-2 한 번이 한 차례 줄었고 B-2-1은 기존 방식과 같은 횟수였다. 시안이 설명하기 쉬웠는지는 실제 사람에게 같은 두 과제를 맡겨 확인할 필요가 있다.

화면 요소 선택 기능의 우선순위를 높일 근거는 부족하다. 위치를 말한 발화는 있었지만 위치를 잘못 이해한 사례는 없었고, 요소 선택을 사용했을 때 얼마나 빨라지는지는 측정하지 않았다. 이 기록은 조건마다 2회, 합성 자료, 한 모델로 수행했으며 속마음을 알고 있던 모델이 사용자 역할도 맡았다. 비개발자의 문장 부담이나 화면 조작 시간으로 일반화할 수 없다.
