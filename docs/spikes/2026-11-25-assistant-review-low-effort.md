# 비서의 변환 문서 검수와 낮은 추론 강도

- Status: Historical
- Scope: 공개 LSR 1.1 합성 PDF 13쪽, 고정 변환본, Codex CLI 0.172.0, Windows 격리 HTTP Host.

## 목적

같은 문서를 검수하고 반영할 때 Codex의 추론 강도를 낮추면 찾는 오류, 변경 범위, 기존 정답 손상, 시간과 토큰이 어떻게 달라지는지 확인했다.

## 무엇을 만들었나

[앞 스파이크](2026-11-25-assistant-review-converted-document.md)의 채점기, 오류 14묶음, 정답에 해당하는 111개 요소, 두 요청문을 사용했다. 플러그인 커밋 `7f162d0e`에서 기준 사본을 재현하고 원본 해시, 문서 revision, 채점 결과 80/111, 오류 ID와 기준 밖 블록을 앞 값과 대조했다. 각 대화에 새 Host와 새 자료 사본을 주고 전체 접근, 턴당 15분, 승인 요청에 답하지 않는 조건을 적용했다. 모델 간 실행은 겹쳤다. 같은 모델의 회차는 순차 실행했고, Sol 2의 반영을 기다리는 동안 Sol 3을 먼저 시작했다. 기준 Host는 `497570f4`이며 앞 Host `e73663c3` 이후의 제품 변경은 소규모 작성 입력 검사와 플러그인 안내에 있었고, 비서의 Codex 전송부는 동일했다.

## 결과·관찰

격리 Host의 `supportedReasoningEfforts`에서 세 모델 모두 `low`, `medium`, `high`, `xhigh`, `max`, `ultra`를 반환했다. `none`과 `minimal`은 세 모델에서 지원하지 않아 실행하지 않았다. 세 모델의 `low` 9개 대화, 18개 턴에서 Host가 수락한 설정과 Codex 세션의 턴별 `effort`가 모두 `low`였다. 카탈로그만 조회한 실행 1회와 예비 유료 실행 0회다.

### 모델별 비교

- **Sol**은 지적 세 회 중 한 회에서 한 묶음을 덜 찾았다. 새로 맞은 요소의 범위는 9–27개에서 8–28개로, 손상은 2·2·2개에서 3·0·1개로 바뀌었다. 변경 블록 중앙값은 36→35개다. 지적은 16초 빨라졌고 반영은 34초 느려졌다. low 2의 반영이 523초 걸렸다. 두 턴 토큰 합 중앙값은 약 8% 줄었다.
- **Terra**는 지적 한 회에서 명단을 놓쳤다. 새로 맞은 요소의 범위는 7–25개에서 6–23개로, 손상은 0·0·1개에서 0·0·0개로 바뀌었다. 변경 블록 중앙값은 25→20개이며 기준 오류 밖은 7→5개다. 지적은 1초 느려졌고 반영은 6초 빨라졌다. 두 턴 토큰 합 중앙값은 약 17% 늘었다. low 세 회 모두 독립 수식을 그림으로 유지했고 표 칸에는 일반 글자를 넣었다.
- **Astra**는 매회 12묶음을 찾았고 새로 맞은 범위도 8–26개로 같았다. 손상은 7·5·2개에서 5·8·2개로 바뀌었다. 변경 블록 중앙값은 44개로 같았다. 지적은 4초 느려졌고 반영은 6초 빨라졌다. 두 턴 토큰 합 중앙값은 약 6% 줄었다.
- **수정 범위와 손상**은 Terra low에서 함께 줄었다. Sol은 변경 블록 중앙값이 한 개 줄면서 손상 회차가 3회에서 2회로 줄었다. Astra는 변경 블록 중앙값과 손상 회차가 같고 최대 손상이 늘었다. 이 표본에서 세 모델에 공통된 방향은 관찰되지 않았다.

## 현재 결정과 어긋나는 점

없음. 활성 문서 경로 전달과 전체 접근은 [범용 비서 ADR](../adr/0021-general-agent-assistant.md)을 따랐다.

## 결론/후속

**미정. Sol low로 오류 후보를 찾고 사람이 선택한 비수식 차이는 Terra low로 반영하는 조합을 다음 확인 대상으로 추천한다.** Sol low는 세 회에 13·12·13개를 지적했고, Terra low는 세 회 모두 기존 정답을 보존했다. Terra low는 수식 구조화에 실패했으므로 수식의 저장 형태와 화면은 사람이 확인해야 한다. 다른 변환본과 선택 블록만 제공하는 조건에서 효과를 다시 확인해야 채택을 판단할 수 있다.

한 Windows PC, 합성 문서 한 개, 조건당 세 번의 관찰이다. 파일 읽기 도구와 수정 방식이 회차마다 달랐고 병렬 실행의 영향, 다른 문서에서의 재현성, 사람이 편집 범위를 제한했을 때의 결과는 측정하지 않았다.
