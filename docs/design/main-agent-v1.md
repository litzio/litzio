# 비서: 현재 동작 계약

- Status: Implemented
- Last verified: 2026-11-13 — 제한 권한의 쓰기 CLI 실패 안내·본문 편집 지침을 코드와 대조. 실제 AI 수락 시험의 범위·결과는 해당 PR 기록을 따른다.
- Authority: [ADR-0021](../adr/0021-general-agent-assistant.md), [ADR-0014](../adr/0014-main-agent-app-server.md), [ADR-0017](../adr/0017-bundled-client-and-official-ai.md).
- Scope: 대상 Host의 Codex·Copilot 연결, 설정, 대화와 창 연동. Docling·플러그인의 세부는 각 계약을 따른다.

## 역할과 운영 원칙

비서는 열린 문서·폴더를 바탕으로 일을 수행하는 범용 에이전트이며, 사람과는 리치오 안에서 소통한다.
운영 방향과 이유는 [ADR-0021의 여섯 결정](../adr/0021-general-agent-assistant.md#결정과-이유)을 따른다.
아래의 ‘현재 동작’은 코드·지시문을 요약한 것이며, 각각을 새 소유자 결정으로 승인했다는 뜻이 아니다.

## 유지하는 규칙

### 사용자가 고르는 설정

1. **승인된 결정:** 비서는 AI 권한·공급자·모델을 스스로 바꾸지 못한다.
   실행 범위와 사용할 AI는 사용자가 고르게 한다.
2. **승인된 결정:** 제한 권한의 전용 Host 도구는 열린 폴더 밖을 거절하고, 읽기 전용에서는 생성·이미지 가져오기를 거절한다. 전체 접근에서도 Host Roots는 지킨다.
   공급자 셸의 승인과 별개로 대상 Host의 파일 경계를 보존한다.
3. **승인된 결정:** Copilot 모드는 Agent·Plan만 선택한다. Autopilot·Allow All·Auto Accept는 별도 모드로 제공하지 않는다.
   전체 접근 여부를 권한 설정 한 곳에서 고르게 한다.

위 세 결정은 [#1565](https://github.com/litzio/litzio/issues/1565)의 문서 정리 범위에서 2026-11-13 소유자가 유지를 승인했다.
이하 4~34는 현재 동작이며, 기존 ADR의 결정은 해당 링크가 권위를 갖는다.

### 문서 작업과 복구

4. 기존 문서는 원본을 바로 고치고 `litzio check <file> --format json`으로 검사한다.
   잘못된 문서 저장을 발견하고 수정하기 위해서다([ADR-0021](../adr/0021-general-agent-assistant.md)).
5. 대화에는 활성 문서의 저장된 경로만 전달하고 미저장 본문은 보내지 않으며, 저장본을 사용한다고 알린다.
   화면의 편집본과 디스크 내용을 혼동하지 않게 한다.
6. 임시 산출물은 앱 데이터의 비서 작업 폴더에 두고, 열린 폴더에서 일하기 전에 그 폴더의 지시 파일을 읽는다.
   사용자 폴더에 임시 파일이 쌓이는 것을 줄이고 해당 작업 지침을 따른다.
7. 추가 제약은 구체적 위험·정상 작업 영향·대체 경로를 설명하며, 되돌릴 수 있는 작업은 수행 방법을 먼저 찾는다.
   과도한 제한으로 작업이 막히는 것을 줄인다([저장소 원칙](../../AGENTS.md#working-principles)).
8. 새 사용자 기능은 Host 공용 작업과 CLI를 함께 제공하고 문서 의미를 인터페이스마다 복제하지 않는다.
   같은 작업의 의미를 공유한다([ADR-0015](../adr/0015-shared-host-operations.md)). 비서 전용 도구 기준은 ADR-0021을 따른다.
9. Host 실패나 불확실한 쓰기는 로컬 재실행으로 바꾸지 않고 기존 요청의 상태·결과부터 조회한다.
   결과를 모르는 쓰기의 중복 실행을 막는다. 상태 미발견은 쓰기가 없었다는 증거가 아니다.
10. 입력 오류는 고치고 충돌은 최신 상태를 다시 읽어 분석하며, 안전한 읽기·입력 수정·충돌 복구에 추가 허락을 묻지 않는다.
    해결 가능한 오류 때문에 작업이 멈추는 것을 줄인다.
11. 도구 성공·요청 접수·화면 렌더·실제 적용을 구분하고 확인하지 못한 결과를 성공이라고 말하지 않는다.
    사람이 결과와 남은 작업을 판단할 수 있게 한다.

### 공급자와 실행 소유권

12. 공급자가 없거나 선택 모델을 쓸 수 없으면 이유를 알리고 다른 공급자로 몰래 바꾸지 않는다.
    사용자의 실행 선택을 보존한다.
13. Codex 최소 버전은 0.141.0이며 필요한 프로토콜 계약이 바뀔 때만 올린다.
    사용 중인 app-server 계약을 갖춘 버전을 기준으로 한다([ADR-0014](../adr/0014-main-agent-app-server.md)).
14. 기존 Codex 로그인·설정·지시문·세션을 재사용하고 별도 홈이나 사용자 설정 사본을 만들지 않는다.
    평소 Codex 사용과의 연속성을 유지한다([ADR-0014](../adr/0014-main-agent-app-server.md)).
15. Host가 공급자 프로세스를 소유하고 비서는 daemon 수명을 따른다. 창을 닫아도 작업을 중단하거나 요청을 자동 재실행하지 않는다.
    화면 수명과 실행 수명을 혼동하지 않게 한다.
16. 대화·첨부는 선택한 Host에, 화면 요청은 발화 창에 고정하며 다른 대상으로 자동 전환하지 않는다.
    다른 Host나 창에서 작업되는 것을 막는다.
17. 오래된 턴의 도구 호출은 거절하고 턴 완료·취소·연결 종료 때 실행 권한을 회수한다.
    이전 요청의 권한이 다음 작업에 남지 않게 한다.

### 창 연동과 질문

18. 요청받은 탭·폴더 조작과 표시 변경은 추가 승인 없이 수행하되 기존 미저장 편집 확인을 존중한다.
    일상 조작은 진행하면서 사람의 편집을 보존한다.
19. 표시 도구는 테마·UI 언어·문서 폭·페이지 배경만 바꾸고 다른 설정·문서 본문은 건드리지 않는다.
    표시 변경의 효과를 해당 창의 표시 설정에 한정한다.
20. 필요한 공급자 실행 승인은 카드로 전달하고 조직 정책 거부를 셸로 우회하지 않는다.
    권한 요청과 단순 대화 질문을 구분한다.
21. 비동기 질문은 턴 종료 뒤에도 남고 답은 연결된 후속 사용자 메시지로 한 번 전달한다.
    턴이 끝났다는 이유로 사람의 답이 사라지지 않게 한다.
22. 공급자를 기다리게 하는 질문·승인 콜백은 턴·연결 종료 때 만료하고 비밀 답은 기록에서 가리며 디스크에서 콜백을 복원하지 않는다.
    끝난 요청에 답을 전달하거나 비밀 입력을 기록에 노출하지 않게 한다.
23. 메시지 접수 결과가 불확실하면 먼저 조회하고 확인되지 않으면 사람이 새로 보내기를 선택한다.
    재시작 뒤에도 같은 메시지를 자동 중복 실행하지 않게 한다.

### 생성과 되돌리기

24. 새 문서·템플릿은 기존 파일을 덮어쓰지 않으며 실패 시 중간 파일을 남기지 않는다.
    생성 때문에 기존 데이터나 빈 문서가 남는 일을 막는다.
25. 생성 파일 삭제 되돌리기는 파일 신원·변경·미저장 편집·복구를 확인하고, 확인 중 다시 바뀌면 거절한다.
    사용자 후속 편집이나 교체된 다른 파일을 삭제하지 않게 한다.
26. 기존 파일 되돌리기는 diff를 선언 위치에서 정확히 대조하며 현재 파일이 마지막 비서 결과와 같을 때만 복원한다.
    반복 블록이나 이후 수정이 잘못 복원되는 것을 막는다.
27. 템플릿은 현재 목록에서 확인하고 지정 항목이 없으면 몰래 대체하지 않으며 기본 제공 항목은 새 이름으로 저장한다.
    잘못된 템플릿 선택과 덮어쓰기를 막는다([템플릿 계약](document-templates-v1.md)).

### Docling 검수와 플러그인

28. Docling 검수는 근거를 읽고 실제 검사한 부분만 기록하며, 근거가 부족하면 uncertain, 읽지 않은 부분은 미대조로 남긴다.
    읽지 않은 페이지까지 완료로 표시하지 않게 한다.
29. Docling 이미지는 사전 승인 없이 읽고 근거가 충분한 교정은 즉시 적용한다. Undo·필수 확인·완료 표시는 사람이 처리하며, Undo 뒤 제안 수정은 supersedes를 쓴다.
    교정 실행과 사람의 완료 판단을 구분한다([검수 계약](plugin-stage1-v1.md#review-작업)).
30. 플러그인 관리·조회·작업은 선언된 범위와 권한으로 수행하고 건별 승인 대신 활동을 남긴다. 불확실한 작업은 같은 requestId로 조회한다.
    외부 쓰기와 중복 실행을 통제한다([플러그인 1단계 계약](plugin-stage1-v1.md#비서-제작-키트)).
31. 플러그인 비밀 값은 도구 입력·문서·대화·활동에 넣거나 읽지 않고 전용 secret 설정 경로로 전달하도록 안내한다.
    자격 증명이 공급자와 기록에 노출되지 않게 한다.

플러그인 제작·등록·신뢰·reload는 플러그인 1단계 계약을 따른다. 정적 validate 성공은 실제 호출 성공을 뜻하지 않는다.
읽기 전용에서도 선언된 조회는 가능하지만 쓰기 거부를 셸로 우회하지 않는다.

### 언어와 입력

32. 답변은 사용자 메시지 언어로, 문서는 별도 요청이 없으면 대상 문서 언어로 쓴다. 기본 언어는 대화 없는 작업에만 쓴다.
    사람이 사용할 언어와 결과를 맞춘다.
33. 첨부·제출은 실제 요청 바이트와 공급자·모델의 한도를 따르며 단순 파일 개수로 막지 않는다.
    큰 요청의 실패를 다루면서 정상 첨부를 불필요하게 제한하지 않는다.
34. 설정·생성 입력의 알 수 없는 옵션, 함께 쓸 수 없는 작성 방식, 유효하지 않은 문서는 거절한다.
    틀린 입력을 성공으로 오인하거나 잘못된 문서를 저장하지 않게 한다.

## 권한 모드

저장된 값이 없으면 전체 접근이 기본값이다. 사용자가 다음 턴의 권한을 고르고, Codex 실행 중 추가 메시지는 해당 턴의 권한을 유지한다.
아래는 현재 매핑이며, 공급자의 승인·조직 정책까지 동일한 격리라고 뜻하지 않는다.

| 권한 | Codex | Copilot | 전용 Host 도구 |
| --- | --- | --- | --- |
| 읽기 전용 | `readOnly`, 네트워크 꺼짐, `on-request` 승인 | 열린 폴더·Host Roots 안 읽기/검색 자동 허용. 나머지는 승인 카드 | 제한 폴더 안 조회. 생성·이미지 가져오기 거절 |
| 열린 폴더 | `workspaceWrite`, 열린 폴더와 플러그인 제작 경로를 writableRoots로 전달, 네트워크 켜짐, OS 임시 경로 쓰기 예외 끔, `on-request` 승인 | 범위 안 경로 있는 파일 작업과 경로 없는 fetch 자동 허용. 셸·범위 밖·위치 불명 요청은 승인 카드 | 열린 폴더와 Host Roots 안에서 작업 |
| 전체 접근 | `dangerFullAccess`, `never` 승인 | 지원 시 `allow_all=on`, 도구·경로·네트워크 요청 자동 승인 | 열린 폴더 제한 없이 선택 Host의 파일 정책 적용 |

Copilot 제한 모드는 `allow_all=off`이며 셸 금지 실행 플래그는 없다. Copilot에는 OS sandbox가 없고 상속한 사전 승인이 승인 요청을 생략할 수 있다.
Codex 조직 정책이 전체 접근을 명시적으로 거부하면 실행 전 `turn/start` 거절에 한해 열린 폴더로 한 번 낮춰 시작한다. 전송 실패·실행 오류는 재실행하지 않는다.
전용 Host 도구의 거부를 공급자 승인으로 해제하는 별도 권한 상태는 없다.

## 화면과 인터페이스의 최소 경계

정확한 route·필드·공급자 프로토콜은 [Host 구성](../../apps/editor/server/assistant-host.ts)과
[대화 구현](../../apps/editor/server/assistant-conversations.ts), [중립 타입](../../apps/editor/shared/assistant.ts)이 근거다.
여기서는 다른 화면·문서가 의존하는 동작만 남긴다.

### 연결과 설정

Codex는 `codex app-server`, Copilot은 `copilot --acp`를 Host가 필요할 때 시작한다.
설정은 대상 Host의 공급자·현재 카탈로그 모델·추론 강도·기본 언어·권한을 저장한다.
설정 UI는 변경을 순차 자동 저장하며, 대화별 선택은 전역 기본값을 바꾸지 않는다.
연결됨은 전송 준비 상태이며 로그인·모델 사용 자격·잔여 한도를 증명하지 않는다.
Copilot 진단은 진행 대화와 분리된 짧은 연결로 새로 조회한다.

### 대화와 표시

패널은 shell이 소유하며 폭 340~560px를 기억한다. 좁은 창에서는 기존 overlay를 쓴다.
마지막 대화는 Host별로 기억하고 기록 목록에서 다시 연다. 공급자가 재개를 지원하지 않으면 오류를 알리고 새 대화를 제공한다.
활성 문서 경로와 열린 폴더·명시적 첨부를 전달하고 본문은 필요할 때 읽는다.
탐색기의 ‘채팅에 추가’가 파일 첨부 진입점이며 `@`는 일반 글자다.
화면 조회는 탭·폴더 메타데이터만 반환하고 미저장 본문·선택·플러그인 결과는 반환하지 않는다.

사용자 메시지는 오른쪽 말풍선, 비서 답변은 왼쪽 본문으로 표시하고 턴 끝에서 전체 답변을 복사한다.
작업 과정은 기본 접힘이며 질문·확인은 과정 밖에 둔다. 위로 읽을 때 위치를 유지하고 새 내용과 하단 이동을 안내한다.
닫힌 비서 버튼은 작업 중·읽지 않은 완료·답변 필요를 구분한다. 열린 동안 상태 표시는 숨긴다.
전송 직후 메시지를 표시하고 공급자 관측과 접수 상태를 별도로 추적한다.
활성 답변만 화면 출력을 완만하게 표시하며 완료·중단·실패 때는 수신한 원문 전체를 즉시 표시한다.

### 질문과 사용량

공용 `request_litzio_user_input`은 두 공급자에 제공한다. `accepted:true`는 저장 접수이며 화면 렌더나 답변 수신을 뜻하지 않는다.
공급자 차단 질문과 승인은 원래 RPC를 기다리게 하고, 일반 비동기 질문의 답은 후속 메시지로 보낸다.
Copilot의 native ACP 질문 확장은 현재 지원하지 않는다.
Codex 계정·컨텍스트 사용량은 공급자가 준 값을 구분해 표시한다.
Copilot은 보고된 컨텍스트·세션 사용량만 표시하며 계정 한도를 추정하지 않는다.

### 문서 도구와 이미지

Codex dynamic tools와 Copilot HTTP MCP는 같은 Host 도구 정의와 실행을 사용한다.
Copilot MCP endpoint는 세션과 활성 턴에 묶이며 daemon 인증을 뜻하지 않는다.
터미널에서 Codex 대화를 이어갈 때는 창 도구 실행기가 없으므로 CLI와 제품 안내 스킬을 사용한다.
새 문서 결과 카드는 열기·생성 파일 삭제 되돌리기를 제공한다. CLI 생성은 카드 대신 경로·검사 결과를 보고한다.
이미지 가져오기는 자산을 즉시 복사하고 상대 경로를 반환하며 본문 삽입과는 별개다. 자산은 명시적으로 지울 때까지 남는다.
삽입 방법과 무관하게 문서 검사로 그림 경로를 확인한다.

## 현재 한계

다음은 소유자가 정한 제약이 아니라 현재 구현의 한계다. 실제로 막히는 사례가 나오면 고친다.
판단이 끝나지 않은 항목도 미래 의무나 새 결정으로 바꾸지 않고 현재 상태만 적는다.

1. 화면·표시 요청은 전달까지 10초, 수신 확인 뒤 5분이 지나면 만료하며 늦은 답을 거절한다. 반복 수신 확인은 시간을 늘리지 않는다.

2. 한 대화에서는 화면 조회·화면 조작·표시 요청을 각 종류별 하나씩만 처리한다.

3. 표시 설정 되돌리기는 원래 창·같은 Host 실행 동안만 가능하고 새로고침·재시작 뒤 사라진다.

4. 파일 변경 보기·되돌리기는 공급자 편집 이벤트가 있는 기존 UTF-8 파일 중 1 MiB 이하만 제공한다. 셸 직접 쓰기·생성·삭제·이동·이진 파일·diff 불일치는 경로만 남긴다.

5. 해당 대화에서 답변이 진행 중이면 파일 변경 보기와 되돌리기를 모두 거절한다.

6. 전체 접근 작업도 변경 보기·되돌리기는 기록 당시와 현재의 열린 폴더 및 Host 범위 안에서만 된다.

7. 첫 메시지로 대화가 만들어진 뒤 공급자는 고정된다. 다른 공급자는 새 대화로 시작한다.

8. 실행 중 모델·추론 강도·일부 Copilot 설정은 잠긴다. Copilot은 추가 메시지를 현재 턴이 끝난 뒤 보내며 CLI 추론 강도 변경은 새 대화가 필요하다.

9. Host 재시작 뒤 저장된 대화 권한은 현재 전역 기본값 이하로만 복원한다. 그보다 높은 권한은 사용자가 다시 선택한다.

10. 공급자 원본 로그의 외부 열기는 로컬 Desktop에서 ID·공급자·파일을 검증한 경우만 지원한다. 브라우저·원격 Host는 비활성화하며 경로를 추정하지 않는다.

11. 제한 권한 첨부는 탐색기에 보이는 열린 폴더 안 파일만 허용한다. 전체 접근은 Host Roots 안 숨김·일반 파일도 허용하지만 폴더·심볼릭 링크는 거절한다.

12. 별도 Codex 홈 격리는 도입하지 않았다. 기존 전역 지시문이 들어올 수 있으며, 과거 ADR-0013의 도입 조건을 현재 비서의 새 의무로 삼지 않는다.

13. 실제 AI 수락 검증은 일상·핵심 업무·플러그인 제작별 기준이 다르다. 이는 [검증 절차](../test/README.md#비서-수락-시험-수동-측정)와 [저장소 검증 기준](../../AGENTS.md#verification)의 현재 운영이며 제품 권한 제약이 아니다.

14. Codex `/` 선택기는 비서 작업 폴더에서 활성화된 목록을 쓰고 전송 때 `$name` 토큰이 남은 선택만 보낸다. 이는 명시 선택 처리이며 범용 에이전트의 모든 스킬 접근을 제한한다는 뜻이 아니다.

15. 파일 변경 전후 내용은 대화 소유 Host 메모리에만 있어 Host 재시작 뒤 행동을 복원하지 않는다. 로그 존재가 대화 재개나 모든 입력·결과의 무손실 보존을 보장하지 않는다.

16. 열린 탭의 경로 표기가 canonical 경로와 다르면 되돌리기 전 미저장 확인·이후 재읽기가 적용되지 않을 수 있다. 저장 시 revision 충돌 보호는 남는다.

17. 제한 권한에서는 `litzio` 쓰기 명령이 app-reset guard에 참여하지 못해 실행되지 않으며 비서는 본문 직접 편집을 쓴다(읽기 전용의 편집 제한은 유지). guard 보호를 유지하기 위한 현재 한계다.

## 검증

실제 AI 동작의 수락 기준과 실행법은 [비서 수락 시험](../test/README.md#비서-수락-시험-수동-측정)을 따른다.
정적 문서·코드 대조, fixture 통과, 실제 AI 실행과 사람의 업무 수락은 각각 구분해 보고한다.
